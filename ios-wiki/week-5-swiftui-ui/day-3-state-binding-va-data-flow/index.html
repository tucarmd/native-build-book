    Tuần 5 · Ngày 3 · State, Binding và data flow¶

    Mục tiêu: Phân biệt state do View sở hữu, binding tới state của parent và đối tượng Observable dùng chung; thiết kế luồng dữ liệu một chiều.
    Thời lượng: 90–120 phút

    Khái niệm: @State, @Binding, source of truth, @Observable, @Bindable, @Environment, unidirectional data flow

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Source of truth và luồng dữ liệu một chiều¶

    Quy tắc quan trọng nhất của SwiftUI: mỗi mẩu dữ liệu có đúng một nơi sở hữu (source of truth). Các view khác nhận nó dưới dạng giá trị chỉ đọc hoặc binding (tham chiếu có thể ghi về nguồn). Dữ liệu chảy xuống từ chủ sở hữu; sự kiện chảy ngược lên bằng cách sửa dữ liệu của chủ.

    Nếu có hai bản sao của cùng dữ liệu ở hai nơi, chúng sẽ lệch nhau. Đây là nguồn bug số một khi mới học. Hãy luôn hỏi: "view nào sở hữu dữ liệu này?"

    2. @State: view sở hữu state cục bộ¶

    @State đánh dấu một thuộc tính giá trị mà View sở hữu và theo dõi. Khi nó đổi, SwiftUI tính lại body. SwiftUI lưu giá trị ở bên ngoài struct, nên việc struct bị tạo lại không làm mất state.

    Dùng cho state nhỏ, thuộc riêng view: bật/tắt, text đang nhập, tab đang chọn. Nên đánh dấu private vì chỉ view đó được sở hữu. Không khởi tạo @State từ tham số truyền vào rồi mong nó cập nhật khi tham số đổi: giá trị ban đầu chỉ được dùng một lần.

    import SwiftUI

struct CounterView: View {
    @State private var count = 0

    var body: some View {
        VStack(spacing: 12) {
            Text("Số lần quét: \(count)")
            Button("Quét thêm") { count += 1 }     // sửa state -> body chạy lại
        }
    }
}

    3. @Binding: truyền quyền đọc/ghi cho view con¶

    View con không sở hữu dữ liệu nhưng cần sửa nó (ví dụ một ô nhập, một toggle). Parent truyền binding bằng ký hiệu $: $isOn lấy ra Binding<Bool>. Con khai báo @Binding var isOn: Bool. Đọc/ghi qua binding đọc/ghi thẳng về state của parent, không tạo bản sao.

    Binding là "con trỏ có theo dõi": một dữ liệu, hai nơi nhìn thấy, không lệch. Với thành phần dùng lại như LabeledToggle, SearchField, binding là cách chuẩn.

    import SwiftUI

struct LabeledToggle: View {
    let title: String
    @Binding var isOn: Bool

    var body: some View {
        Toggle(title, isOn: $isOn)
    }
}

struct SettingsView: View {
    @State private var autoConnect = true          // chủ sở hữu duy nhất

    var body: some View {
        Form {
            LabeledToggle(title: "Tự động kết nối", isOn: $autoConnect)
            Text(autoConnect ? "Sẽ kết nối khi mở app" : "Kết nối thủ công")
        }
    }
}

    4. Observable: state dùng chung dạng class¶

    Khi state phức tạp (nhiều thuộc tính, có logic, dùng bởi nhiều view), tạo class đánh dấu @Observable (iOS 17, framework Observation). SwiftUI tự theo dõi thuộc tính nào view thực sự đọc trong body và chỉ cập nhật khi chính thuộc tính đó đổi, chính xác hơn ObservableObject cũ.

    Cách giữ: • View tạo và sở hữu: @State private var model = VehicleFormModel(). • View con chỉ đọc: nhận như tham số thường. • View con cần sửa thuộc tính bằng $: dùng @Bindable var model. • Chia sẻ toàn app: đưa vào environment, đọc bằng @Environment(Type.self).

    (Với iOS 16 trở xuống dùng ObservableObject + @Published + @StateObject/@ObservedObject.)

    import SwiftUI
import Observation

@Observable
final class VehicleForm {
    var make = ""
    var model = ""
    var year = 2024

    var isValid: Bool { !make.isEmpty && !model.isEmpty && (1990...2100).contains(year) }
}

struct VehicleFormView: View {
    @State private var form = VehicleForm()            // view này sở hữu

    var body: some View {
        Form {
            FormFields(form: form)
            Text(form.isValid ? "Hợp lệ" : "Chưa hợp lệ")
        }
    }
}

struct FormFields: View {
    @Bindable var form: VehicleForm                    // cần $ để ghi vào thuộc tính

    var body: some View {
        TextField("Hãng", text: $form.make)
        TextField("Model", text: $form.model)
        Stepper("Năm \(form.year)", value: $form.year, in: 1990...2100)
    }
}

    5. Chọn công cụ nào¶

    • Giá trị đơn giản, thuộc riêng view: @State. • View con cần đọc/ghi giá trị của parent: @Binding. • State phức tạp, logic, nhiều view: @Observable class + @State (sở hữu) hoặc truyền tham số (đọc) hoặc @Bindable (ghi). • Dữ liệu dùng chung toàn app/cây view: @Environment. • Dữ liệu chỉ để hiển thị: tham số let.

    Một kinh nghiệm: bắt đầu bằng @State; chỉ nâng lên class khi logic và thuộc tính trở nên nhiều. Đẩy state "lên" thấp nhất có thể (lowest common ancestor): view cha chung nhỏ nhất của các view cần nó.

    6. So sánh với Angular và lỗi thường gặp¶

    So sánh: • @State ~ thuộc tính component (hoặc signal()); @Binding ~ [(ngModel)]/two-way binding; @Observable ~ service chứa signal/BehaviorSubject. • @Environment ~ dependency injection qua injector. • Không cần ChangeDetectorRef hay unsubscribe: SwiftUI tự theo dõi theo cách dùng.

    Lỗi thường gặp: 1. Dùng @State cho dữ liệu của parent: bản sao bị lệch. Dùng @Binding. 2. Khởi tạo @State từ prop rồi thắc mắc vì sao không cập nhật khi prop đổi. 3. Quên $ khi truyền binding, hoặc dùng $ sai chỗ. 4. Tạo @Observable object trong body hoặc không giữ bằng @State: bị tạo lại mỗi lần render, mất dữ liệu. 5. Sửa state trong body (gây vòng lặp): chỉ sửa trong action (Button, .onChange, .task). 6. Truyền cả model lớn vào mọi view con thay vì từng giá trị cần thiết.

    7. Tóm tắt¶

    • Mỗi dữ liệu có một source of truth; dữ liệu chảy xuống, sự kiện chảy lên. • @State: giá trị cục bộ view sở hữu. @Binding: quyền đọc/ghi tới state của nơi khác ($). • @Observable class cho state phức tạp; giữ bằng @State, ghi bằng @Bindable. • @Environment để chia sẻ xuyên cây view. • Chọn công cụ nhỏ nhất đủ dùng; đặt state ở tổ tiên chung thấp nhất.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — State cục bộ¶

    Viết ConnectionBadge có nút bật/tắt kết nối và hiển thị "Đã kết nối" hoặc "Chưa kết nối" với màu khác nhau. State thuộc về view nào?

    Gợi ý Chỉ view này dùng state nên dùng @State private.
    Đáp án 
    import SwiftUI

struct ConnectionBadge: View {
    @State private var isConnected = false

    var body: some View {
        VStack(spacing: 12) {
            Text(isConnected ? "Đã kết nối" : "Chưa kết nối")
                .foregroundStyle(isConnected ? .green : .red)
            Button(isConnected ? "Ngắt" : "Kết nối") { isConnected.toggle() }
        }
    }
}
    **Giải thích:** State chỉ dùng trong view này nên là `@State private`. Khi `isConnected` đổi, SwiftUI tính lại `body`, chữ và màu tự cập nhật.

    Bài 2 — Tách view con với Binding¶

    Tách ô tìm kiếm thành SearchField nhận @Binding var text: String. View cha giữ @State private var query và lọc danh sách xe theo query.

    Gợi ý Cha truyền $query; con dùng TextField("...", text: $text).
    Đáp án 
    import SwiftUI

struct SearchField: View {
    @Binding var text: String
    var body: some View {
        HStack {
            Image(systemName: "magnifyingglass")
            TextField("Tìm xe", text: $text)
        }
        .padding(10)
        .background(.background.secondary, in: RoundedRectangle(cornerRadius: 10))
    }
}

struct VehicleSearch: View {
    @State private var query = ""
    let vehicles = ["Toyota Camry", "Honda Civic", "Ford Focus"]

    private var filtered: [String] {
        query.isEmpty ? vehicles : vehicles.filter { $0.localizedCaseInsensitiveContains(query) }
    }

    var body: some View {
        VStack {
            SearchField(text: $query)
            List(filtered, id: \.self) { Text($0) }
        }
    }
}
    **Giải thích:** Cha sở hữu `query`; con chỉ giữ binding nên mọi gõ phím cập nhật thẳng state của cha. `filtered` là computed property nên luôn khớp với `query`.

    Bài 3 — @Observable cho form¶

    Tạo @Observable class VehicleForm gồm make, model, year, và isValid. Dùng @State ở view cha và @Bindable ở view con để chỉnh. Vô hiệu hóa nút Lưu khi chưa hợp lệ.

    Gợi ý Button(...).disabled(!form.isValid)
    Đáp án 
    import SwiftUI
import Observation

@Observable
final class VehicleForm {
    var make = ""
    var model = ""
    var year = 2024
    var isValid: Bool { !make.isEmpty && !model.isEmpty && (1990...2100).contains(year) }
}

struct FormScreen: View {
    @State private var form = VehicleForm()

    var body: some View {
        Form {
            Fields(form: form)
            Button("Lưu") { print("Saved \(form.make)") }
                .disabled(!form.isValid)
        }
    }
}

struct Fields: View {
    @Bindable var form: VehicleForm
    var body: some View {
        TextField("Hãng", text: $form.make)
        TextField("Model", text: $form.model)
        Stepper("Năm \(form.year)", value: $form.year, in: 1990...2100)
    }
}
    **Giải thích:** `isValid` là computed property nên không lệch dữ liệu. `@State` giữ instance qua các lần render; `@Bindable` cho phép dùng `$form.make` với class Observable.

    Bài 4 — Tìm lỗi source of truth¶

    Đoạn sau khiến toggle ở con không thay đổi giá trị ở cha. Vì sao và sửa thế nào?

    struct Child: View { @State var isOn: Bool; var body: some View { Toggle("A", isOn: $isOn) } } struct Parent: View { @State private var isOn = false; var body: some View { Child(isOn: isOn) } }

    Gợi ý Child tạo bản sao riêng của giá trị.
    Đáp án 
    import SwiftUI

struct Child: View {
    @Binding var isOn: Bool            // không phải @State
    var body: some View { Toggle("A", isOn: $isOn) }
}

struct Parent: View {
    @State private var isOn = false
    var body: some View { Child(isOn: $isOn) }   // truyền binding
}
    **Giải thích:** Với `@State` ở Child, `isOn` chỉ là giá trị khởi tạo rồi trở thành bản sao riêng, lệch với Parent. `@Binding` + `$isOn` giữ một nguồn dữ liệu duy nhất.
