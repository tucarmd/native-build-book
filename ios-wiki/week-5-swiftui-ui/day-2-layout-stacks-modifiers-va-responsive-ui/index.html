    Tuần 5 · Ngày 2 · Layout, stacks, modifiers và responsive UI¶

    Mục tiêu: Dùng VStack, HStack, ZStack, Spacer, frame, alignment và modifier theo thứ tự có chủ đích để dựng layout thích ứng với kích thước màn hình.
    Thời lượng: 75–90 phút

    Khái niệm: VStack/HStack/ZStack, Spacer, frame, padding, alignment, ScrollView, Dynamic Type, safe area

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Cách SwiftUI tính layout¶

    Layout trong SwiftUI theo quy trình ba bước: (1) view cha đề xuất kích thước cho con; (2) con chọn kích thước nó muốn và báo lại; (3) cha đặt con vào vị trí. Hiểu ba bước này giúp giải thích hầu hết hành vi "kỳ lạ".

    Ví dụ: Text chỉ lấy kích thước vừa đủ chữ. Color và Spacer tham lam, chiếm hết chỗ được đề xuất. .frame(width:height:) không "ép" view con đổi kích thước mà đặt một khung có kích thước cố định quanh nó, rồi căn con vào giữa khung.

    2. Stack và alignment¶

    • VStack: xếp dọc. HStack: xếp ngang. ZStack: xếp chồng (nền, huy hiệu đè lên ảnh). • alignment: cách căn theo trục còn lại (.leading, .center, .trailing cho VStack; .top, .firstTextBaseline cho HStack). • spacing: khoảng cách giữa các con; nếu không đặt, dùng khoảng mặc định theo ngữ cảnh. • Spacer(): đẩy các view ra xa, chiếm mọi khoảng trống có thể.

    Khác Flexbox/CSS: không có flex-wrap mặc định hay z-index lung tung; thứ tự trong ZStack chính là thứ tự xếp chồng.

    import SwiftUI

struct VehicleHeader: View {
    var body: some View {
        HStack(alignment: .top, spacing: 12) {
            Image(systemName: "car.fill")
                .font(.largeTitle)
            VStack(alignment: .leading, spacing: 4) {
                Text("Toyota Camry").font(.headline)
                Text("Năm 2024 · 12.500 km").font(.subheadline).foregroundStyle(.secondary)
            }
            Spacer()                                   // đẩy badge sang phải
            Text("MỚI").font(.caption.bold()).padding(6)
                .background(.green.opacity(0.2), in: Capsule())
        }
        .padding()
    }
}

struct Hero: View {
    var body: some View {
        ZStack(alignment: .bottomLeading) {
            LinearGradient(colors: [.blue, .indigo], startPoint: .top, endPoint: .bottom)
            Text("Chẩn đoán xe").font(.title.bold()).foregroundStyle(.white).padding()
        }
        .frame(height: 160)
        .clipShape(RoundedRectangle(cornerRadius: 16))
    }
}

    3. frame, padding và thứ tự modifier¶

    padding thêm khoảng đệm quanh view. frame(maxWidth: .infinity) cho phép view mở rộng hết bề ngang cha (cách làm nút full-width). frame(minHeight:), frame(idealWidth:) cho phạm vi kích thước linh hoạt thay vì cố định.

    Thứ tự modifier quyết định kết quả vì mỗi modifier bọc kết quả trước: • .padding().background(.blue): nền bao cả padding. • .background(.blue).padding(): nền chỉ bao nội dung. • .frame(maxWidth: .infinity).background(.blue): nền kéo dài hết ngang; đổi thứ tự thì nền chỉ ôm nội dung. Nguyên tắc: nội dung → padding → frame → background/overlay → clipShape → shadow → padding ngoài.

    import SwiftUI

struct PrimaryButtonStyleDemo: View {
    var body: some View {
        VStack(spacing: 16) {
            Text("Bắt đầu chẩn đoán")
                .font(.headline)
                .foregroundStyle(.white)
                .frame(maxWidth: .infinity)      // full-width
                .padding(.vertical, 14)
                .background(.blue, in: RoundedRectangle(cornerRadius: 12))

            Text("Nền chỉ ôm chữ")
                .padding(8)
                .background(.gray.opacity(0.2), in: Capsule())
        }
        .padding(.horizontal)
    }
}

    4. Responsive: cuộn, Dynamic Type, safe area, size class¶

    iPhone có nhiều cỡ màn hình, iPad và chế độ xoay còn nhiều hơn, nên không đặt kích thước cố định. Các công cụ chính: • ScrollView khi nội dung có thể dài hơn màn hình; LazyVStack để chỉ dựng view đang thấy (danh sách dài). • Dynamic Type: người dùng tăng cỡ chữ hệ thống thì chữ phải co giãn. Dùng text style (.font(.body), .headline) thay vì cỡ cố định; @ScaledMetric để co giãn kích thước theo chữ. • Safe area: nội dung mặc định tránh notch, Dynamic Island, home indicator. Chỉ dùng .ignoresSafeArea() cho nền. • ViewThatFits: thử nhiều layout theo thứ tự, dùng layout đầu tiên vừa chỗ (ngang trước, dọc sau). • @Environment(\.horizontalSizeClass) để đổi layout giữa iPhone (compact) và iPad (regular). • Hạn chế GeometryReader vì nó chiếm hết chỗ và làm layout phức tạp; ưu tiên stack, frame linh hoạt, containerRelativeFrame (iOS 17).

    import SwiftUI

struct AdaptiveStatus: View {
    @Environment(\.horizontalSizeClass) private var sizeClass
    @ScaledMetric private var iconSize: CGFloat = 28

    var body: some View {
        ScrollView {
            LazyVStack(alignment: .leading, spacing: 16) {
                ViewThatFits {
                    HStack { content }            // ưu tiên ngang
                    VStack(alignment: .leading) { content }   // nếu không vừa thì dọc
                }
                if sizeClass == .regular {
                    Text("Bố cục rộng cho iPad").foregroundStyle(.secondary)
                }
            }
            .padding()
        }
    }

    @ViewBuilder private var content: some View {
        Image(systemName: "bolt.car").font(.system(size: iconSize))
        Text("Đang sạc · 87%").font(.headline)
        Text("Còn 32 phút").foregroundStyle(.secondary)
    }
}

    5. So sánh với CSS/Flexbox¶

    • VStack/HStack ~ display:flex với flex-direction cột/hàng. • Spacer ~ flex:1 hoặc margin-left:auto. • frame(maxWidth:.infinity) ~ width:100%. • ZStack ~ position:absolute chồng lớp. • Media query ~ size class, ViewThatFits. • rem/em ~ Dynamic Type và @ScaledMetric. • Thiếu cảm giác "box model" như CSS: không có margin; dùng padding trước hoặc sau để mô phỏng. • Không có file CSS: kiểu dáng đi cùng view, nên dễ thấy ảnh hưởng.

    6. Lỗi thường gặp¶

    1. Đặt frame(width: 375) cố định: vỡ trên máy nhỏ hoặc iPad.
    2. Dùng GeometryReader ở mọi chỗ: layout co lại bất ngờ.
    3. Quên Spacer hoặc quên nó chiếm mọi chỗ khiến phần tử bị đẩy lệch.
    4. Chồng nhiều padding mà không hiểu chúng cộng dồn.
    5. Cỡ chữ cố định .font(.system(size: 14)): không theo Dynamic Type; kiểm tra bằng Environment Overrides trong Xcode hoặc preview với .dynamicTypeSize(.xxxLarge).
    6. Dùng ignoresSafeArea() cho cả nội dung làm chữ bị che bởi notch.
    7. Đặt List trong ScrollView: hai vùng cuộn lồng nhau gây hành vi lạ.

    7. Tóm tắt¶

    • Layout: cha đề xuất → con chọn → cha đặt; Spacer và Color tham lam, Text vừa đủ. • Stack + alignment + spacing là công cụ chính; ZStack để xếp chồng. • Thứ tự modifier quyết định kết quả; frame(maxWidth: .infinity) cho full-width. • Thích ứng bằng ScrollView, Dynamic Type, safe area, ViewThatFits, size class. • Tránh kích thước cố định và lạm dụng GeometryReader.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Card thông tin xe¶

    Dựng card gồm icon xe bên trái, tên xe và năm ở giữa, badge "MỚI" bên phải, nền bo góc, padding hợp lý. Dùng HStack, VStack, Spacer.

    Gợi ý Spacer nằm giữa nhóm chữ và badge để đẩy badge sang phải.
    Đáp án 
    import SwiftUI

struct VehicleCard: View {
    var body: some View {
        HStack(spacing: 12) {
            Image(systemName: "car.fill").font(.title2).foregroundStyle(.tint)
            VStack(alignment: .leading, spacing: 2) {
                Text("Toyota Camry").font(.headline)
                Text("Năm 2024").font(.subheadline).foregroundStyle(.secondary)
            }
            Spacer()
            Text("MỚI").font(.caption.bold())
                .padding(.horizontal, 8).padding(.vertical, 4)
                .background(.green.opacity(0.2), in: Capsule())
        }
        .padding(16)
        .background(.background.secondary, in: RoundedRectangle(cornerRadius: 12))
        .padding(.horizontal)
    }
}
    **Giải thích:** Modifier theo thứ tự nội dung → padding → background → padding ngoài giúp card có khoảng cách bên trong và lề màn hình.

    Bài 2 — Nút full-width¶

    Viết nút "Kết nối" rộng bằng chiều ngang màn hình (trừ lề), có nền xanh, chữ trắng, bo góc. Giải thích vì sao đặt .frame(maxWidth: .infinity) trước .background.

    Gợi ý Nền bọc view đã có frame.
    Đáp án 
    import SwiftUI

struct ConnectButton: View {
    var action: () -> Void

    var body: some View {
        Button(action: action) {
            Text("Kết nối")
                .font(.headline)
                .foregroundStyle(.white)
                .frame(maxWidth: .infinity)
                .padding(.vertical, 14)
                .background(.blue, in: RoundedRectangle(cornerRadius: 12))
        }
        .padding(.horizontal)
    }
}
    **Giải thích:** Nếu `background` đặt trước `frame`, nền chỉ ôm chữ; frame mở rộng nhưng nền không đi theo. Đặt frame trước làm nền phủ hết chiều ngang.

    Bài 3 — Layout thích ứng¶

    Dùng ViewThatFits để hiển thị ba thông số (tốc độ, nhiên liệu, nhiệt độ) theo hàng ngang nếu đủ chỗ, nếu không thì xếp dọc. Kiểm tra bằng preview Dynamic Type lớn.

    Gợi ý ViewThatFits thử các lựa chọn theo thứ tự.
    Đáp án 
    import SwiftUI

struct Metrics: View {
    var body: some View {
        ViewThatFits {
            HStack(spacing: 24) { metrics }
            VStack(alignment: .leading, spacing: 12) { metrics }
        }
        .padding()
    }

    @ViewBuilder private var metrics: some View {
        Label("62 km/h", systemImage: "speedometer")
        Label("45%", systemImage: "fuelpump")
        Label("90°C", systemImage: "thermometer")
    }
}

#Preview("Chữ lớn") {
    Metrics().dynamicTypeSize(.accessibility2)
}
    **Giải thích:** Khi chữ lớn, hàng ngang không vừa nên `ViewThatFits` chuyển sang xếp dọc. Cách này thay cho media query và không cần tính kích thước tay.
