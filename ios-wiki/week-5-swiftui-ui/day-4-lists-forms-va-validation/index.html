    Tuần 5 · Ngày 4 · Lists, forms và validation¶

    Mục tiêu: Tạo danh sách có định danh ổn định, form nhập xe và validation hiển thị lỗi theo từng trường trước khi lưu.
    Thời lượng: 90–120 phút

    Khái niệm: List, ForEach, Identifiable, Form, TextField, Picker, swipeActions, validation

    • Đã đọc xong
    • Đã làm hết bài tập

    1. List và ForEach đúng cách¶

    List là view cuộn với các dòng tái sử dụng (như UITableView), có sẵn kiểu iOS, swipe, chọn dòng. Truyền mảng Identifiable vào List là đủ. Dùng ForEach bên trong List khi cần trộn nhiều nguồn hoặc onDelete/onMove.

    Id phải ổn định và duy nhất (bài 4.5). Với dữ liệu có thể thay đổi, đừng dùng chỉ số mảng làm id. Khi cần xóa theo thao tác vuốt, dùng .swipeActions (kiểm soát nút) hoặc .onDelete (kiểu cổ điển với IndexSet).

    Để danh sách phản ứng với thay đổi, mảng phải nằm trong state (@State hoặc @Observable).

    import SwiftUI

struct Vehicle: Identifiable, Equatable {
    let id: UUID
    var make: String
    var model: String
    var year: Int
    init(id: UUID = UUID(), make: String, model: String, year: Int) {
        self.id = id; self.make = make; self.model = model; self.year = year
    }
}

struct VehicleListScreen: View {
    @State private var vehicles = [
        Vehicle(make: "Toyota", model: "Camry", year: 2024),
        Vehicle(make: "Honda", model: "Civic", year: 2022)
    ]

    var body: some View {
        List {
            ForEach(vehicles) { vehicle in
                VStack(alignment: .leading) {
                    Text("\(vehicle.make) \(vehicle.model)").font(.headline)
                    Text("Năm \(vehicle.year)").font(.caption).foregroundStyle(.secondary)
                }
                .swipeActions(edge: .trailing) {
                    Button(role: .destructive) {
                        vehicles.removeAll { $0.id == vehicle.id }
                    } label: { Label("Xóa", systemImage: "trash") }
                }
            }
        }
    }
}

    2. Form và các control nhập liệu¶

    Form nhóm các control theo kiểu "Settings" của iOS. Thường dùng: TextField, SecureField, Toggle, Picker, Stepper, DatePicker, Section. Mỗi control nhận binding tới state.

    Với TextField: .keyboardType(.numberPad), .textInputAutocapitalization(.never), .autocorrectionDisabled() và .submitLabel(.next) làm trải nghiệm nhập tốt hơn. Để nhập số, dùng TextField("Năm", value: $year, format: .number).

    Picker hoạt động với enum CaseIterable & Hashable: dùng .tag(value) hoặc ForEach(Type.allCases) (nhớ conform Identifiable hoặc id: \.self).

    import SwiftUI

enum FuelType: String, CaseIterable, Identifiable {
    case gasoline = "Xăng", diesel = "Dầu", electric = "Điện"
    var id: Self { self }
}

struct AddVehicleForm: View {
    @State private var make = ""
    @State private var model = ""
    @State private var year = 2024
    @State private var fuel = FuelType.gasoline
    @State private var isOwned = true

    var body: some View {
        Form {
            Section("Thông tin") {
                TextField("Hãng", text: $make)
                TextField("Model", text: $model)
                TextField("Năm", value: $year, format: .number.grouping(.never))
                    .keyboardType(.numberPad)
            }
            Section("Loại nhiên liệu") {
                Picker("Nhiên liệu", selection: $fuel) {
                    ForEach(FuelType.allCases) { Text($0.rawValue).tag($0) }
                }
            }
            Section { Toggle("Xe của tôi", isOn: $isOwned) }
        }
    }
}

    3. Validation: tách logic và hiển thị lỗi theo trường¶

    Đặt quy tắc kiểm tra ở một nơi (hàm thuần hoặc model) rồi để UI chỉ hiển thị kết quả. Dùng lại các kiểu lỗi từ tuần 3. Cách làm gọn: trả về mảng/dictionary lỗi theo trường, hoặc từng thuộc tính makeError: String?.

    Hiển thị lỗi sau khi người dùng đã tương tác (đã rời khỏi ô hoặc bấm Lưu), không hiện ngay khi form vừa mở. Vô hiệu hóa nút Lưu cho đến khi hợp lệ hoặc cho phép bấm rồi hiển thị tất cả lỗi: chọn một cách và nhất quán.

    import SwiftUI
import Observation

@Observable
final class VehicleDraft {
    var make = ""
    var model = ""
    var year = 2024
    var didTryToSave = false

    var makeError: String? { make.trimmingCharacters(in: .whitespaces).isEmpty ? "Nhập hãng xe" : nil }
    var modelError: String? { model.trimmingCharacters(in: .whitespaces).isEmpty ? "Nhập model" : nil }
    var yearError: String? { (1990...2100).contains(year) ? nil : "Năm phải từ 1990 đến 2100" }
    var isValid: Bool { makeError == nil && modelError == nil && yearError == nil }
}

struct FieldError: View {
    let message: String?
    var body: some View {
        if let message {
            Text(message).font(.caption).foregroundStyle(.red)
        }
    }
}

struct DraftForm: View {
    @State private var draft = VehicleDraft()
    var onSave: (Vehicle) -> Void

    var body: some View {
        @Bindable var draft = draft
        Form {
            Section {
                TextField("Hãng", text: $draft.make)
                if draft.didTryToSave { FieldError(message: draft.makeError) }
                TextField("Model", text: $draft.model)
                if draft.didTryToSave { FieldError(message: draft.modelError) }
                Stepper("Năm \(draft.year)", value: $draft.year, in: 1900...2200)
                if draft.didTryToSave { FieldError(message: draft.yearError) }
            }
            Button("Lưu") {
                draft.didTryToSave = true
                guard draft.isValid else { return }
                onSave(Vehicle(make: draft.make, model: draft.model, year: draft.year))
            }
        }
    }
}

    4. So sánh với Angular Forms¶

    • Reactive Forms với FormGroup/Validators ~ một model (@Observable) cộng computed property lỗi. • [(ngModel)] ~ $binding. • ngIf hiển thị lỗi theo touched ~ cờ didTryToSave hoặc @FocusState theo dõi ô đã rời. • ion-item/ion-input ~ control trong Form/Section. • Swipe-to-delete ion-item-sliding ~ .swipeActions. • Với validation dùng lại giữa tầng UI và dữ liệu, đặt quy tắc trong model/validator (tuần 3), UI chỉ chuyển nó thành chữ.

    5. Lỗi thường gặp¶

    1. Dùng chỉ số mảng làm id: xóa/chèn xong thì UI sai dòng.
    2. List không cập nhật vì mảng không nằm trong state.
    3. Hiện lỗi ngay lúc mở form, người dùng thấy toàn chữ đỏ.
    4. Parse chuỗi sang số thủ công trong body: dùng TextField(value:format:).
    5. Lặp quy tắc validation ở nhiều nơi.
    6. Không đặt keyboardType, autocapitalization đúng: nhập liệu khó chịu.
    7. Không xử lý bàn phím che nội dung: Form xử lý sẵn; custom layout cần .scrollDismissesKeyboard và ScrollView.
    8. Lưu khi bấm nhanh nhiều lần: hãy vô hiệu hóa nút khi đang lưu.

    6. Tóm tắt¶

    • List/ForEach cần id ổn định; mảng phải nằm trong state để UI cập nhật. • Form và control nhập liệu dùng binding; chọn keyboardType và định dạng phù hợp. • Validation tập trung ở model (computed property lỗi), UI chỉ hiển thị. • Hiển thị lỗi sau khi người dùng đã tương tác hoặc bấm Lưu. • swipeActions cho xóa; xác nhận khi thao tác nguy hiểm (bài 5).

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Danh sách có thêm/xóa¶

    Tạo màn hình danh sách xe lưu trong @State, có nút "+" thêm xe mẫu và vuốt để xóa. Vì sao id của Vehicle phải là thuộc tính lưu trữ?

    Gợi ý Dùng ToolbarItem để đặt nút +, và swipeActions cho xóa.
    Đáp án 
    import SwiftUI

struct Vehicle: Identifiable {
    let id = UUID()
    var name: String
}

struct VehiclesScreen: View {
    @State private var vehicles = [Vehicle(name: "Camry")]

    var body: some View {
        NavigationStack {
            List {
                ForEach(vehicles) { v in
                    Text(v.name)
                        .swipeActions {
                            Button("Xóa", role: .destructive) {
                                vehicles.removeAll { $0.id == v.id }
                            }
                        }
                }
            }
            .navigationTitle("Xe")
            .toolbar {
                Button { vehicles.append(Vehicle(name: "Xe \(vehicles.count + 1)")) } label: {
                    Image(systemName: "plus")
                }
            }
        }
    }
}
    **Giải thích:** `let id = UUID()` được tạo một lần cho mỗi instance, nên ổn định. Nếu là computed property tạo UUID mới, id thay đổi mỗi lần render và SwiftUI coi mọi dòng là mới.

    Bài 2 — Form nhập xe có Picker¶

    Tạo form có TextField hãng, TextField model, Picker loại nhiên liệu (enum) và Stepper năm. Bàn phím số cho trường số.

    Gợi ý Enum cần CaseIterable & Identifiable hoặc id: \.self.
    Đáp án 
    import SwiftUI

enum Fuel: String, CaseIterable, Identifiable {
    case gasoline = "Xăng", diesel = "Dầu", electric = "Điện"
    var id: Self { self }
}

struct NewVehicleForm: View {
    @State private var make = ""
    @State private var model = ""
    @State private var fuel = Fuel.gasoline
    @State private var year = 2024

    var body: some View {
        Form {
            TextField("Hãng", text: $make)
            TextField("Model", text: $model)
            Picker("Nhiên liệu", selection: $fuel) {
                ForEach(Fuel.allCases) { Text($0.rawValue).tag($0) }
            }
            Stepper("Năm \(year)", value: $year, in: 1990...2100)
        }
    }
}
    **Giải thích:** `Stepper` giới hạn khoảng giá trị nên không cần kiểm tra tay. `Picker` liên kết với enum qua `tag`, giữ kiểu an toàn thay cho chuỗi.

    Bài 3 — Validation hiển thị lỗi¶

    Thêm validation: hãng và model không rỗng, năm 1990–2100. Chỉ hiển thị lỗi sau khi bấm Lưu lần đầu. Nút Lưu chỉ gọi onSave khi hợp lệ.

    Gợi ý Dùng cờ didTryToSave và computed property lỗi trong model.
    Đáp án 
    import SwiftUI
import Observation

@Observable
final class Draft {
    var make = ""
    var year = 2024
    var didTry = false
    var makeError: String? { make.isEmpty ? "Nhập hãng xe" : nil }
    var yearError: String? { (1990...2100).contains(year) ? nil : "Năm không hợp lệ" }
    var isValid: Bool { makeError == nil && yearError == nil }
}

struct DraftView: View {
    @State private var draft = Draft()
    var onSave: (String, Int) -> Void

    var body: some View {
        @Bindable var draft = draft
        Form {
            TextField("Hãng", text: $draft.make)
            if draft.didTry, let e = draft.makeError { Text(e).foregroundStyle(.red) }
            Stepper("Năm \(draft.year)", value: $draft.year, in: 1900...2200)
            if draft.didTry, let e = draft.yearError { Text(e).foregroundStyle(.red) }
            Button("Lưu") {
                draft.didTry = true
                if draft.isValid { onSave(draft.make, draft.year) }
            }
        }
    }
}
    **Giải thích:** Quy tắc nằm trong model nên có thể test độc lập. Cờ `didTry` tránh hiện lỗi khi form vừa mở, giúp trải nghiệm thân thiện hơn.

    Bài 4 — Phát hiện lỗi danh sách¶

    List dùng ForEach(0..<vehicles.count, id: \.self) và có chức năng xóa. Điều gì sai khi xóa dòng giữa và cách sửa?

    Gợi ý

    Chỉ số mảng thay đổi sau khi xóa.

    Đáp án 
    // Sai: id là chỉ số, sau khi xóa các dòng dưới đổi id -> animation/state sai
ForEach(0..<vehicles.count, id: \.self) { i in Text(vehicles[i].name) }

// Đúng: dùng phần tử Identifiable với id ổn định
ForEach(vehicles) { vehicle in Text(vehicle.name) }
    **Giải thích:** Với id là chỉ số, sau khi xóa phần tử ở giữa các dòng sau đổi id, SwiftUI hiểu là dòng bị thay thế thay vì dịch chuyển. Với id ổn định, nó biết đúng dòng nào biến mất.
