    Tuần 6 · Ngày 1 · Model dữ liệu với Codable¶

    Mục tiêu: Ánh xạ JSON từ API vào Swift model, xử lý tên field khác nhau, field thiếu, ngày tháng và lỗi decode.
    Thời lượng: 75–90 phút

    Khái niệm: Codable, Decodable / Encodable, JSONDecoder, CodingKeys, keyDecodingStrategy, DTO vs domain model, DecodingError

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Codable là gì¶

    Codable là tên gọi gộp của hai protocol: Decodable (chuyển dữ liệu ngoài, thường là JSON, thành Swift) và Encodable (chuyển Swift thành dữ liệu ngoài). Nếu mọi thuộc tính của struct đều là Codable (String, Int, Double, Bool, Date, URL, Optional, Array, Dictionary, struct khác Codable), bạn chỉ cần khai báo : Codable và compiler tự sinh toàn bộ code chuyển đổi.

    So với TypeScript: JSON.parse(text) as Vehicle chỉ ép kiểu và không kiểm tra thật; dữ liệu sai vẫn lọt vào. JSONDecoder của Swift kiểm tra thật sự từng field theo kiểu: sai kiểu hoặc thiếu field bắt buộc thì ném lỗi, nên bạn biết ngay dữ liệu không đúng hợp đồng.

    import Foundation

struct VehicleDTO: Codable {
    let id: String
    let make: String
    let model: String
    let year: Int
    let mileage: Double?       // field có thể vắng mặt: dùng Optional
}

let json = """
{ "id": "V001", "make": "Toyota", "model": "Camry", "year": 2024 }
""".data(using: .utf8)!

let vehicle = try JSONDecoder().decode(VehicleDTO.self, from: json)
print(vehicle.make, vehicle.mileage ?? 0)       // Toyota 0.0

let back = try JSONEncoder().encode(vehicle)     // Swift -> JSON
print(String(data: back, encoding: .utf8)!)

    2. Tên field khác nhau: CodingKeys và strategy¶

    API thường dùng snake_case (fuel_type, created_at), còn Swift dùng camelCase. Hai cách xử lý: 1. Đặt decoder.keyDecodingStrategy = .convertFromSnakeCase: tự đổi tên cho mọi field. Gọn nhất khi quy ước nhất quán. 2. Khai báo enum CodingKeys: String, CodingKey để ánh xạ từng field. Dùng khi tên khác hẳn hoặc chỉ muốn đổi vài field. Khi tự khai báo CodingKeys, phải liệt kê mọi thuộc tính cần decode (những thuộc tính không có trong enum thì phải có giá trị mặc định).

    Ngày tháng: đặt decoder.dateDecodingStrategy = .iso8601 cho chuỗi dạng 2024-05-01T08:30:00Z. Nếu định dạng khác, dùng .formatted(dateFormatter) hoặc .custom.

    import Foundation

struct DiagnosticDTO: Decodable {
    let code: String
    let fuelType: String
    let createdAt: Date
}

let json = """
{ "code": "P0301", "fuel_type": "gasoline", "created_at": "2024-05-01T08:30:00Z" }
""".data(using: .utf8)!

let decoder = JSONDecoder()
decoder.keyDecodingStrategy = .convertFromSnakeCase
decoder.dateDecodingStrategy = .iso8601
let item = try decoder.decode(DiagnosticDTO.self, from: json)
print(item.fuelType, item.createdAt)

// Cách 2: CodingKeys tự ánh xạ
struct VehicleDTO: Decodable {
    let id: String
    let displayName: String
    let registeredAt: Date?

    enum CodingKeys: String, CodingKey {
        case id
        case displayName = "name"
        case registeredAt = "registered_at"
    }
}

    3. DTO và domain model¶

    DTO (Data Transfer Object) là struct phản ánh đúng hình dạng JSON của server: tên field, Optional, kiểu chuỗi cho enum. Domain model là kiểu app dùng: tên rõ nghĩa, enum thay chuỗi, dữ liệu đã được kiểm tra. Tách hai lớp giúp khi API đổi tên field hay cấu trúc, bạn chỉ sửa DTO và hàm chuyển đổi, UI và logic không đổi.

    Chuyển đổi bằng init(dto:) hoặc hàm toDomain(). Đây cũng là nơi quyết định xử lý dữ liệu xấu: bỏ qua, dùng mặc định hay báo lỗi.

    import Foundation

enum FuelType: String { case gasoline, diesel, electric, unknown }

struct Vehicle: Identifiable {
    let id: String
    let displayName: String
    let year: Int
    let fuel: FuelType
}

struct VehicleDTO: Decodable {
    let id: String
    let make: String
    let model: String
    let year: Int
    let fuelType: String?
}

extension Vehicle {
    init(dto: VehicleDTO) {
        self.id = dto.id
        self.displayName = "\(dto.make) \(dto.model)"
        self.year = dto.year
        self.fuel = dto.fuelType.flatMap(FuelType.init(rawValue:)) ?? .unknown
    }
}

    4. Xử lý lỗi decode¶

    JSONDecoder.decode ném DecodingError với bốn loại: keyNotFound (thiếu field), typeMismatch (sai kiểu), valueNotFound (giá trị null cho kiểu không Optional), dataCorrupted (JSON sai cú pháp). Mỗi loại kèm codingPath cho biết chính xác field nào lỗi. Hãy log chi tiết khi phát triển, và hiển thị thông báo chung cho người dùng.

    Khi muốn bỏ qua phần tử xấu trong mảng thay vì thất bại cả mảng, bạn có thể decode từng phần tử bằng wrapper Failable<T>; chỉ làm khi nghiệp vụ cho phép.

    import Foundation

struct Item: Decodable { let id: Int; let name: String }

let bad = #"{ "id": "one", "name": "x" }"#.data(using: .utf8)!

do {
    _ = try JSONDecoder().decode(Item.self, from: bad)
} catch let DecodingError.typeMismatch(type, context) {
    print("Sai kiểu \(type) tại \(context.codingPath.map(\.stringValue))")
} catch let DecodingError.keyNotFound(key, _) {
    print("Thiếu field \(key.stringValue)")
} catch {
    print("Lỗi khác: \(error)")
}

    5. So sánh với TypeScript¶

    • interface + JSON.parse không kiểm tra lúc chạy; Swift kiểm tra thật. Thư viện như zod/io-ts của TypeScript gần với tinh thần này. • snake_case → camelCase thường xử lý bằng thư viện hay interceptor; Swift có sẵn strategy. • field?: string của TS ~ Optional trong DTO. • Union type thay đổi theo "type" cần init(from:) tùy biến hoặc enum có associated value, vì Swift không "đoán" kiểu. • Số nguyên lớn: JSON number sang Int được, nhưng số thập phân vào Int thì lỗi (khác JS không phân biệt).

    6. Lỗi thường gặp¶

    1. Khai báo field là String nhưng server trả số (hoặc ngược lại): typeMismatch.
    2. Server trả null hoặc bỏ field mà DTO không để Optional: keyNotFound/valueNotFound.
    3. Dùng convertFromSnakeCase rồi lại khai báo CodingKeys thủ công: hai cơ chế đè nhau gây nhầm lẫn.
    4. Quên đặt strategy ngày tháng: lỗi decode Date.
    5. Dùng domain model làm DTO nên mỗi lần server đổi là sửa toàn app.
    6. Nuốt lỗi decode bằng try?: mất khả năng chẩn đoán.
    7. Tạo JSONDecoder() mới liên tục trong vòng lặp nóng: tạo một lần và dùng lại.

    7. Tóm tắt¶

    • Codable tự sinh chuyển đổi JSON ↔ Swift khi mọi thuộc tính đều Codable. • keyDecodingStrategy, dateDecodingStrategy và CodingKeys xử lý khác biệt về tên field/ngày tháng. • Tách DTO (hình dạng server) khỏi domain model (hình dạng app); chuyển đổi ở một chỗ. • DecodingError cho biết chính xác field và lý do; log khi phát triển. • Dùng Optional cho field có thể vắng mặt.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Decode JSON đơn giản¶

    Với JSON {"id":"V001","make":"Toyota","model":"Camry","year":2024}, tạo VehicleDTO: Decodable và in make sau khi decode. Thêm field mileage có thể vắng mặt.

    Gợi ý Dùng JSONDecoder().decode(_:from:) với Data; field có thể vắng mặt dùng Double?.
    Đáp án 
    import Foundation

struct VehicleDTO: Decodable {
    let id: String
    let make: String
    let model: String
    let year: Int
    let mileage: Double?
}

let data = #"{"id":"V001","make":"Toyota","model":"Camry","year":2024}"#.data(using: .utf8)!
let dto = try JSONDecoder().decode(VehicleDTO.self, from: data)
print(dto.make, dto.mileage ?? 0)
    **Giải thích:** Optional cho phép thiếu field mà không lỗi. Nếu `mileage` là `Double` không Optional thì decode ném `keyNotFound`.

    Bài 2 — snake_case và ngày tháng¶

    JSON có {"vehicle_id":"V1","fuel_type":"diesel","created_at":"2024-05-01T08:30:00Z"}. Cấu hình decoder để decode vào struct dùng camelCase và Date.

    Gợi ý convertFromSnakeCase và iso8601.
    Đáp án 
    import Foundation

struct Record: Decodable {
    let vehicleId: String
    let fuelType: String
    let createdAt: Date
}

let json = #"{"vehicle_id":"V1","fuel_type":"diesel","created_at":"2024-05-01T08:30:00Z"}"#.data(using: .utf8)!
let decoder = JSONDecoder()
decoder.keyDecodingStrategy = .convertFromSnakeCase
decoder.dateDecodingStrategy = .iso8601
let record = try decoder.decode(Record.self, from: json)
print(record.vehicleId, record.createdAt)
    **Giải thích:** Hai strategy tự xử lý đổi tên và parse ngày, giúp tránh viết `CodingKeys` cho từng field.

    Bài 3 — DTO sang domain model¶

    Từ VehicleDTO có fuelType: String?, tạo Vehicle domain với enum FuelType. Giá trị lạ hoặc thiếu thì dùng .unknown. Vì sao không dùng thẳng DTO trong UI?

    Gợi ý FuelType(rawValue:) trả về Optional; dùng flatMap và ??.
    Đáp án 
    import Foundation

enum FuelType: String { case gasoline, diesel, electric, unknown }

struct VehicleDTO: Decodable { let id: String; let fuelType: String? }
struct Vehicle { let id: String; let fuel: FuelType }

extension Vehicle {
    init(dto: VehicleDTO) {
        id = dto.id
        fuel = dto.fuelType.flatMap(FuelType.init(rawValue:)) ?? .unknown
    }
}

print(Vehicle(dto: VehicleDTO(id: "1", fuelType: "hydrogen")).fuel)   // unknown
    **Giải thích:** DTO bám theo server (có thể đổi, có Optional, chuỗi tự do) nên cô lập nó. Domain model ổn định, kiểu mạnh, và việc xử lý giá trị lạ nằm ở một chỗ duy nhất.

    Bài 4 — Đọc lỗi decode¶

    Decode {"id":"one","name":"x"} vào struct Item { let id: Int; let name: String }. Bắt lỗi và in field gây lỗi từ codingPath.

    Gợi ý catch let DecodingError.typeMismatch(type, context).
    Đáp án 
    import Foundation

struct Item: Decodable { let id: Int; let name: String }
let data = #"{"id":"one","name":"x"}"#.data(using: .utf8)!

do {
    _ = try JSONDecoder().decode(Item.self, from: data)
} catch let DecodingError.typeMismatch(_, context) {
    print("Sai kiểu ở:", context.codingPath.map(\.stringValue).joined(separator: "."))   // id
} catch {
    print(error)
}
    **Giải thích:** `codingPath` chỉ rõ đường dẫn tới field sai, giúp chẩn đoán nhanh khi server trả dữ liệu không đúng hợp đồng.
