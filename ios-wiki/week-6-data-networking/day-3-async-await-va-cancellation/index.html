    Tuần 6 · Ngày 3 · async/await và cancellation¶

    Mục tiêu: Viết hàm async, dùng Task từ UI, chạy song song bằng async let/TaskGroup và hủy công việc không còn cần thiết.
    Thời lượng: 90–120 phút

    Khái niệm: async / await, Task, .task modifier, async let, TaskGroup, cancellation, @MainActor

    • Đã đọc xong
    • Đã làm hết bài tập

    1. async/await là gì¶

    Hàm đánh dấu async có thể tạm dừng (suspend) ở await mà không chặn luồng: trong lúc chờ mạng, luồng được dùng để làm việc khác (như vẽ UI). Khi có kết quả, hàm tiếp tục từ chỗ dừng. Code đọc từ trên xuống như đồng bộ nhưng không chặn.

    Quy tắc: await chỉ dùng trong ngữ cảnh async. Hàm async có thể throws: gọi bằng try await. Từ ngữ cảnh đồng bộ (action của Button), bạn mở một Task { } để bước vào thế giới async.

    So với JS: tương tự async/await trên Promise, nhưng hệ thống kiểu của Swift bắt buộc await ở mọi điểm tạm dừng nên bạn thấy rõ chúng ở đâu. Swift không có "callback hell" hay Promise chain; Combine/RxJS ít khi cần cho request đơn.

    import Foundation

func fetchName(id: Int) async throws -> String {
    try await Task.sleep(for: .milliseconds(300))      // giả lập mạng
    return "Xe \(id)"
}

func run() async {
    do {
        let name = try await fetchName(id: 1)           // tạm dừng ở đây, không chặn luồng
        print(name)
    } catch {
        print("Lỗi: \(error)")
    }
}

    2. Task: bắt đầu công việc bất đồng bộ¶

    Task { ... } khởi chạy công việc async từ code đồng bộ, kế thừa actor hiện tại (trong View là @MainActor). Trả về handle Task để hủy hoặc chờ kết quả (await task.value). Task.detached tách khỏi ngữ cảnh actor, hiếm khi cần.

    Trong SwiftUI, thay vì onAppear { Task { ... } }, dùng modifier .task { await load() }: công việc tự bắt đầu khi view xuất hiện và tự hủy khi view biến mất. .task(id: value) chạy lại và hủy lần cũ mỗi khi value đổi, hợp cho tìm kiếm theo từ khóa.

    import SwiftUI

struct VehiclesView: View {
    @State private var names: [String] = []
    @State private var query = ""

    var body: some View {
        List(names, id: \.self) { Text($0) }
            .searchable(text: $query)
            .task(id: query) {                          // tự hủy lần trước khi query đổi
                try? await Task.sleep(for: .milliseconds(300))   // debounce
                guard !Task.isCancelled else { return }
                names = await search(query)
            }
    }

    func search(_ q: String) async -> [String] {
        ["Camry", "Civic", "Focus"].filter { q.isEmpty || $0.localizedCaseInsensitiveContains(q) }
    }
}

    3. Chạy song song: async let và TaskGroup¶

    Gọi await lần lượt thì chạy tuần tự. Muốn chạy đồng thời các việc độc lập, dùng async let (số lượng cố định) hoặc TaskGroup (số lượng động). Tổng thời gian xấp xỉ việc lâu nhất, không phải tổng các việc.

    withThrowingTaskGroup thêm nhiều task con; nếu một task ném lỗi, các task còn lại bị hủy khi lỗi lan ra khỏi group. Hợp để tải thông tin nhiều xe cùng lúc, nhưng nên giới hạn mức song song (đừng mở 500 request cùng lúc).

    import Foundation

func loadVehicle(_ id: Int) async throws -> String {
    try await Task.sleep(for: .milliseconds(200))
    return "Xe \(id)"
}
func loadOwner() async throws -> String { try await Task.sleep(for: .milliseconds(200)); return "An" }

func loadScreen() async throws {
    // Số lượng cố định: async let
    async let vehicle = loadVehicle(1)
    async let owner = loadOwner()
    let (v, o) = try await (vehicle, owner)               // cả hai chạy song song
    print(v, o)

    // Số lượng động: TaskGroup
    let names = try await withThrowingTaskGroup(of: String.self) { group in
        for id in 1...5 { group.addTask { try await loadVehicle(id) } }
        var results: [String] = []
        for try await name in group { results.append(name) }
        return results.sorted()
    }
    print(names)
}

    4. Hủy công việc (cancellation)¶

    Cancellation trong Swift là hợp tác (cooperative): hủy chỉ đánh dấu task là "đã bị hủy"; code phải tự kiểm tra và dừng. Các API hệ thống như URLSession và Task.sleep tự ném CancellationError hoặc URLError(.cancelled). Với vòng lặp tự viết, gọi try Task.checkCancellation() hoặc kiểm tra Task.isCancelled.

    Việc hủy xảy ra khi: view biến mất (.task), .task(id:) đổi id, bạn gọi task.cancel(), hoặc task cha bị hủy (lan xuống task con). Khi bắt lỗi, đừng hiển thị CancellationError như lỗi thật cho người dùng.

    import Foundation

func importAll(_ ids: [Int]) async throws -> Int {
    var done = 0
    for id in ids {
        try Task.checkCancellation()          // dừng nếu bị hủy
        try await Task.sleep(for: .milliseconds(100))
        done += id
    }
    return done
}

func demo() async {
    let task = Task { try await importAll(Array(1...100)) }
    try? await Task.sleep(for: .milliseconds(250))
    task.cancel()
    do {
        _ = try await task.value
    } catch is CancellationError {
        print("Đã hủy, không hiện lỗi")       // bình thường, bỏ qua
    } catch {
        print("Lỗi thật: \(error)")
    }
}

    5. Cập nhật UI an toàn: @MainActor¶

    Mọi thay đổi giao diện phải xảy ra trên main thread. Trong Swift hiện đại, điều này được biểu diễn bằng @MainActor: View đã ngầm là @MainActor, nên Task tạo từ View hay ViewModel @MainActor chạy phần cập nhật state trên main. Phần nặng (decode JSON lớn) có thể chuyển sang nền bằng hàm nonisolated hoặc actor khác (chi tiết ở tuần 7).

    Đánh dấu cả ViewModel là @MainActor là cách đơn giản và an toàn: mọi thuộc tính state chỉ bị sửa trên main, tránh data race.

    import SwiftUI
import Observation

@MainActor
@Observable
final class VehicleListViewModel {
    var names: [String] = []
    var isLoading = false

    func load() async {
        isLoading = true
        defer { isLoading = false }
        try? await Task.sleep(for: .seconds(1))   // việc chờ không chặn main
        names = ["Camry", "Civic"]                  // gán state trên main
    }
}

    6. So sánh với JS/RxJS và lỗi thường gặp¶

    So sánh: • Promise.all ~ async let/TaskGroup; AbortController ~ Task.cancel() + kiểm tra hủy; ngOnDestroy + takeUntil ~ .task tự hủy. • switchMap hủy request cũ khi có giá trị mới ~ .task(id:). • JS đơn luồng nên không có data race; Swift đa luồng nên cần actor/@MainActor (tuần 7).

    Lỗi thường gặp: 1. Dùng Task { } trong onAppear và quên hủy: request tiếp tục sau khi rời màn. 2. Chạy tuần tự các request độc lập làm chậm. 3. Hiện CancellationError như lỗi cho người dùng. 4. Sửa state UI từ task nền không phải @MainActor. 5. Chặn bằng Task.sleep/semaphore ở nơi không cần. 6. Tạo vô hạn task không giới hạn mức song song. 7. Quên rằng hủy là hợp tác: vòng lặp CPU không kiểm tra hủy thì không dừng.

    7. Tóm tắt¶

    • async hàm tạm dừng ở await mà không chặn luồng; từ code đồng bộ dùng Task { }. • Trong SwiftUI ưu tiên .task và .task(id:): tự hủy theo vòng đời view. • async let/TaskGroup để chạy song song. • Hủy là hợp tác: dùng Task.checkCancellation(); đừng hiển thị CancellationError như lỗi. • Đánh dấu ViewModel là @MainActor để cập nhật UI an toàn.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Chạy song song¶

    Viết loadDashboard() tải thông tin xe và danh sách mã lỗi cùng lúc bằng async let rồi in kết quả. Giải thích vì sao tổng thời gian không phải là tổng hai request.

    Gợi ý async let bắt đầu ngay; await ở cuối để lấy cả hai.
    Đáp án 
    import Foundation

func loadVehicle() async throws -> String { try await Task.sleep(for: .milliseconds(300)); return "Camry" }
func loadCodes() async throws -> [String] { try await Task.sleep(for: .milliseconds(300)); return ["P0301"] }

func loadDashboard() async throws {
    async let vehicle = loadVehicle()
    async let codes = loadCodes()
    let (v, c) = try await (vehicle, codes)
    print(v, c)
}
    **Giải thích:** Hai việc bắt đầu gần như đồng thời; tổng thời gian xấp xỉ việc lâu nhất (khoảng 300ms) thay vì cộng (600ms).

    Bài 2 — Tìm kiếm có debounce và hủy¶

    Dùng .task(id: query) để tìm kiếm xe theo từ khóa, chờ 300ms trước khi gọi để tránh gọi mỗi phím. Điều gì xảy ra với lần tìm trước khi query đổi?

    Gợi ý Task.sleep ném lỗi khi bị hủy; kiểm tra Task.isCancelled.
    Đáp án 
    import SwiftUI

struct SearchView: View {
    @State private var query = ""
    @State private var results: [String] = []

    var body: some View {
        List(results, id: \.self) { Text($0) }
            .searchable(text: $query)
            .task(id: query) {
                do {
                    try await Task.sleep(for: .milliseconds(300))   // debounce
                    results = await search(query)
                } catch {
                    // bị hủy do query đổi: bỏ qua
                }
            }
    }

    func search(_ q: String) async -> [String] { ["Camry"].filter { $0.localizedCaseInsensitiveContains(q) } }
}
    **Giải thích:** Mỗi lần `query` đổi, task cũ bị hủy tự động; `Task.sleep` ném lỗi nên dừng ngay, chỉ task mới nhất thực sự gọi tìm kiếm.

    Bài 3 — Hủy vòng lặp dài¶

    Viết importAll(ids:) xử lý lần lượt từng id, dừng khi bị hủy. Gọi nó trong Task, hủy sau 250ms và phân biệt CancellationError với lỗi thật.

    Gợi ý try Task.checkCancellation() trong vòng lặp; catch is CancellationError.
    Đáp án 
    import Foundation

func importAll(ids: [Int]) async throws -> Int {
    var count = 0
    for _ in ids {
        try Task.checkCancellation()
        try await Task.sleep(for: .milliseconds(100))
        count += 1
    }
    return count
}

let task = Task { try await importAll(ids: Array(1...50)) }
try? await Task.sleep(for: .milliseconds(250))
task.cancel()
do { _ = try await task.value }
catch is CancellationError { print("Đã hủy") }
catch { print("Lỗi thật \(error)") }
    **Giải thích:** Hủy là hợp tác: vòng lặp chủ động kiểm tra. `CancellationError` là tình huống bình thường, không nên báo lỗi cho người dùng.

    Bài 4 — ViewModel @MainActor¶

    Viết VehicleListViewModel @MainActor @Observable với state: LoadState và hàm load() gọi một repository async. Xử lý lỗi và bỏ qua CancellationError.

    Gợi ý enum LoadState như tuần 5; catch is CancellationError trước catch chung.
    Đáp án 
    import Observation

enum LoadState<Value> { case idle, loading, loaded(Value), failed(String) }

protocol VehicleRepository { func getAll() async throws -> [String] }

@MainActor
@Observable
final class VehicleListViewModel {
    private(set) var state: LoadState<[String]> = .idle
    private let repository: any VehicleRepository

    init(repository: any VehicleRepository) { self.repository = repository }

    func load() async {
        state = .loading
        do {
            state = .loaded(try await repository.getAll())
        } catch is CancellationError {
            // view biến mất: không đổi sang lỗi
        } catch {
            state = .failed(error.localizedDescription)
        }
    }
}
    **Giải thích:** `@MainActor` đảm bảo state chỉ bị sửa trên main. Bỏ qua `CancellationError` tránh hiển thị lỗi vô nghĩa khi người dùng rời màn.
