    Tuần 6 · Ngày 4 · Persistence: UserDefaults, files và SwiftData¶

    Mục tiêu: Chọn nơi lưu phù hợp cho cấu hình, file và dữ liệu có cấu trúc; dùng SwiftData cho dữ liệu offline-first.
    Thời lượng: 90–120 phút

    Khái niệm: UserDefaults, @AppStorage, FileManager, Codable JSON file, SwiftData, @Model, @Query, offline-first

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Chọn nơi lưu theo loại dữ liệu¶

    Không có một nơi lưu "tốt nhất"; chọn theo bản chất dữ liệu: • Cài đặt nhỏ, giá trị đơn giản (chế độ tối, đơn vị km/mi, đã xem hướng dẫn): UserDefaults/@AppStorage. • Một tài liệu/blob (cache JSON, file tải về, ảnh): file trong thư mục của app (FileManager). • Dữ liệu có cấu trúc, nhiều bản ghi, cần truy vấn/sắp xếp/quan hệ: SwiftData (hoặc Core Data, SQLite). • Bí mật (token, mật khẩu): Keychain (tuần 7), không bao giờ UserDefaults.

    Nguyên tắc offline-first: UI đọc từ kho cục bộ (nguồn sự thật), mạng chỉ làm nhiệm vụ đồng bộ vào kho. Nhờ đó app mở nhanh, hoạt động khi mất mạng và UI luôn nhất quán.

    2. UserDefaults và @AppStorage¶

    UserDefaults lưu cặp khóa–giá trị nhỏ (String, Int, Bool, Double, Data, URL, mảng/dictionary đơn giản), tồn tại giữa các lần mở app. Không đặt dữ liệu lớn hay nhạy cảm. Trong SwiftUI, @AppStorage("key") biến nó thành state: đổi giá trị thì view tự cập nhật và tự lưu.

    Luôn dùng hằng cho khóa để tránh gõ sai. Với enum có RawRepresentable kiểu String/Int, @AppStorage lưu được trực tiếp.

    import SwiftUI

enum Units: String { case km, mile }

struct SettingsView: View {
    @AppStorage("settings.autoConnect") private var autoConnect = true
    @AppStorage("settings.units") private var units = Units.km

    var body: some View {
        Form {
            Toggle("Tự động kết nối", isOn: $autoConnect)
            Picker("Đơn vị", selection: $units) {
                Text("Kilômét").tag(Units.km)
                Text("Dặm").tag(Units.mile)
            }
        }
    }
}

// Ngoài SwiftUI:
let defaults = UserDefaults.standard
defaults.set(true, forKey: "hasSeenOnboarding")
let seen = defaults.bool(forKey: "hasSeenOnboarding")

    3. Lưu file với FileManager và Codable¶

    Mỗi app có sandbox riêng. Hai thư mục thường dùng: documentsDirectory (dữ liệu người dùng, được sao lưu iCloud) và cachesDirectory (dữ liệu có thể tạo lại, hệ thống có thể xóa khi thiếu dung lượng). Lưu một mảng Codable thành file JSON là giải pháp đơn giản cho dữ liệu nhỏ: encode rồi write(to:options:.atomic) (ghi nguyên tử để tránh file hỏng giữa chừng).

    Hạn chế: đọc/ghi toàn bộ mỗi lần, không truy vấn, khó xử lý đồng thời. Khi dữ liệu lớn hoặc cần tìm kiếm, chuyển sang SwiftData.

    import Foundation

struct Vehicle: Codable, Identifiable { let id: String; var name: String }

struct VehicleFileStore {
    private let url = URL.documentsDirectory.appending(path: "vehicles.json")

    func load() throws -> [Vehicle] {
        guard FileManager.default.fileExists(atPath: url.path) else { return [] }
        let data = try Data(contentsOf: url)
        return try JSONDecoder().decode([Vehicle].self, from: data)
    }

    func save(_ vehicles: [Vehicle]) throws {
        let data = try JSONEncoder().encode(vehicles)
        try data.write(to: url, options: .atomic)
    }
}

    4. SwiftData: dữ liệu có cấu trúc¶

    SwiftData (iOS 17) là framework lưu trữ khai báo dựa trên Core Data nhưng dùng Swift thuần. Bạn đánh dấu class bằng @Model; SwiftData lưu thuộc tính (Codable) và quan hệ giữa các model. Các thành phần: • @Model class: định nghĩa bảng. @Attribute(.unique) cho khóa duy nhất. • ModelContainer: kho dữ liệu, tạo bằng .modelContainer(for:) trên scene/view. • ModelContext: nơi chèn/sửa/xóa (insert, delete); thay đổi tự lưu. • @Query: lấy dữ liệu vào view, tự cập nhật khi dữ liệu đổi, có sắp xếp và lọc.

    Tách model lưu trữ (@Model, là class) khỏi domain model (struct) nếu bạn muốn giữ domain độc lập với framework; với app nhỏ có thể dùng @Model trực tiếp.

    import SwiftUI
import SwiftData

@Model
final class VehicleEntity {
    @Attribute(.unique) var id: String
    var make: String
    var model: String
    var year: Int

    init(id: String, make: String, model: String, year: Int) {
        self.id = id; self.make = make; self.model = model; self.year = year
    }
}

struct SavedVehiclesView: View {
    @Environment(\.modelContext) private var context
    @Query(sort: \VehicleEntity.year, order: .reverse) private var vehicles: [VehicleEntity]

    var body: some View {
        List {
            ForEach(vehicles) { v in
                Text("\(v.make) \(v.model) (\(v.year))")
            }
            .onDelete { offsets in
                for index in offsets { context.delete(vehicles[index]) }
            }
        }
        .toolbar {
            Button("Thêm") {
                context.insert(VehicleEntity(id: UUID().uuidString, make: "Toyota", model: "Camry", year: 2024))
            }
        }
    }
}

@main
struct VehicleApp: App {
    var body: some Scene {
        WindowGroup {
            NavigationStack { SavedVehiclesView() }
        }
        .modelContainer(for: VehicleEntity.self)    // tạo kho cho cả app
    }
}

    5. Offline-first và đồng bộ¶

    Mẫu phổ biến: màn hình hiển thị dữ liệu từ kho cục bộ; khi mở, repository gọi API, rồi cập nhật (upsert) vào kho; @Query thấy thay đổi và UI tự đổi. Nếu mất mạng, người dùng vẫn thấy dữ liệu cũ và một banner trạng thái.

    Những điều cần quyết định sớm: khóa định danh (dùng id từ server), chiến lược xung đột (server thắng hay thay đổi cục bộ thắng), dữ liệu bị xóa ở server xử lý thế nào, thời điểm làm mới, và migration khi model đổi (SwiftData hỗ trợ migration có phiên bản; hãy thử trước khi phát hành). Nếu cần hỗ trợ iOS dưới 17, dùng Core Data hoặc SQLite wrapper.

    6. So sánh với Ionic/Angular và lỗi thường gặp¶

    So sánh: • localStorage/Capacitor Preferences ~ UserDefaults/@AppStorage. • Capacitor Filesystem ~ FileManager. • IndexedDB/SQLite plugin/Ionic Storage ~ SwiftData/Core Data. • Secure Storage plugin ~ Keychain.

    Lỗi thường gặp: 1. Lưu token hay mật khẩu trong UserDefaults: không an toàn. 2. Lưu dữ liệu lớn vào UserDefaults: chậm, bị giới hạn. 3. Khóa chuỗi gõ sai ở nhiều nơi: dùng hằng/@AppStorage với enum. 4. Ghi file không nguyên tử: file hỏng khi app bị kill giữa chừng. 5. Quên .modelContainer(for:): crash No ModelContext khi dùng @Query. 6. Đổi model SwiftData mà không có migration: mất dữ liệu hoặc crash khi mở app cũ. 7. Không kiểm soát luồng: ModelContext không thread-safe, dùng trên main (hoặc ModelActor).

    7. Tóm tắt¶

    • Chọn nơi lưu theo loại dữ liệu: UserDefaults (cài đặt), file (blob/JSON nhỏ), SwiftData (có cấu trúc), Keychain (bí mật). • @AppStorage kết nối UserDefaults với state SwiftUI. • Ghi file với .atomic; dùng thư mục Documents/Caches đúng mục đích. • SwiftData: @Model, ModelContainer, ModelContext, @Query. • Offline-first: UI đọc từ kho cục bộ, mạng chỉ đồng bộ vào kho.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Lưu cài đặt¶

    Thêm cài đặt "Tự động kết nối" bằng @AppStorage. Giải thích vì sao không dùng UserDefaults để lưu token đăng nhập.

    Gợi ý @AppStorage trả về Binding qua $. Token là bí mật.
    Đáp án 
    import SwiftUI

struct SettingsScreen: View {
    @AppStorage("settings.autoConnect") private var autoConnect = true

    var body: some View {
        Form {
            Toggle("Tự động kết nối", isOn: $autoConnect)
        }
    }
}
    **Giải thích:** UserDefaults không mã hóa và dễ bị đọc từ bản sao lưu/thiết bị bị jailbreak. Token cần Keychain, nơi có bảo vệ phần cứng.

    Bài 2 — Lưu mảng xe vào file¶

    Viết VehicleFileStore với load() và save(_:) lưu [Vehicle] thành JSON trong Documents. File chưa tồn tại thì trả mảng rỗng. Vì sao nên ghi .atomic?

    Gợi ý URL.documentsDirectory.appending(path:), JSONEncoder/Decoder, write(options: .atomic).
    Đáp án 
    import Foundation

struct Vehicle: Codable { let id: String; var name: String }

struct VehicleFileStore {
    private let url = URL.documentsDirectory.appending(path: "vehicles.json")

    func load() throws -> [Vehicle] {
        guard FileManager.default.fileExists(atPath: url.path) else { return [] }
        return try JSONDecoder().decode([Vehicle].self, from: Data(contentsOf: url))
    }

    func save(_ vehicles: [Vehicle]) throws {
        try JSONEncoder().encode(vehicles).write(to: url, options: .atomic)
    }
}
    **Giải thích:** Ghi nguyên tử viết ra file tạm rồi đổi tên, nên nếu app bị kill giữa chừng, file cũ vẫn nguyên vẹn thay vì bị cắt dở.

    Bài 3 — SwiftData cơ bản¶

    Tạo @Model VehicleEntity với id duy nhất, hiển thị bằng @Query sắp xếp theo năm giảm dần, có thêm và xóa. Quên .modelContainer thì chuyện gì xảy ra?

    Gợi ý context.insert, context.delete, @Query(sort:order:).
    Đáp án 
    import SwiftUI
import SwiftData

@Model
final class VehicleEntity {
    @Attribute(.unique) var id: String
    var name: String
    var year: Int
    init(id: String, name: String, year: Int) { self.id = id; self.name = name; self.year = year }
}

struct SavedList: View {
    @Environment(\.modelContext) private var context
    @Query(sort: \VehicleEntity.year, order: .reverse) private var items: [VehicleEntity]

    var body: some View {
        List {
            ForEach(items) { Text("\($0.name) \($0.year)") }
                .onDelete { for i in $0 { context.delete(items[i]) } }
        }
        .toolbar {
            Button("Thêm") { context.insert(VehicleEntity(id: UUID().uuidString, name: "Camry", year: 2024)) }
        }
    }
}
// Cần .modelContainer(for: VehicleEntity.self) ở WindowGroup/view cha; nếu thiếu, app crash vì không có ModelContext.
    **Giải thích:** `@Query` tự cập nhật khi context thay đổi. `ModelContainer` là kho thật sự; thiếu nó, môi trường không có `modelContext` nên truy cập sẽ lỗi.

    Bài 4 — Thiết kế offline-first¶

    Mô tả luồng khi mở màn hình danh sách xe để app hoạt động cả khi mất mạng: nguồn dữ liệu cho UI, khi nào gọi API, xử lý khi API lỗi và xung đột.

    Gợi ý UI đọc từ kho cục bộ; API chỉ cập nhật kho.
    Đáp án 1. UI luôn đọc từ SwiftData (@Query): hiển thị ngay dữ liệu đã lưu. 2. Khi màn hình xuất hiện (.task), repository gọi API ở nền. 3. Thành công: upsert theo id vào SwiftData -> @Query tự cập nhật UI. 4. Lỗi/offline: giữ nguyên dữ liệu cũ, hiển thị banner "Đang offline" + nút làm mới. 5. Xung đột: chọn chiến lược rõ (ví dụ server thắng với dữ liệu chỉ đọc; với dữ liệu người dùng sửa cục bộ, đánh dấu pendingSync và đẩy lên khi có mạng). 6. Xóa ở server: so sánh danh sách id để xóa bản ghi cục bộ tương ứng. **Giải thích:** Chỉ có một nguồn sự thật cho UI (kho cục bộ) nên UI nhất quán dù mạng ra sao. Các quyết định xung đột cần được chốt sớm vì ảnh hưởng thiết kế dữ liệu.
