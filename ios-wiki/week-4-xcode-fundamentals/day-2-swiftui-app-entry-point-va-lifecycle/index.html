    Tuần 4 · Ngày 2 · SwiftUI App entry point và lifecycle¶

    Mục tiêu: Hiểu @main, App, Scene, WindowGroup, vòng đời scene và cách theo dõi scenePhase.
    Thời lượng: 75–90 phút

    Khái niệm: @main, App protocol, Scene, WindowGroup, scenePhase, UIApplicationDelegateAdaptor

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Điểm vào của ứng dụng¶

    Mỗi app Swift cần một điểm vào. Trong project SwiftUI, đó là struct có thuộc tính @main và conform protocol App. Compiler sinh hàm main() thay bạn: nó khởi tạo struct và khởi động vòng lặp sự kiện.

    Tương đương trong Angular: main.ts gọi bootstrapApplication(AppComponent). Ở SwiftUI, @main struct MyApp: App chính là main.ts, và ContentView là component gốc.

    import SwiftUI

@main
struct VehicleDiagnosticsApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

    2. App, Scene và WindowGroup¶

    App yêu cầu một thuộc tính body trả về some Scene. Scene mô tả một "phần giao diện" mà hệ điều hành quản lý. WindowGroup là scene phổ biến nhất: nó tạo cửa sổ chứa view gốc của bạn. Trên iPhone có một cửa sổ; trên iPad và Mac, người dùng có thể mở nhiều cửa sổ cho cùng một app, mỗi cửa sổ có trạng thái riêng.

    some Scene là opaque type (bài 2.4): hàm trả về một kiểu cụ thể nhưng ẩn tên. Bạn không cần quan tâm kiểu thật, chỉ cần biết nó là Scene.

    Bạn có thể giữ state toàn app ở App bằng @State (cho state giá trị) hoặc tạo đối tượng dùng chung rồi truyền xuống bằng environment (tuần 5, 7).

    3. Vòng đời: scenePhase¶

    Ứng dụng iOS không chỉ chạy hoặc tắt. Mỗi scene có ba phase: • .active: đang hiển thị và nhận tương tác. • .inactive: hiển thị nhưng không tương tác (ví dụ đang kéo Control Center, cuộc gọi đến, chuyển app). • .background: không còn thấy. Hệ thống có thể tạm dừng hoặc tắt app bất kỳ lúc nào để lấy lại bộ nhớ, nên đây là lúc phải lưu dữ liệu.

    Đọc bằng @Environment(\.scenePhase) và phản ứng với .onChange. Dùng để: lưu dữ liệu khi vào background, tạm dừng quét BLE, làm mới dữ liệu khi quay lại active. Từ iOS 17 onChange nhận hai tham số (giá trị cũ, mới).

    import SwiftUI

@main
struct VehicleDiagnosticsApp: App {
    @Environment(\.scenePhase) private var scenePhase

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        .onChange(of: scenePhase) { oldPhase, newPhase in
            switch newPhase {
            case .active:     print("Đang hoạt động")
            case .inactive:   print("Tạm ngắt tương tác")
            case .background: print("Vào nền: lưu dữ liệu, dừng tác vụ không cần")
            @unknown default: break
            }
        }
    }
}

    4. UIApplicationDelegate khi cần¶

    Một số việc vẫn cần UIApplicationDelegate của UIKit: đăng ký push notification (device token), xử lý một số callback hệ thống, SDK bên thứ ba (Firebase…) yêu cầu hook vào application(_:didFinishLaunchingWithOptions:). SwiftUI cho phép dùng nó thông qua @UIApplicationDelegateAdaptor.

    Nguyên tắc: ưu tiên API thuần SwiftUI; chỉ dùng delegate khi framework yêu cầu. Giữ delegate mỏng, đưa logic về service riêng để dễ test.

    import SwiftUI
import UIKit

final class AppDelegate: NSObject, UIApplicationDelegate {
    func application(_ application: UIApplication,
                     didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]? = nil) -> Bool {
        print("App launched")
        return true
    }
}

@main
struct VehicleDiagnosticsApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) private var appDelegate

    var body: some Scene {
        WindowGroup { ContentView() }
    }
}

    5. So sánh với Angular/Ionic¶

    • bootstrapApplication ~ @main struct ...: App. • AppComponent ~ view gốc trong WindowGroup. • Ionic App.addListener('appStateChange') của Capacitor ~ scenePhase. • Ionic pause/resume ~ .background/.active. • APP_INITIALIZER ~ khởi tạo service ở App.init() hoặc ở composition root. • Hệ điều hành có thể giết app đang ở background mà không báo trước: khác với trang web, bạn không có sự kiện "beforeunload" đáng tin; vì vậy hãy lưu trạng thái quan trọng khi chuyển sang .background, không đợi đến lúc app thoát.

    6. Lỗi thường gặp¶

    1. Có hai @main trong cùng target: lỗi "Attribute 'main' can only apply to one type".
    2. Khởi tạo công việc nặng trong App.init() làm màn hình khởi động chậm: hãy lazy hoặc chạy bất đồng bộ.
    3. Đặt state quan trọng chỉ trong ContentView khi cần chia sẻ toàn app.
    4. Chạy công việc dài ở .background mà không xin thêm thời gian (beginBackgroundTask) rồi bị hệ thống dừng.
    5. Không lưu dữ liệu khi vào nền, mất dữ liệu khi hệ thống kill app.
    6. Quên rằng .inactive xảy ra trong nhiều tình huống tạm thời; đừng coi nó là "thoát app".

    7. Tóm tắt¶

    • @main + App: điểm vào, body trả về some Scene. • WindowGroup tạo cửa sổ chứa view gốc; mỗi scene có trạng thái riêng. • scenePhase: .active, .inactive, .background; dùng onChange để lưu dữ liệu và dừng tác vụ. • @UIApplicationDelegateAdaptor khi cần hook UIKit/SDK bên thứ ba. • Hệ thống có thể kill app ở nền: lưu dữ liệu sớm.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Theo dõi vòng đời¶

    Thêm scenePhase vào VehicleDiagnosticsApp để in ra phase mỗi lần thay đổi. Chạy trên Simulator, bấm Home (⇧⌘H) rồi mở lại app và ghi lại thứ tự các phase.

    Gợi ý @Environment(\.scenePhase) và .onChange(of:) gắn vào WindowGroup.
    Đáp án 
    import SwiftUI

@main
struct VehicleDiagnosticsApp: App {
    @Environment(\.scenePhase) private var scenePhase

    var body: some Scene {
        WindowGroup { ContentView() }
            .onChange(of: scenePhase) { _, newPhase in
                print("scenePhase = \(newPhase)")
            }
    }
}
// Khi bấm Home: inactive -> background. Mở lại: inactive -> active.
    **Giải thích:** App đi qua `.inactive` trước khi vào `.background` và cũng qua `.inactive` khi quay lại. Đây là lý do không nên lưu dữ liệu nặng ở `.inactive`.

    Bài 2 — Lưu dữ liệu khi vào nền¶

    Giả sử có class DraftStore { func save() }. Gọi save() khi app chuyển sang .background. Vì sao không gọi khi .inactive?

    Gợi ý Chỉ so sánh newPhase == .background.
    Đáp án 
    import SwiftUI

final class DraftStore { func save() { print("Saved") } }

@main
struct VehicleDiagnosticsApp: App {
    @Environment(\.scenePhase) private var scenePhase
    private let store = DraftStore()

    var body: some Scene {
        WindowGroup { ContentView() }
            .onChange(of: scenePhase) { _, newPhase in
                if newPhase == .background { store.save() }
            }
    }
}
    **Giải thích:** `.inactive` xảy ra thường xuyên và tạm thời (kéo thông báo, cuộc gọi), gọi save ở đó gây lưu thừa. `.background` là tín hiệu đáng tin rằng người dùng đã rời app và hệ thống có thể kill nó.

    Bài 3 — Ánh xạ khái niệm¶

    Lập bảng ánh xạ: main.ts/bootstrapApplication, AppComponent, App.addListener("appStateChange") của Capacitor, APP_INITIALIZER tương ứng với khái niệm nào trong SwiftUI?

    Gợi ý Hãy nghĩ tới @main, WindowGroup, scenePhase và init của App.
    Đáp án 
    main.ts / bootstrapApplication  ->  @main struct MyApp: App
AppComponent                      ->  view gốc trong WindowGroup { ContentView() }
appStateChange (Capacitor)        ->  @Environment(\.scenePhase) + onChange
APP_INITIALIZER                   ->  init() của App hoặc composition root
    **Giải thích:** Ánh xạ này giúp bạn tìm đúng "nơi để làm việc X" khi chuyển từ Angular sang SwiftUI, thay vì tìm kiếm các khái niệm không tồn tại.
