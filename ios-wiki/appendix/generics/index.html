    Phụ lục · Generics trong Swift¶

    Mục tiêu: Viết hàm và kiểu dùng cho nhiều kiểu dữ liệu bằng generics, hiểu constraint, associatedtype, và phân biệt generic với some/any.
    Thời lượng: Tham khảo khi cần

    Khái niệm: generic function, generic type, constraint, where, associatedtype, some / any, property wrapper

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Vấn đề generics giải quyết¶

    Giả sử bạn cần hoán đổi hai giá trị. Không có generics, bạn phải viết swapInts, swapStrings, swapDoubles… với thân hàm y hệt. Generics cho phép viết một lần với "kiểu giữ chỗ" T, compiler tự áp dụng cho từng kiểu cụ thể mà vẫn kiểm tra kiểu đầy đủ.

    Bạn đã dùng generics từ tuần 1: Array<Element>, Dictionary<Key, Value>, Set<Element>, Optional<Wrapped>, Result<Success, Failure> đều là kiểu generic. [Int] chỉ là cách viết gọn của Array<Int>.

    // Không generics: lặp code
func swapInts(_ a: inout Int, _ b: inout Int) { let t = a; a = b; b = t }
func swapStrings(_ a: inout String, _ b: inout String) { let t = a; a = b; b = t }

// Có generics: một lần cho mọi kiểu
func swapValues<T>(_ a: inout T, _ b: inout T) { let t = a; a = b; b = t }

var x = 1, y = 2
swapValues(&x, &y)                    // T = Int, suy luận tự động
var s1 = "a", s2 = "b"
swapValues(&s1, &s2)                  // T = String
print(x, y, s1, s2)                   // 2 1 b a

    2. Generic function và generic type¶

    Tham số kiểu đặt trong dấu <> sau tên hàm hoặc kiểu: func f<T>(...), struct Stack<Element>. Compiler suy luận kiểu từ đối số; với kiểu generic bạn thường viết rõ khi khởi tạo (Stack<String>()) trừ khi suy luận được.

    Kiểu generic dùng được cho: collection tự viết (Stack, Queue, Cache), kết quả/trạng thái (LoadState<Value>), wrapper (Box<T>), cặp giá trị (Pair<A, B>). Tên tham số kiểu: T, U khi tổng quát, hoặc tên có nghĩa (Element, Key, Value, Item) khi vai trò rõ.

    struct Stack<Element> {
    private var storage: [Element] = []
    var isEmpty: Bool { storage.isEmpty }
    mutating func push(_ item: Element) { storage.append(item) }
    mutating func pop() -> Element? { storage.popLast() }      // Optional: rỗng thì nil
    func peek() -> Element? { storage.last }
}

struct Pair<A, B> {
    let first: A
    let second: B
    func swapped() -> Pair<B, A> { Pair<B, A>(first: second, second: first) }
}

var numbers = Stack<Int>()
numbers.push(1); numbers.push(2)
print(numbers.pop() ?? -1, numbers.peek() ?? -1)               // 2 1

let p = Pair(first: "V1", second: 2024)                        // suy luận Pair<String, Int>
print(p.swapped().first)                                       // 2024

    3. Ràng buộc (constraint) và mệnh đề where¶

    Khi thân hàm cần một khả năng của kiểu (so sánh, cộng, băm), phải ràng buộc tham số kiểu bằng protocol: <T: Comparable>. Compiler từ chối dùng < với T không ràng buộc. Có thể ràng buộc nhiều protocol bằng & (T: Hashable & Comparable) hoặc ràng buộc vào lớp (T: Animal).

    Mệnh đề where diễn đạt ràng buộc phức tạp, nhất là liên quan tới kiểu liên kết: where C.Element: Equatable, where A.Element == B.Element. Các protocol hay dùng làm ràng buộc: Equatable, Hashable, Comparable, Numeric, Identifiable, Codable, Sequence, Collection.

    func largest<T: Comparable>(_ items: [T]) -> T? { items.max() }

func uniqueSorted<T: Hashable & Comparable>(_ items: [T]) -> [T] {
    Array(Set(items)).sorted()
}

func sum<T: Numeric>(_ items: [T]) -> T { items.reduce(0, +) }

func allEqual<C: Collection>(_ items: C) -> Bool where C.Element: Equatable {
    guard let first = items.first else { return true }
    return items.allSatisfy { $0 == first }
}

func merged<A: Sequence, B: Sequence>(_ a: A, _ b: B) -> [A.Element] where A.Element == B.Element {
    Array(a) + Array(b)
}

class Animal { }
func feed<T: Animal>(_ animal: T) -> String { "fed \(type(of: animal))" }   // ràng buộc vào lớp

print(largest([3, 9, 4]) ?? 0, uniqueSorted([3, 1, 3, 2]), sum([1.5, 2.5]))
print(allEqual([1, 1, 1]), merged([1, 2], Set([3])).count, feed(Animal()))

    4. associatedtype và primary associated types¶

    Protocol không viết <T> mà dùng associatedtype: một kiểu giữ chỗ do kiểu conform quyết định. Ví dụ Collection có Element, Repository có Item.

    Hệ quả: protocol có associatedtype (hoặc Self requirement) không dùng được như một kiểu trơn (var x: Repository sai). Bạn dùng nó như ràng buộc generic (<R: Repository>), hoặc some/any.

    Từ Swift 5.7, protocol khai báo "primary associated types" nên viết được some Collection<Int> hoặc any Collection<String> (chỉ rõ kiểu phần tử), rất gọn. Collection, Sequence, Publisher đều hỗ trợ.

    protocol Container {
    associatedtype Item
    var items: [Item] { get }
    mutating func add(_ item: Item)
}

struct IntBox: Container {
    var items: [Int] = []
    mutating func add(_ item: Int) { items.append(item) }          // Item suy luận là Int
}

func fill<C: Container>(_ container: inout C, with values: [C.Item]) {
    values.forEach { container.add($0) }
}

var box = IntBox()
fill(&box, with: [1, 2, 3])

// Primary associated types: chỉ rõ Element ngay trong kiểu
func total(of numbers: some Collection<Int>) -> Int { numbers.reduce(0, +) }
func describe(_ names: any Collection<String>) -> String { names.joined(separator: ", ") }

print(box.items, total(of: [1, 2, 3]), describe(["A", "B"]))

    5. Generic, some và any: chọn cái nào¶

    Ba cách dùng protocol làm kiểu, khác nhau về lúc quyết định kiểu và chi phí: • Generic <S: Scanner>: kiểu cụ thể được xác định tại lời gọi, compiler chuyên biệt hóa mã, nhanh nhất. Dùng khi cần nhắc nhiều lần tới cùng một kiểu (ví dụ hai tham số phải cùng kiểu) hoặc ràng buộc phức tạp. • some Scanner: cú pháp rút gọn của generic cho tham số, hoặc kiểu trả về "ẩn tên nhưng cố định" (some View). Một lời gọi luôn trả về cùng một kiểu thật. • any Scanner: existential, kiểu thật quyết định lúc chạy; có thể lưu nhiều kiểu khác nhau trong một mảng, đổi giá trị giữa các kiểu. Linh hoạt nhất, có chi phí nhỏ (boxing, dynamic dispatch).

    Quy tắc: mặc định some/generic; dùng any khi thực sự cần trộn nhiều kiểu hoặc lưu protocol trong thuộc tính.

    protocol Scanner { func scan() -> String }
struct ObdScanner: Scanner { func scan() -> String { "OBD" } }
struct BleScanner: Scanner { func scan() -> String { "BLE" } }

func useGeneric<S: Scanner>(_ s: S) -> String { s.scan() }              // chuyên biệt hóa lúc biên dịch
func useSome(_ s: some Scanner) -> String { s.scan() }                  // rút gọn của generic
func useAny(_ s: any Scanner) -> String { s.scan() }                    // dynamic

func sameKind<S: Scanner>(_ a: S, _ b: S) -> Bool { a.scan() == b.scan() }   // generic: hai tham số CÙNG kiểu
// sameKind(ObdScanner(), BleScanner())   // LỖI: hai kiểu khác nhau

let mixed: [any Scanner] = [ObdScanner(), BleScanner()]                 // chỉ any trộn được nhiều kiểu
print(mixed.map { $0.scan() }, useGeneric(ObdScanner()), useSome(BleScanner()), useAny(ObdScanner()))

func makeDefault() -> some Scanner { ObdScanner() }                      // kiểu trả về ẩn tên, cố định
print(makeDefault().scan(), sameKind(ObdScanner(), ObdScanner()))

    6. Generics trong thực tế: Cache, property wrapper, API client¶

    Một số mẫu generic bạn sẽ gặp và tự viết: • Collection/cache tổng quát: Cache<Key: Hashable, Value>. • Trạng thái tải dữ liệu: LoadState<Value> (tuần 5). • API client: func get<T: Decodable>(_ path: String) async throws -> T (tuần 6): người gọi chỉ định kiểu kết quả, một hàm dùng cho mọi endpoint. • Repository generic với associatedtype hoặc <Item: Identifiable> (tuần 2). • Property wrapper generic: @Clamped(0...100) var volume, @AppStorage, @State đều là generic.

    Swift 5.9 còn có variadic generics (parameter packs, each T) cho số lượng tham số kiểu bất kỳ; dùng khi viết thư viện, hiếm cần trong app.

    struct Cache<Key: Hashable, Value> {
    private var storage: [Key: Value] = [:]
    private var order: [Key] = []
    let capacity: Int

    init(capacity: Int) { self.capacity = capacity }

    mutating func set(_ value: Value, for key: Key) {
        if storage[key] == nil { order.append(key) }
        storage[key] = value
        if order.count > capacity { storage[order.removeFirst()] = nil }   // loại phần tử cũ nhất
    }
    func value(for key: Key) -> Value? { storage[key] }
}

@propertyWrapper
struct Clamped<Value: Comparable> {
    private var value: Value
    let range: ClosedRange<Value>

    init(wrappedValue: Value, _ range: ClosedRange<Value>) {
        self.range = range
        self.value = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }
    var wrappedValue: Value {
        get { value }
        set { value = min(max(newValue, range.lowerBound), range.upperBound) }
    }
}

struct Settings { @Clamped(0...100) var volume = 50 }

enum LoadState<Value> { case idle, loading, loaded(Value), failed(String) }

var cache = Cache<String, Int>(capacity: 2)
cache.set(1, for: "a"); cache.set(2, for: "b"); cache.set(3, for: "c")
print(cache.value(for: "a") as Any, cache.value(for: "c") ?? -1)     // nil 3
var settings = Settings(); settings.volume = 250
print(settings.volume)                                                // 100
let state: LoadState<[String]> = .loaded(["A"])
if case .loaded(let items) = state { print(items) }

    7. Giới hạn của generics¶

    • Generic type là invariant: Stack<Dog> không dùng được thay Stack<Animal> dù Dog là subclass của Animal. (Array, Optional, Dictionary là ngoại lệ do compiler hỗ trợ đặc biệt.) • Protocol có associatedtype/Self không dùng làm kiểu trơn: cần some/any hoặc generic. • Không thể quyết định kiểu hoàn toàn lúc chạy: nếu cần kiểu động, dùng any hoặc enum. • Không có "specialization" tùy biến theo kiểu như C++ templates; bạn dùng extension có điều kiện/overload. • Quá nhiều lớp generic làm thông báo lỗi dài và thời gian biên dịch tăng. • Kiểu generic khó dùng với Objective-C (không bridging được).

    8. So sánh với TypeScript, Java, C++ và Kotlin¶

    • TypeScript: function f<T>(x: T) giống nhau về cú pháp, nhưng generics TS chỉ là thông tin lúc biên dịch (bị xóa), cấu trúc (structural) và có conditional/mapped types; Swift dùng protocol conformance làm ràng buộc, kiểu tồn tại lúc chạy, không có conditional types. • T extends Comparable (TS/Java/Kotlin) ↔ T: Comparable (Swift). • Java: generics bị type erasure; Swift chuyên biệt hóa (nhanh, giữ kiểu). • C++ templates: tương tự về chuyên biệt hóa nhưng Swift kiểm tra ràng buộc từ đầu (không lỗi "bên trong template"). • Kotlin: reified cho kiểu lúc chạy (chỉ inline); Swift giữ kiểu mặc định. • Promise<T>/Observable<T> ↔ async -> T/AsyncSequence; Array<T> ↔ [T].

    9. Lỗi thường gặp¶

    1. "Binary operator '+' cannot be applied to operands of type 'T'": thiếu ràng buộc Numeric/Comparable/…
    2. "Protocol 'X' can only be used as a generic constraint because it has Self or associated type requirements": dùng some/any hoặc generic.
    3. "Generic parameter 'T' could not be inferred": thêm kiểu tường minh (Stack<Int>(), decode(User.self…)).
    4. Lạm dụng Any/[String: Any] thay vì generics hoặc enum: mất an toàn kiểu.
    5. Over-engineering: viết generic cho thứ chỉ dùng với một kiểu.
    6. Nhầm some (một kiểu cố định) với any (nhiều kiểu): hàm trả some P không được trả hai kiểu khác nhau theo điều kiện.
    7. Đặt ràng buộc quá rộng/hẹp so với nhu cầu thật: Collection thay vì [T] giúp hàm dùng được cho nhiều dãy hơn.

    10. Tóm tắt¶

    • Generics: một mã cho nhiều kiểu, giữ an toàn kiểu; compiler chuyên biệt hóa. • Ràng buộc bằng protocol (<T: Comparable>) và where. • associatedtype là generic của protocol; dùng some/any hoặc ràng buộc khi dùng làm kiểu. • Chọn: generic/some (nhanh, một kiểu cố định), any (trộn nhiều kiểu). • Mẫu thực tế: Cache, LoadState, API client get<T: Decodable>, repository, property wrapper. • Giới hạn: invariant, protocol có associatedtype, thông báo lỗi dài.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Thực hành 1 — Hàm generic với ràng buộc¶

    Viết func groupBy<T, K: Hashable>(_ items: [T], key: (T) -> K) -> [K: [T]] và dùng nó để nhóm danh sách tên xe theo chữ cái đầu. Vì sao K cần Hashable?

    Gợi ý Dùng reduce(into:) hoặc Dictionary(grouping:by:).
    Đáp án 
    func groupBy<T, K: Hashable>(_ items: [T], key: (T) -> K) -> [K: [T]] {
    items.reduce(into: [K: [T]]()) { result, item in
        result[key(item), default: []].append(item)
    }
}

let names = ["Camry", "Civic", "Focus", "Corolla"]
let byLetter = groupBy(names) { $0.first! }       // [Character: [String]]
print(byLetter["C"] ?? [])
    **Giải thích:** `K` làm khóa dictionary nên phải `Hashable`. Hàm generic ở hai tham số kiểu: `T` cho phần tử và `K` cho khóa nhóm, dùng được với mọi kiểu dữ liệu.

    Thực hành 2 — Queue generic¶

    Viết struct Queue<Element> với enqueue, dequeue (Optional), peek, count. Thêm extension Queue: Equatable where Element: Equatable. Giải thích conditional conformance.

    Gợi ý Dùng mảng lưu trữ; extension có where cho Equatable.
    Đáp án 
    struct Queue<Element> {
    private var storage: [Element] = []
    var count: Int { storage.count }
    func peek() -> Element? { storage.first }
    mutating func enqueue(_ item: Element) { storage.append(item) }
    mutating func dequeue() -> Element? { storage.isEmpty ? nil : storage.removeFirst() }
}

extension Queue: Equatable where Element: Equatable {
    static func == (lhs: Queue, rhs: Queue) -> Bool { lhs.storage == rhs.storage }
}

var q1 = Queue<Int>(); q1.enqueue(1); q1.enqueue(2)
var q2 = Queue<Int>(); q2.enqueue(1); q2.enqueue(2)
print(q1 == q2, q1.dequeue() ?? -1)    // true 1
    **Giải thích:** Queue so sánh được nhưng Queue thì không, vì chỉ có conformance khi phần tử so sánh được. Thư viện chuẩn làm tương tự cho Array.

    Thực hành 3 — some hay any¶

    Chọn some, any hay generic cho: (a) hàm in thông tin của một Scanner bất kỳ; (b) mảng chứa nhiều loại scanner; (c) hàm so sánh hai scanner phải cùng kiểu; (d) hàm trả về scanner mặc định.

    Gợi ý Hỏi: có cần trộn nhiều kiểu? có cần hai tham số cùng kiểu?
    Đáp án 
    protocol Scanner { func scan() -> String }

func show(_ s: some Scanner) { print(s.scan()) }                  // (a) some (hoặc generic)
let all: [any Scanner] = []                                        // (b) any: trộn nhiều kiểu
func same<S: Scanner>(_ a: S, _ b: S) -> Bool { a.scan() == b.scan() }   // (c) generic: cùng kiểu
struct Obd: Scanner { func scan() -> String { "OBD" } }
func makeDefault() -> some Scanner { Obd() }                       // (d) some: một kiểu cố định, ẩn tên
    **Giải thích:** Chỉ `any` trộn được nhiều kiểu trong một collection; generic cần thiết khi nhiều tham số phải cùng kiểu; `some` gọn cho trường hợp còn lại.

    Thực hành 4 — API client generic¶

    Viết func get<T: Decodable>(_ json: String, as type: T.Type = T.self) throws -> T giải mã JSON chuỗi thành T. Dùng cho hai kiểu khác nhau (Vehicle và [Vehicle]).

    Gợi ý JSONDecoder().decode(T.self, from:).
    Đáp án 
    import Foundation

struct Vehicle: Decodable { let id: String; let name: String }

func get<T: Decodable>(_ json: String, as type: T.Type = T.self) throws -> T {
    try JSONDecoder().decode(T.self, from: Data(json.utf8))
}

let one: Vehicle = try get(#"{"id":"1","name":"Camry"}"#)
let many = try get(#"[{"id":"1","name":"A"},{"id":"2","name":"B"}]"#, as: [Vehicle].self)
print(one.name, many.count)
    **Giải thích:** Một hàm phục vụ mọi kiểu `Decodable`; người gọi chỉ định kiểu kết quả qua annotation hoặc tham số `as:`. Đây là nền của `APIClient.get` ở tuần 6.
