    Phụ lục · Null-safety trong Swift¶

    Mục tiêu: Hiểu Optional là một kiểu, dùng thành thạo các cách mở Optional, thiết kế API không có null bất ngờ và xử lý dữ liệu ngoài (JSON, UI) an toàn.
    Thời lượng: Tham khảo khi cần

    Khái niệm: Optional, if let / guard let, ?? / ?., map / flatMap, IUO, failable init, decodeIfPresent

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Vấn đề null và cách Swift giải quyết¶

    Tony Hoare gọi tham chiếu null là "sai lầm tỷ đô": một giá trị đặc biệt có thể nằm ở bất kỳ biến nào, và chương trình crash khi dùng nó ("Cannot read property of undefined"). Cách giải của Swift là đưa "có thể vắng mặt" vào hệ thống kiểu: • Kiểu thường (String, Int, Vehicle) KHÔNG BAO GIỜ là nil. • Giá trị có thể vắng mặt phải khai báo là Optional (String?). • Compiler bắt bạn xử lý trường hợp nil trước khi dùng giá trị.

    Nhờ đó câu hỏi "biến này có thể nil không?" được trả lời ngay từ kiểu, và phần lớn lỗi null bị bắt khi biên dịch thay vì trên máy người dùng. Đây là null-safety.

    2. Optional là một enum¶

    Optional<Wrapped> thật ra là một enum generic có hai case: .none (viết là nil) và .some(Wrapped). String? là cách viết gọn của Optional<String>. Bạn có thể dùng pattern matching như với mọi enum: case .some(let x), hoặc dạng gọn let x?.

    Quy tắc khởi tạo: biến var Optional tự động có giá trị nil; hằng let Optional không tự có, phải gán. for case let x? in array duyệt và bỏ qua phần tử nil.

    let name: String? = "Camry"

switch name {
case .some(let n): print("có: \(n)")
case .none:        print("nil")
}

if case let n? = name { print(n) }                      // pattern x?

var plate: String?                                       // var Optional tự nil
print(plate == nil)                                      // true
// let id: String?                                       // let Optional phải gán giá trị mới dùng được

let maybeNumbers: [Int?] = [1, nil, 3]
for case let n? in maybeNumbers { print(n) }             // chỉ in 1 và 3

    3. Hộp công cụ mở Optional¶

    Chọn công cụ theo ý định: • if let / if let x (rút gọn): làm việc nếu có giá trị; hỗ trợ nhiều binding trong một câu (if let a, let b). • guard let: thoát sớm nếu thiếu; giá trị dùng được cho phần còn lại của hàm. • ??: giá trị mặc định khi nil. Muốn gán mặc định vào biến đang nil, viết x = x ?? mặcĐịnh (Swift không có toán tử ??=). • ?. (optional chaining): truy cập dây chuyền; một mắt xích nil thì cả chuỗi là nil. • map / flatMap: biến đổi giá trị bên trong mà không mở tay. • try?: biến lỗi thành nil. • ! (force unwrap): crash nếu nil. Chỉ khi bất biến được bảo đảm.

    Tránh tạo "kim tự tháp" if let lồng nhau: dùng guard let hoặc gộp binding.

    struct Owner { var name: String? }
struct Vehicle { var owner: Owner?; var year: Int? }
let v: Vehicle? = Vehicle(owner: Owner(name: "An"), year: nil)

if let owner = v?.owner, let name = owner.name { print(name) }       // nhiều binding
if let year = v?.year { print(year) } else { print("không có năm") }

let label = v?.owner?.name ?? "Chưa có chủ xe"                       // chaining + mặc định

var title: String?
title = title ?? "Untitled"                                         // gán mặc định nếu nil (Swift không có ??=)

func describe(_ v: Vehicle?) -> String {
    guard let v, let year = v.year else { return "unknown" }         // guard let rút gọn, thoát sớm
    return "year \(year)"
}
print(describe(v), label, title ?? "", Int("12") ?? 0)

    4. map, flatMap và Optional lồng nhau¶

    map áp một hàm lên giá trị bên trong nếu có; flatMap dùng khi hàm đó cũng trả Optional (tránh Int??). Trên mảng, compactMap map rồi bỏ nil.

    Bẫy kinh điển: Optional lồng nhau T??. Dictionary có giá trị Optional ([String: Int?]) khi tra khóa trả về Int??: ba tình huống khác nhau (không có khóa, có khóa nhưng nil, có giá trị). Nếu không cần phân biệt, làm phẳng bằng ?? nil hoặc tránh lưu Optional trong dictionary (xóa khóa thay vì gán nil).

    import Foundation

let dict: [String: Int?] = ["a": 1, "b": nil]
let a = dict["a"]          // Optional(Optional(1))
let b = dict["b"]          // Optional(nil): CÓ khóa nhưng giá trị nil
let z = dict["z"]          // nil: KHÔNG có khóa
let flat: Int? = dict["a"] ?? nil                       // làm phẳng: Optional(1)

let ids = ["1", "x", "3"].compactMap(Int.init)         // [1, 3]
let doubled = ids.map { $0 * 2 }                       // [2, 6]

let name: String? = "  An "
let length = name.map { $0.trimmingCharacters(in: .whitespaces) }.map(\.count)   // Int?
let parsed = name.flatMap { Int($0.trimmingCharacters(in: .whitespaces)) }        // Int? (nil vì "An" không phải số)
print(a as Any, b as Any, z as Any, flat as Any, length as Any, parsed as Any)

    5. Implicitly unwrapped Optional và weak/unowned¶

    T! (implicitly unwrapped optional, IUO) là Optional được tự mở mỗi lần dùng; nil thì crash. Nó tồn tại cho trường hợp "chắc chắn sẽ có giá trị trước khi dùng nhưng chưa có ở lúc khởi tạo": @IBOutlet của UIKit, hoặc hai đối tượng khởi tạo vòng tròn. Trong code mới của bạn, tránh IUO; dùng Optional thường, lazy var, hoặc thiết kế lại để khởi tạo đủ ngay.

    Liên quan: tham chiếu weak luôn là Optional vì có thể về nil khi đối tượng bị giải phóng; unowned không Optional nhưng crash nếu truy cập sau khi giải phóng (tuần 3). Đây là lý do delegate luôn là weak var delegate: X?.

    final class Screen {
    var title: String!                       // IUO: hứa sẽ gán trước khi dùng
    weak var delegate: AnyObject?            // weak luôn là Optional

    func configure() { title = "Home" }
    func titleLength() -> Int { title.count }   // tự mở: nil thì crash
}

let s = Screen()
s.configure()                                // phải gọi trước, nếu không titleLength() crash
print(s.titleLength())

    6. Thiết kế API null-safe¶

    Null-safety tốt nằm ở thiết kế, không chỉ ở cú pháp: • Trả về collection rỗng thay vì nil khi "không có kết quả" ([], không phải [T]?): người gọi khỏi phải xử lý hai kiểu "rỗng". • Dùng Optional cho "có thể không có" bình thường (tìm không thấy); dùng throws khi cần biết lý do thất bại; dùng enum khi có nhiều kết quả nghiệp vụ. • "Parse, don't validate": biến dữ liệu thô thành kiểu bảo đảm hợp lệ ngay biên (Email, Year) bằng failable init (init?) hoặc throwing init; phần còn lại của app nhận kiểu đã hợp lệ và khỏi kiểm tra lại. • Đặt giá trị mặc định có nghĩa nghiệp vụ, không dùng giá trị "ma thuật" (-1, "") để biểu diễn nil. • Khởi tạo đầy đủ: thuộc tính bắt buộc là non-optional và gán trong init.

    import Foundation

struct Email {
    let value: String

    init?(_ raw: String) {                                       // failable init: thất bại thì nil
        let normalized = raw.trimmingCharacters(in: .whitespaces).lowercased()
        let parts = normalized.split(separator: "@")
        guard parts.count == 2, parts[1].contains(".") else { return nil }
        value = normalized
    }
}

func send(to email: Email) { print("gửi tới \(email.value)") }    // chỉ nhận Email hợp lệ, khỏi kiểm tra lại

if let email = Email(" An@Example.com ") { send(to: email) }
print(Email("sai") == nil)

enum YearError: Error { case outOfRange(Int) }
struct Year {
    let value: Int
    init(_ value: Int) throws {                                  // throwing init: cần biết lý do
        guard (1990...2100).contains(value) else { throw YearError.outOfRange(value) }
        self.value = value
    }
}

// Trả về mảng rỗng thay vì nil
func matching(_ text: String, in all: [String]) -> [String] { all.filter { $0.contains(text) } }
print(matching("C", in: ["Camry", "Honda"]), (try? Year(2024).value) ?? 0)

    7. Null-safety với dữ liệu ngoài: JSON và Codable¶

    Dữ liệu từ server là nơi nil xuất hiện nhiều nhất: field thiếu, field null, kiểu sai. Với Codable: • Khai báo Optional cho field có thể thiếu hoặc null; decode tự gán nil. • Field bắt buộc là non-optional: thiếu thì decode ném keyNotFound (bạn biết ngay hợp đồng bị vi phạm). • decodeIfPresent + ?? mặc định trong init(from:) khi muốn giá trị mặc định cho field thiếu. • Tách DTO (có Optional, giống server) khỏi domain model (non-optional, đã chuẩn hóa) và chuyển ở một chỗ (tuần 6).

    Với [String: Any] từ API cũ hoặc UserDefaults: dùng as? và if let, không dùng as!.

    import Foundation

struct VehicleDTO: Decodable {
    let id: String                 // bắt buộc
    let mileage: Double?           // thiếu hoặc null -> nil
    let fuel: String               // mặc định "unknown" nếu thiếu

    enum CodingKeys: String, CodingKey { case id, mileage, fuel }

    init(from decoder: Decoder) throws {
        let c = try decoder.container(keyedBy: CodingKeys.self)
        id = try c.decode(String.self, forKey: .id)
        mileage = try c.decodeIfPresent(Double.self, forKey: .mileage)
        fuel = try c.decodeIfPresent(String.self, forKey: .fuel) ?? "unknown"
    }
}

let json = #"{"id":"V1","mileage":null}"#.data(using: .utf8)!
let dto = try JSONDecoder().decode(VehicleDTO.self, from: json)
print(dto.id, dto.mileage as Any, dto.fuel)                  // V1 nil unknown

let raw: [String: Any] = ["year": 2024, "name": "Camry"]
if let year = raw["year"] as? Int, let name = raw["name"] as? String { print(name, year) }   // as? an toàn

    8. Null-safety trong SwiftUI và concurrency¶

    • .sheet(item:): truyền Binding<Item?>; nil nghĩa là không hiển thị, có giá trị thì hiển thị với item đã mở hộp. Một state Optional thay cho cặp Bool + dữ liệu. • if let trong body để hiển thị phần tử có điều kiện; tránh !. • Optional state cho kết quả chưa có (@State var result: Result?), nhưng với màn hình dữ liệu nên dùng enum LoadState (idle/loading/loaded/failed) để rõ ràng hơn Optional. • [weak self] + guard let self trong closure bất đồng bộ (tuần 3). • Task.sleep, URLSession ném lỗi thay vì trả nil: dùng try đúng chỗ.

    import SwiftUI

struct Detail: Identifiable { let id: String }

struct ListScreen: View {
    @State private var selected: Detail?                      // nil = chưa chọn
    @State private var errorMessage: String?

    var body: some View {
        VStack(spacing: 12) {
            Button("Mở chi tiết") { selected = Detail(id: "V1") }
            if let message = errorMessage {                    // hiển thị có điều kiện
                Text(message).foregroundStyle(.red)
            }
        }
        .sheet(item: $selected) { detail in                    // detail đã được mở hộp (non-optional)
            Text("Chi tiết \(detail.id)")
        }
    }
}

    9. So sánh với TypeScript, Kotlin, Java và Objective-C¶

    • TypeScript strictNullChecks: string | null | undefined ↔ String?; ?. và ?? có cú pháp và ý nghĩa gần giống. Khác: Swift bắt buộc cho toàn ngôn ngữ (không tắt được) và chỉ có một giá trị vắng mặt (nil), không có undefined. ! non-null assertion của TS ↔ ! của Swift (crash thật nếu sai, còn TS chỉ "im lặng"). • Kotlin: String?, ?., ?: (↔ ??), !! (↔ !), x?.let { } (↔ if let/map) gần như tương đương. Kotlin có smart cast sau kiểm tra null; Swift cần mở hộp rõ ràng (if let). • Java: không có null-safety trong ngôn ngữ (Optional<T> chỉ là lớp thư viện, không bắt buộc); NullPointerException là lỗi phổ biến. • Objective-C: gửi message tới nil im lặng trả 0/nil; API được nhập vào Swift qua chú thích nullable/nonnull/_Nullable thành Optional hoặc non-Optional; thiếu chú thích thì thành IUO (T!). Cẩn trọng khi dùng API Objective-C cũ. • Angular: ?. trong template và strict mode tương tự; Swift thực thi ở mọi nơi.

    10. Lỗi thường gặp¶

    1. Thêm ! để "cho compiler im": crash lúc chạy. Dùng guard let/?? và xác định nil có hợp lệ hay là lỗi dữ liệu.
    2. Kim tự tháp if let lồng nhau: dùng guard let hoặc gộp binding.
    3. Dùng try! hoặc as! với dữ liệu ngoài.
    4. Dùng giá trị ma thuật ("", -1, 0) thay cho nil: lẫn với dữ liệu thật.
    5. Trả [T]? thay vì [T]: hai kiểu "rỗng".
    6. Optional lồng nhau T?? trong dictionary.
    7. Dùng IUO (T!) trong code mới.
    8. ?? mặc định che giấu lỗi thật; khi thiếu dữ liệu là bất thường, hãy báo lỗi.
    9. Quên rằng so sánh opt == value hợp lệ nhưng chỉ đúng khi có giá trị.
    10. DTO dùng thẳng làm model UI nên Optional lan khắp app: chuyển sang domain model non-optional ở biên.

    11. Tóm tắt¶

    • Kiểu thường không bao giờ nil; "có thể vắng mặt" phải là Optional (T?, thực chất là enum .some/.none). • Công cụ: if let, guard let, ??, ?., map/flatMap, try?; ! chỉ khi bất biến chắc chắn. • Tránh T?? và IUO; weak luôn Optional. • Thiết kế: trả collection rỗng, failable/throwing init, kiểu bảo đảm hợp lệ ("parse, don't validate"). • Dữ liệu ngoài: Optional trong DTO, decodeIfPresent + mặc định; chuyển sang domain model non-optional. • SwiftUI: state Optional cho .sheet(item:); LoadState cho màn hình dữ liệu.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Thực hành 1 — Sửa code dùng force unwrap¶

    Hàm sau có thể crash theo ba cách khác nhau. Viết lại an toàn, trả về String:

    func ownerLabel(_ v: Vehicle?, _ yearText: String) -> String { let name = v!.owner!.name! let year = Int(yearText)! return "(name) - (year)" }

    Gợi ý Dùng optional chaining, guard let và ?? (hoặc trả Optional).
    Đáp án 
    struct Owner { var name: String? }
struct Vehicle { var owner: Owner? }

func ownerLabel(_ v: Vehicle?, _ yearText: String) -> String {
    guard let name = v?.owner?.name else { return "Chưa có chủ xe" }
    let year = Int(yearText) ?? 0
    return year == 0 ? name : "\(name) - \(year)"
}

print(ownerLabel(nil, "2024"))
print(ownerLabel(Vehicle(owner: Owner(name: "An")), "abc"))
    **Giải thích:** Mỗi `!` ban đầu là một điểm crash: xe nil, owner nil, name nil, chuỗi không phải số. Optional chaining gom ba cái đầu, `??`/guard xử lý nil bằng hành vi có chủ ý.

    Thực hành 2 — Failable init¶

    Viết struct PlateNumber với init?(_ raw: String) chấp nhận chuỗi 6–12 ký tự (sau khi trim và viết hoa), nếu không hợp lệ trả nil. Viết hàm register(_ plate: PlateNumber) và giải thích lợi ích.

    Gợi ý guard + return nil; hàm register nhận PlateNumber chứ không nhận String.
    Đáp án 
    import Foundation

struct PlateNumber {
    let value: String
    init?(_ raw: String) {
        let t = raw.trimmingCharacters(in: .whitespaces).uppercased()
        guard (6...12).contains(t.count) else { return nil }
        value = t
    }
}

func register(_ plate: PlateNumber) { print("Đăng ký \(plate.value)") }

if let plate = PlateNumber(" 30a-12345 ") { register(plate) }
print(PlateNumber("A1") == nil)
    **Giải thích:** Kiểu `PlateNumber` chứng minh dữ liệu đã hợp lệ, nên `register` không cần kiểm tra lại và không thể nhận chuỗi bậy. Lỗi được chặn ngay ở biên.

    Thực hành 3 — Decode field thiếu và null¶

    JSON có thể là {"id":"V1"} hoặc {"id":"V1","mileage":null} hoặc {"id":"V1","mileage":1200,"fuel":"diesel"}. Viết DTO decode cả ba và dùng "gasoline" làm nhiên liệu mặc định.

    Gợi ý decodeIfPresent và ?? "gasoline".
    Đáp án 
    import Foundation

struct DTO: Decodable {
    let id: String
    let mileage: Double?
    let fuel: String

    enum CodingKeys: String, CodingKey { case id, mileage, fuel }
    init(from decoder: Decoder) throws {
        let c = try decoder.container(keyedBy: CodingKeys.self)
        id = try c.decode(String.self, forKey: .id)
        mileage = try c.decodeIfPresent(Double.self, forKey: .mileage)
        fuel = try c.decodeIfPresent(String.self, forKey: .fuel) ?? "gasoline"
    }
}

for json in [#"{"id":"V1"}"#, #"{"id":"V1","mileage":null}"#, #"{"id":"V1","mileage":1200,"fuel":"diesel"}"#] {
    let dto = try JSONDecoder().decode(DTO.self, from: Data(json.utf8))
    print(dto.mileage as Any, dto.fuel)
}
    **Giải thích:** `decodeIfPresent` trả nil cho cả "thiếu khóa" và `null`, còn `decode` sẽ ném lỗi. Giá trị mặc định đặt rõ ràng ở một chỗ thay vì rải trong UI.

    Thực hành 4 — Optional lồng nhau¶

    Với let settings: [String: Bool?] = ["darkMode": true, "beta": nil], giá trị của settings["darkMode"], settings["beta"] và settings["missing"] là gì? Làm sao biết "khóa có tồn tại nhưng nil"?

    Gợi ý Mỗi kết quả có kiểu Bool??.
    Đáp án 
    let settings: [String: Bool?] = ["darkMode": true, "beta": nil]

let a = settings["darkMode"]        // Optional(Optional(true))
let b = settings["beta"]            // Optional(nil)   -> CÓ khóa, giá trị nil
let c = settings["missing"]         // nil             -> KHÔNG có khóa

print(settings.keys.contains("beta"))   // true: cách rõ nhất để kiểm tra khóa tồn tại
let flat: Bool? = settings["darkMode"] ?? nil   // làm phẳng về Bool?
    **Giải thích:** Dictionary với giá trị Optional tạo ra ba trạng thái. Nếu không cần phân biệt, đừng lưu `nil` trong dictionary (xóa khóa thay vào đó) hoặc dùng enum diễn đạt rõ.
