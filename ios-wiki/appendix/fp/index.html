    Phụ lục · Functional Programming trong Swift¶

    Mục tiêu: Dùng hàm như giá trị, closure, hàm bậc cao, hàm thuần và bất biến để biến đổi dữ liệu gọn gàng, dễ test; biết khi nào kết hợp với OOP.
    Thời lượng: Tham khảo khi cần

    Khái niệm: first-class function, closure, map / filter / reduce, pure function, immutability, composition, reducer

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Functional programming là gì và vì sao hữu ích¶

    Functional programming (FP) xây chương trình từ các hàm nhỏ, có thể ghép lại. Các ý chính: • Hàm là giá trị: truyền vào, trả về, lưu trong biến. • Hàm thuần (pure): cùng đầu vào luôn cho cùng đầu ra, không có tác dụng phụ. • Bất biến (immutability): không sửa dữ liệu tại chỗ mà tạo giá trị mới. • Hàm bậc cao: hàm nhận hoặc trả về hàm (map, filter, reduce). • Kết hợp (composition): ghép hàm nhỏ thành hàm lớn.

    Lợi ích thực tế: dễ test (không cần mock), dễ suy luận (không có trạng thái ẩn), an toàn khi chạy đa luồng (không chia sẻ trạng thái mutable), code ngắn khi biến đổi dữ liệu.

    Swift không phải ngôn ngữ functional thuần. Nó cho bạn các công cụ functional và để bạn pha trộn với OOP/protocol. Quy tắc thực dụng: phần biến đổi dữ liệu viết kiểu functional, phần có tác dụng phụ (IO, UI, state) đặt ở rìa.

    2. Hàm là giá trị: kiểu hàm, truyền, trả về¶

    Mọi hàm Swift có một kiểu, viết dạng (Tham số) -> Kết quả. Bạn có thể gán vào biến, đặt tên bằng typealias, lưu trong mảng/dictionary, truyền làm tham số và trả về từ hàm khác. Toán tử như +, *, > cũng là hàm nên truyền thẳng được.

    Phân biệt hai kiểu tham số hàm: • Non-escaping (mặc định): chạy xong trong lời gọi hàm, không được lưu lại. An toàn, không cần lo vòng tham chiếu. • @escaping: được lưu để chạy sau (callback, handler, Task). Có thể gây retain cycle nên cần [weak self] khi bắt self (tuần 3).

    typealias Transform = (Int) -> Int
let double: Transform = { $0 * 2 }
let negate: Transform = { -$0 }

func apply(_ value: Int, _ transform: Transform) -> Int { transform(value) }
print(apply(5, double), apply(5, negate))          // 10 -5

// Hàm lưu trong dictionary; toán tử cũng là hàm
let operations: [String: (Int, Int) -> Int] = ["add": (+), "mul": (*)]
print(operations["add"]?(2, 3) ?? 0)               // 5

// Hàm trả về hàm
func multiplier(_ factor: Int) -> (Int) -> Int { { $0 * factor } }
let triple = multiplier(3)
print(triple(7))                                   // 21

// Non-escaping và @escaping
func runNow(_ work: () -> Void) { work() }                      // chạy xong ngay
var handlers: [() -> Void] = []
func register(_ handler: @escaping () -> Void) { handlers.append(handler) }   // lưu lại để chạy sau

    3. Closure: cú pháp rút gọn, capture và @autoclosure¶

    Closure là hàm không tên có thể "bắt" (capture) biến xung quanh. Cú pháp rút gọn dần: đầy đủ → bỏ kiểu và return → trailing closure (đặt ngoài ngoặc khi là tham số cuối) → viết tắt $0, $1. Nếu closure chỉ gọi một hàm/toán tử khác, truyền thẳng hàm đó (sorted(by: >)). Key path \.make cũng dùng được như hàm (Root) -> Value.

    Capture: closure giữ tham chiếu tới biến nó dùng, nên biến sống lâu hơn phạm vi gốc (đếm count ở ví dụ). Với class, đây là nguồn retain cycle: dùng capture list [weak self].

    @autoclosure tự bọc đối số thành closure để trì hoãn tính toán: biểu thức chỉ được tính khi cần (&&, ??, assert dùng cơ chế này).

    let years = [2019, 2024, 2021]
let a = years.sorted(by: { (lhs: Int, rhs: Int) -> Bool in return lhs > rhs })   // đầy đủ
let b = years.sorted(by: { lhs, rhs in lhs > rhs })     // suy luận kiểu, bỏ return
let c2 = years.sorted { $0 > $1 }                       // trailing closure + $0
let d = years.sorted(by: >)                             // toán tử là hàm
print(a == b, b == c2, c2 == d)                         // true true true

// Capture: closure giữ biến count sống
func makeCounter() -> () -> Int {
    var count = 0
    return { count += 1; return count }
}
let next = makeCounter()
print(next(), next(), next())                           // 1 2 3

// @autoclosure: trì hoãn tính toán
func expensive() -> String { print("computed"); return "tốn kém" }
func debugLog(_ enabled: Bool, _ message: @autoclosure () -> String) {
    if enabled { print(message()) }                     // chỉ tính message khi enabled
}
debugLog(false, expensive())                            // không in "computed"
debugLog(true, expensive())                             // in "computed" rồi "tốn kém"

    4. Hàm bậc cao trong thư viện chuẩn¶

    Các hàm bậc cao quan trọng (đều trả về giá trị mới, không sửa collection gốc): • map: biến đổi từng phần tử. • filter: giữ phần tử thỏa điều kiện. • reduce(_:_:) / reduce(into:_:): gộp thành một giá trị (số, dictionary…). • compactMap: map rồi bỏ nil. flatMap: map rồi làm phẳng mảng lồng nhau. • sorted(by:), first(where:), contains(where:), allSatisfy, zip, enumerated. • Dictionary(grouping:by:): nhóm theo khóa. • .lazy: trì hoãn tính toán, chỉ xử lý phần tử khi cần (hợp với dãy lớn).

    Chọn vòng lặp for khi cần break/continue, có tác dụng phụ, hoặc thuật toán phức tạp; chọn hàm bậc cao khi biến đổi dữ liệu. Đừng nối quá nhiều bước trong một biểu thức khó đọc: đặt tên cho các bước trung gian.

    struct Vehicle { let make: String; let year: Int; let tags: [String]; let km: Double }

let fleet = [
    Vehicle(make: "Toyota", year: 2024, tags: ["ev", "city"], km: 1200),
    Vehicle(make: "Honda", year: 2018, tags: ["city"], km: 90_000),
    Vehicle(make: "Ford", year: 2022, tags: ["suv", "city"], km: 30_000),
    Vehicle(make: "Toyota", year: 2019, tags: ["suv"], km: 60_000)
]

let recentMakes = fleet.filter { $0.year >= 2020 }.map(\.make)         // ["Toyota", "Ford"]
let allTags = Set(fleet.flatMap(\.tags))                                // làm phẳng + loại trùng
let totalKm = fleet.reduce(0) { $0 + $1.km }
let byMake = Dictionary(grouping: fleet, by: \.make)                    // [String: [Vehicle]]
let countByMake = fleet.reduce(into: [String: Int]()) { $0[$1.make, default: 0] += 1 }
let firstEV = fleet.first { $0.tags.contains("ev") }?.make              // Optional
let allRecent = fleet.allSatisfy { $0.year >= 2015 }
let labels = zip(fleet.map(\.make), fleet.map(\.year)).map { "\($0)-\($1)" }

// lazy: chỉ tính 3 phần tử đầu thay vì cả triệu
let firstThree = (1...1_000_000).lazy.filter { $0 % 7 == 0 }.map { $0 * 2 }.prefix(3)
print(Array(firstThree), countByMake["Toyota"] ?? 0, byMake.keys.sorted(), allTags.count, totalKm, firstEV ?? "-", allRecent, labels.count, recentMakes)

    5. Hàm thuần, bất biến và "lõi thuần, vỏ tác dụng phụ"¶

    Hàm thuần không đọc và không sửa trạng thái bên ngoài (biến toàn cục, file, mạng, giờ hệ thống, số ngẫu nhiên). Hàm không thuần khó test và gây lỗi khi nhiều luồng chạy đồng thời. Cách sửa: đưa mọi thứ hàm cần thành tham số, trả kết quả thay vì sửa biến ngoài.

    Mô hình "functional core, imperative shell" rất hợp với app: logic nghiệp vụ (tính, lọc, kiểm tra) là hàm thuần ở lõi; phần có tác dụng phụ (đọc BLE, ghi log, cập nhật UI, gọi API) là lớp vỏ mỏng gọi lõi. Nhờ vậy 80% logic test được bằng đầu vào/đầu ra, không cần mock.

    Bất biến trong Swift: ưu tiên let, struct và enum; method mutating chỉ tác động vào chính giá trị đó (value semantics), không lan ra bản sao khác. Copy-on-write của collection làm việc tạo bản mới rẻ.

    // Không thuần: phụ thuộc và sửa trạng thái ngoài
var taxRate = 0.1
var runningTotal = 0.0
func addImpure(price: Double) { runningTotal += price * (1 + taxRate) }

// Thuần: mọi thứ cần thiết là tham số, kết quả là giá trị trả về
func priceWithTax(_ price: Double, rate: Double) -> Double { price * (1 + rate) }
let total = [10.0, 20.0].map { priceWithTax($0, rate: 0.1) }.reduce(0, +)   // 33.0

// Lõi thuần: dễ test
struct Reading { let rpm: Int; let temperature: Double }
func isOverheating(_ r: Reading) -> Bool { r.temperature > 105 }
func alerts(from readings: [Reading]) -> [Reading] { readings.filter(isOverheating) }

// Vỏ có tác dụng phụ (IO) chỉ gọi lõi:
func onNewReadings(_ readings: [Reading]) {
    let bad = alerts(from: readings)                    // lõi thuần
    if !bad.isEmpty { print("ALERT: \(bad.count) readings")}   // tác dụng phụ ở rìa
}
addImpure(price: 10)
print(total, runningTotal)

    6. Kết hợp hàm: compose, currying và toán tử pipe¶

    Ghép hàm nhỏ thành hàm lớn là cốt lõi của FP. Ba kỹ thuật: • Compose: compose(f, g) tạo hàm x -> g(f(x)). • Currying: biến hàm nhiều tham số thành chuỗi hàm một tham số (add(10)(5)), giúp áp dụng từng phần (partial application). • Pipe: toán tử |> viết dữ liệu chảy từ trái sang phải, dễ đọc hơn gọi lồng nhau.

    Swift cho phép tự định nghĩa toán tử, nhưng hãy dùng tiết kiệm: toán tử lạ làm người đọc khó hiểu. Với đa số trường hợp, chuỗi .map{}.filter{} và hàm có tên rõ nghĩa đã đủ tốt. Kỹ thuật compose/curry hữu ích khi xây thư viện nhỏ hoặc tái sử dụng bộ biến đổi.

    import Foundation

func compose<A, B, C>(_ f: @escaping (A) -> B, _ g: @escaping (B) -> C) -> (A) -> C {
    { g(f($0)) }
}

func curry<A, B, C>(_ f: @escaping (A, B) -> C) -> (A) -> (B) -> C {
    { a in { b in f(a, b) } }
}

let add = curry { (a: Int, b: Int) in a + b }
let addTen = add(10)                                    // áp dụng từng phần
print(addTen(5))                                        // 15

let trim: (String) -> String = { $0.trimmingCharacters(in: .whitespaces) }
let upper: (String) -> String = { $0.uppercased() }
let normalize = compose(trim, upper)
print(normalize("  camry "))                            // CAMRY

// Toán tử pipe tự định nghĩa
precedencegroup PipePrecedence {
    associativity: left
    higherThan: AssignmentPrecedence
}
infix operator |>: PipePrecedence
func |> <A, B>(value: A, transform: (A) -> B) -> B { transform(value) }

let length = "  toyota  " |> trim |> upper |> { $0.count }
print(length)                                           // 6

    7. Optional và Result như "hộp" có map/flatMap¶

    Optional và Result đều là "hộp" chứa giá trị (hoặc thiếu/lỗi) và có map/flatMap để biến đổi giá trị bên trong mà không phải mở hộp bằng tay: • opt.map(f): áp f nếu có giá trị, giữ nil nếu không. • opt.flatMap(f) khi f bản thân trả Optional (tránh Optional<Optional<T>>). • result.map, result.flatMap, result.mapError (đổi kiểu lỗi), result.get() (ném lỗi).

    Điều này cho phép nối các bước có thể thất bại thành một chuỗi, nếu một bước hỏng thì cả chuỗi dừng và mang theo lỗi/nil. Đây là cách FP xử lý "có thể thiếu/có thể lỗi" mà không cần if lồng nhau; chi tiết ở bài Null-safety.

    let input: String? = "2024"

let year = input.flatMap(Int.init)                       // Int?  (Int.init trả Optional)
let label = year.map { "Năm \($0)" } ?? "Không rõ"       // String

enum ParseError: Error { case notNumber }

func parse(_ s: String) -> Result<Int, ParseError> {
    if let n = Int(s) { return .success(n) }
    return .failure(.notNumber)
}

let doubled = parse("12").map { $0 * 2 }                              // success(24)
let chained = parse("5").flatMap { parse(String($0 + 1)) }            // success(6)
struct DisplayError: Error { let message: String }
let mapped = parse("x").mapError { _ in DisplayError(message: "Không phải số") }   // đổi kiểu lỗi

print(label, (try? doubled.get()) ?? -1, (try? chained.get()) ?? -1)
if case .failure(let error) = mapped { print(error.message) }

    8. Functional trong ứng dụng thật: reducer và SwiftUI¶

    • SwiftUI: body là hàm thuần của state (UI = f(state)). Nếu body có tác dụng phụ thì bạn đang đi ngược thiết kế của nó. • Reducer: hàm thuần (State, Action) -> State tập trung mọi thay đổi trạng thái. Tương tự Redux/NgRx mà dev Angular đã biết. Máy trạng thái BLE (tuần 8) là một reducer. Rất dễ test: đưa chuỗi action, so sánh state cuối. • Concurrency: async let, TaskGroup và AsyncSequence (có map, filter) mang tư duy functional vào bất đồng bộ. • Combine/AsyncSequence: pipeline biến đổi luồng dữ liệu, tương tự RxJS.

    Lưu ý: toàn bộ bộ máy FP có chi phí cấp phát và độ khó đọc. Dùng khi nó làm code rõ hơn, đừng ép mọi thứ thành FP.

    struct AppState: Equatable {
    var count = 0
    var isLoading = false
    var error: String?
}

enum Action {
    case increment
    case setLoading(Bool)
    case failed(String)
}

func reduce(_ state: AppState, _ action: Action) -> AppState {
    var next = state                                   // làm việc trên bản sao
    switch action {
    case .increment:        next.count += 1
    case .setLoading(let v): next.isLoading = v
    case .failed(let m):    next.error = m; next.isLoading = false
    }
    return next
}

let actions: [Action] = [.setLoading(true), .increment, .increment, .failed("timeout")]
let final = actions.reduce(AppState(), reduce)         // reduce nhận hàm reduce làm tham số
print(final)    // AppState(count: 2, isLoading: false, error: Optional("timeout"))

    9. So sánh với TypeScript/JavaScript và RxJS¶

    • map/filter/reduce/flatMap/some/every của JS ↔ map/filter/reduce/flatMap/contains(where:)/allSatisfy của Swift. flatMap của Swift trên Array tương đương flatMap JS; compactMap tương đương map(...).filter(x => x != null). • Arrow function x => x * 2 ↔ closure { $0 * 2 }. • Lodash/fp, Ramda (pipe, compose, curry) ↔ tự viết compose/curry/|> như trên (Swift chưa có sẵn). • Immutability: JS cần Object.freeze, spread, Immer; Swift có sẵn nhờ let và value type. • RxJS operators (map, filter, switchMap) ↔ Combine, AsyncSequence và .task(id:). • NgRx reducer ↔ hàm reduce(state, action) thuần như trên. • Kiểu: Swift kiểm tra kiểu hàm chặt hơn; không có any ngầm, không có ép kiểu số.

    10. Lỗi thường gặp¶

    1. Chuỗi hàm quá dài, lồng nhau khó đọc: đặt tên cho bước trung gian.
    2. Dùng map chỉ để lặp có tác dụng phụ: dùng forEach hoặc for. map dành cho biến đổi.
    3. filter rồi first trên mảng lớn: dùng first(where:) hoặc lazy để dừng sớm.
    4. Closure @escaping bắt self mạnh gây retain cycle.
    5. Hàm "thuần" nhưng đọc Date()/UUID(): không còn thuần; đưa thời gian/id vào làm tham số hoặc inject.
    6. Quá tay với toán tử tự định nghĩa và generic phức tạp: compiler chậm và đồng đội khó hiểu.
    7. Sửa mảng trong forEach (không tác dụng với struct, hoặc gây lỗi): dùng map/chỉ số.
    8. Nhầm map với flatMap/compactMap khi kết quả là mảng lồng hoặc Optional.
    9. Hiệu năng: reduce tạo bản sao khi dùng $0 + [x] trong vòng lặp lớn; dùng reduce(into:).

    11. Tóm tắt¶

    • Hàm là giá trị: kiểu hàm, truyền, trả về, lưu trữ; closure bắt biến; @escaping cho callback lưu lại. • Hàm bậc cao (map, filter, reduce, compactMap, flatMap, Dictionary(grouping:), lazy) cho biến đổi dữ liệu. • Hàm thuần + bất biến: "lõi thuần, vỏ tác dụng phụ". • Compose, curry và pipe để ghép hàm nhỏ; dùng tiết kiệm. • Optional/Result có map/flatMap; reducer (State, Action) -> State cho quản lý state. • Kết hợp hài hòa với OOP/protocol thay vì thay thế.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Thực hành 1 — Đường ống biến đổi dữ liệu¶

    Với fleet ở trên, viết các biểu thức (không dùng for): (a) tên hãng của xe từ 2020 trở đi, sắp xếp, không trùng; (b) tổng km của các xe có tag "suv"; (c) dictionary đếm số xe theo năm.

    Gợi ý filter → map → Set/sorted; filter + reduce; reduce(into:).
    Đáp án 
    let recentMakes = Array(Set(fleet.filter { $0.year >= 2020 }.map(\.make))).sorted()
let suvKm = fleet.filter { $0.tags.contains("suv") }.reduce(0) { $0 + $1.km }
let countByYear = fleet.reduce(into: [Int: Int]()) { $0[$1.year, default: 0] += 1 }
    **Giải thích:** Mỗi bước là một hàm thuần tạo giá trị mới; mảng gốc `fleet` không đổi. `reduce(into:)` hiệu quả hơn cộng dồn từng bản sao.

    Thực hành 2 — Compose và curry¶

    Viết compose và curry generic. Dùng chúng để tạo clampThenDouble từ clamp(0...100) (là hàm một tham số) và double. Kiểm tra clampThenDouble(150).

    Gợi ý clamp có thể là hàm trả về hàm: func clamp(_ range: ClosedRange) -> (Int) -> Int.
    Đáp án 
    func compose<A, B, C>(_ f: @escaping (A) -> B, _ g: @escaping (B) -> C) -> (A) -> C { { g(f($0)) } }

func clamp(_ range: ClosedRange<Int>) -> (Int) -> Int {
    { min(max($0, range.lowerBound), range.upperBound) }
}
let double: (Int) -> Int = { $0 * 2 }

let clampThenDouble = compose(clamp(0...100), double)
print(clampThenDouble(150))      // 200: 150 -> 100 -> 200
    **Giải thích:** `clamp(0...100)` là áp dụng từng phần của một hàm nhiều tham số. Compose ghép hai bước nhỏ thành một hàm tái sử dụng được.

    Thực hành 3 — Biến hàm không thuần thành thuần¶

    Hàm sau không thuần. Viết lại để dễ test: nhận thời gian hiện tại và hạn dùng làm tham số, và trả về trạng thái thay vì in ra.

    func checkToken(expiry: Date) { if Date() > expiry { print("expired") } else { print("ok") } }

    Gợi ý Inject `now` và trả về enum.
    Đáp án 
    import Foundation

enum TokenStatus { case valid, expired }

func tokenStatus(expiry: Date, now: Date) -> TokenStatus {
    now > expiry ? .expired : .valid
}

let base = Date(timeIntervalSince1970: 1_700_000_000)
assert(tokenStatus(expiry: base, now: base.addingTimeInterval(1)) == .expired)
assert(tokenStatus(expiry: base, now: base.addingTimeInterval(-1)) == .valid)

// Vỏ tác dụng phụ:
let status = tokenStatus(expiry: base, now: Date())
print(status)
    **Giải thích:** Thời gian là đầu vào ẩn. Khi biến nó thành tham số, hàm xác định, có thể test mọi trường hợp mà không phụ thuộc đồng hồ.

    Thực hành 4 — Reducer cho màn hình tải dữ liệu¶

    Viết enum Action { case load, loaded([String]), failed(String) } và hàm thuần reduce(state, action) cho struct State { var items: [String]; var isLoading: Bool; var error: String? }. Chứng minh chuỗi .load, .failed("x"), .load, .loaded(["a"]) cho items == ["a"] và error == nil.

    Gợi ý Mỗi action cập nhật đúng các trường; .load xóa error cũ.
    Đáp án 
    struct State: Equatable { var items: [String] = []; var isLoading = false; var error: String? }
enum Action { case load, loaded([String]), failed(String) }

func reduce(_ s: State, _ a: Action) -> State {
    var n = s
    switch a {
    case .load:               n.isLoading = true; n.error = nil
    case .loaded(let items):  n.items = items; n.isLoading = false
    case .failed(let m):      n.error = m; n.isLoading = false
    }
    return n
}

let final = [Action.load, .failed("x"), .load, .loaded(["a"])].reduce(State(), reduce)
assert(final.items == ["a"] && final.error == nil && !final.isLoading)
    **Giải thích:** Mọi thay đổi trạng thái nằm trong một hàm thuần nên test chỉ là đưa chuỗi action và so sánh state cuối, không cần UI hay mạng.
