    Phụ lục · Extension (extension function) trong Swift¶

    Mục tiêu: Thêm method, computed property, initializer và conformance vào kiểu có sẵn; dùng extension có điều kiện, protocol extension và tổ chức code bằng extension.
    Thời lượng: Tham khảo khi cần

    Khái niệm: extension, mutating extension, conditional extension, protocol extension, conditional conformance, @retroactive

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Extension là gì¶

    Extension cho phép thêm chức năng vào một kiểu đã tồn tại (struct, class, enum, protocol), kể cả kiểu của thư viện chuẩn hay của Apple mà bạn không có mã nguồn. Đây là khái niệm tương đương: • "Extension function" của Kotlin. • "Extension method" của C#. • Module augmentation / declaration merging của TypeScript, hoặc thêm vào prototype trong JavaScript (nhưng an toàn kiểu và có phạm vi module).

    Extension có thể thêm: computed property, instance method, type method, initializer, subscript, nested type và protocol conformance. Extension KHÔNG thể: thêm stored property (do đó không có property observer), ghi đè method đã có, hoặc thay đổi cách kiểu được lưu trữ.

    Tên gọi "extension function" trong Swift chỉ là cách người dùng ngôn ngữ khác gọi một method được khai báo trong extension.

    2. Thêm method và computed property cho kiểu có sẵn¶

    Cú pháp: extension TênKiểu { ... }. Bên trong, self là giá trị của kiểu được mở rộng. Dùng cho tiện ích gắn với kiểu nhưng không đủ lớn để thành một kiểu riêng: chuẩn hóa chuỗi, kiểm tra số, định dạng ngày. Đặt tên theo quy ước Swift (rõ nghĩa, giống thư viện chuẩn).

    Một mẫu rất hữu ích cho null-safety: subscript an toàn array[safe: index] trả về Optional thay vì crash khi chỉ số vượt phạm vi.

    import Foundation

extension String {
    var trimmed: String { trimmingCharacters(in: .whitespacesAndNewlines) }
    var isBlank: Bool { trimmed.isEmpty }
    func truncated(to length: Int, trailing: String = "…") -> String {
        count <= length ? self : String(prefix(length)) + trailing
    }
}

extension Int {
    var isEven: Bool { self % 2 == 0 }
    func clamped(to range: ClosedRange<Int>) -> Int { Swift.min(Swift.max(self, range.lowerBound), range.upperBound) }   // Swift. vì Int có thành viên min/max
}

extension Date {
    var isToday: Bool { Calendar.current.isDateInToday(self) }
}

extension Array {
    subscript(safe index: Int) -> Element? {              // không crash khi ngoài phạm vi
        indices.contains(index) ? self[index] : nil
    }
}

print("  Toyota Camry  ".trimmed.truncated(to: 6))          // Toyota…
print(150.clamped(to: 0...100), 4.isEven, Date().isToday)  // 100 true true
print([1, 2, 3][safe: 5] ?? -1)                              // -1

    3. Extension cho value type: mutating¶

    Với struct/enum (value type), method nào thay đổi chính giá trị phải đánh dấu mutating, kể cả trong extension. Nó chỉ gọi được trên biến var. Với kiểu như Int, Array, String (đều là struct), đây là cách thêm thao tác sửa tại chỗ.

    Cặp "non-mutating trả về bản mới" và "mutating sửa tại chỗ" là quy ước của thư viện chuẩn (sorted() và sort(), reversed() và reverse()). Hãy đặt tên theo quy ước: dạng sửa tại chỗ là động từ (square()), dạng trả bản mới là phân từ/danh từ (squared()).

    extension Int {
    mutating func square() { self = self * self }          // sửa tại chỗ
    func squared() -> Int { self * self }                   // trả bản mới
}

extension Array where Element: Equatable {
    mutating func remove(all item: Element) { removeAll { $0 == item } }
}

var n = 5
n.square()                                                  // 25
let m = 4.squared()                                         // 16

var xs = [1, 2, 1, 3]
xs.remove(all: 1)                                           // [2, 3]
print(n, m, xs)

    4. Extension cho initializer và static member¶

    Extension thêm được init mới và hằng/hàm cấp kiểu (static). Với struct, đặt initializer tùy biến trong extension để KHÔNG làm mất memberwise initializer tự sinh (nếu đặt trong thân struct thì nó biến mất). Với class, convenience init đặt trong extension.

    Dùng static let trong extension để tạo "namespace" hằng và dữ liệu mẫu, rất tiện cho preview SwiftUI: Vehicle.samples, Color.brand.

    import SwiftUI

extension Color {
    init(hex: UInt32, opacity: Double = 1) {
        self.init(.sRGB,
                  red: Double((hex >> 16) & 0xFF) / 255,
                  green: Double((hex >> 8) & 0xFF) / 255,
                  blue: Double(hex & 0xFF) / 255,
                  opacity: opacity)
    }
    static let brand = Color(hex: 0xA95A4A)
}

struct Vehicle {
    let id: String
    let name: String
}

extension Vehicle {
    init(csv: String) {                                     // memberwise init vẫn còn nguyên
        let parts = csv.split(separator: ",").map(String.init)
        self.init(id: parts.first ?? "", name: parts.last ?? "")
    }
    static let samples = [
        Vehicle(id: "V1", name: "Camry"),
        Vehicle(csv: "V2,Civic")
    ]
}

    5. Extension có điều kiện (where) và conditional conformance¶

    where giới hạn extension cho những kiểu thỏa điều kiện, nên tiện ích chỉ xuất hiện khi hợp lý: • extension Sequence where Element: Numeric: total cho mọi dãy số. • extension Collection where Element == Int: average chỉ cho mảng Int. • extension Optional where Wrapped == String: tiện ích cho chuỗi có thể nil (null-safety). • extension Collection where Element: Identifiable: find(id:).

    Conditional conformance: extension Pair: Equatable where A: Equatable, B: Equatable nghĩa là Pair so sánh được khi cả hai thành phần so sánh được. Thư viện chuẩn dùng nhiều (Array: Equatable khi Element: Equatable).

    extension Sequence where Element: Numeric {
    var total: Element { reduce(0, +) }
}

extension Collection where Element == Int {
    var average: Double? { isEmpty ? nil : Double(total) / Double(count) }   // rỗng thì nil
}

extension Optional where Wrapped == String {
    var isNilOrEmpty: Bool { self?.isEmpty ?? true }
    func orDefault(_ fallback: String) -> String { isNilOrEmpty ? fallback : (self ?? fallback) }
}

extension Collection where Element: Identifiable {
    func find(id: Element.ID) -> Element? { first { $0.id == id } }
}

struct Pair<A, B> { let first: A; let second: B }
extension Pair: Equatable where A: Equatable, B: Equatable { }

struct Item: Identifiable { let id: Int }
print([1.5, 2.5].total, [2, 4, 6].average ?? 0, [Int]().average as Any)
let name: String? = nil
print(name.isNilOrEmpty, name.orDefault("Không rõ"), [Item(id: 7)].find(id: 7) != nil)
print(Pair(first: 1, second: "a") == Pair(first: 1, second: "a"))

    6. Protocol extension: cài đặt mặc định và bẫy dispatch¶

    extension của protocol cung cấp cài đặt mặc định cho mọi kiểu conform, thay cho code chung ở lớp cha (bài OOP). Có thể thêm ràng buộc (extension Collection where Element: Describable).

    Bẫy quan trọng: hàm là requirement khai báo trong protocol được gọi theo kiểu thật (dynamic dispatch). Hàm chỉ tồn tại trong extension mà KHÔNG khai báo trong protocol được chọn theo kiểu khai báo của biến (static dispatch). Khi bạn tưởng đã "override", kết quả có thể là bản mặc định. Quy tắc: muốn kiểu conform ghi đè được thì phải khai báo hàm trong protocol.

    protocol Greeter {
    func greet() -> String                                   // requirement
}
extension Greeter {
    func greet() -> String { "Hello" }                       // mặc định cho requirement
    func shout() -> String { "HELLO" }                       // KHÔNG nằm trong protocol
}

struct Friendly: Greeter {
    func greet() -> String { "Hi!" }
    func shout() -> String { "HI!!" }
}

let g: any Greeter = Friendly()
print(g.greet())                // Hi!     dynamic dispatch: gọi bản của Friendly
print(g.shout())                // HELLO   static dispatch theo kiểu khai báo (Greeter)
print(Friendly().shout())       // HI!!    kiểu là Friendly nên gọi bản của Friendly

    7. Dùng extension để tổ chức code, trong SwiftUI¶

    Tổ chức code: • Tách mỗi conformance vào một extension riêng (extension Vehicle: Codable, extension Vehicle: CustomStringConvertible) và chú thích // MARK: -. • Gom helper nội bộ bằng private extension. • Đặt tiện ích dùng chung ở file Kiểu+Mục đích.swift (ví dụ String+Trimmed.swift), ở mức truy cập hẹp nhất.

    Trong SwiftUI, extension của View là nơi chuẩn để đóng gói modifier (.cardStyle()), và extension của Binding giúp xử lý binding.

    import SwiftUI

extension View {
    func cardStyle() -> some View {
        padding(16)
            .background(.background.secondary, in: RoundedRectangle(cornerRadius: 12))
    }

    func hidden(_ isHidden: Bool) -> some View {
        opacity(isHidden ? 0 : 1)
    }
}

extension Binding {
    func onChange(_ handler: @escaping (Value) -> Void) -> Binding<Value> {
        Binding(get: { wrappedValue }, set: { wrappedValue = $0; handler($0) })
    }
}

struct Vehicle { let make: String; let model: String }

// MARK: - CustomStringConvertible
extension Vehicle: CustomStringConvertible {
    var description: String { "\(make) \(model)" }
}

// MARK: - Helpers nội bộ
private extension Vehicle {
    var sortKey: String { description.lowercased() }
}

    8. Ranh giới, rủi ro và retroactive conformance¶

    • Xung đột tên: nếu hai module cùng thêm method trùng tên vào một kiểu, lời gọi có thể mơ hồ. Dùng tên rõ nghĩa, đặt internal/fileprivate khi không cần công khai. • Không override: extension không ghi đè được method có sẵn của lớp; chỉ thêm mới. • Retroactive conformance: cho kiểu của bên thứ ba conform protocol của bên thứ ba (ví dụ URL: Identifiable). Nếu sau này chính thư viện đó cũng thêm conformance, app của bạn có thể hành xử sai. Swift 6 yêu cầu đánh dấu @retroactive để thể hiện bạn nhận rủi ro này; chỉ dùng khi thật cần. • Đừng nhồi logic nghiệp vụ lớn vào extension của kiểu chuẩn (String, Array): tạo kiểu riêng. • Extension là toàn cục trong module: thêm vào String sẽ thấy ở mọi nơi trong module, hãy cân nhắc phạm vi.

    import Foundation

// Retroactive conformance: kiểu (URL) và protocol (Identifiable) đều không thuộc module của bạn
extension URL: @retroactive Identifiable {
    public var id: String { absoluteString }      // phải public vì khớp requirement của protocol public
}

// Không thêm được stored property:
// extension Vehicle { var cache: [String] = [] }   // LỖI: extensions must not contain stored properties

    9. So sánh với Kotlin, C#, TypeScript và JavaScript¶

    • Kotlin fun String.trimmed(), C# this string s: tương đương extension String { func trimmed() }. Cả ba đều được giải quyết tĩnh theo kiểu khai báo. • Kotlin extension function không truy cập được thành viên private của kiểu; Swift extension trong cùng file thì truy cập được private của khai báo. • TypeScript: thêm vào interface bằng khai báo trùng tên (declaration merging) hoặc declare module; muốn thêm hành vi thật phải tự gắn vào prototype. Swift thêm hành vi thật, có kiểm tra kiểu. • JavaScript: sửa String.prototype là cách tương đương nhưng nguy hiểm (monkey patching, xung đột toàn cục). Extension của Swift có phạm vi module và kiểm tra lúc biên dịch. • Angular: pipe/utility function ~ extension nhỏ gọn của kiểu dữ liệu.

    10. Lỗi thường gặp¶

    1. Cố thêm stored property: lỗi "extensions must not contain stored properties". Dùng computed property, hoặc đặt dữ liệu trong kiểu.
    2. Đặt initializer của struct trong thân (mất memberwise init) thay vì trong extension.
    3. Quên mutating khi extension của struct sửa chính nó.
    4. Hàm trong protocol extension không khai báo trong protocol: "override" không có tác dụng với biến kiểu protocol.
    5. Thêm quá nhiều tiện ích vào String/Array công khai: ô nhiễm namespace, xung đột.
    6. Đặt tên khác quy ước thư viện chuẩn (động từ cho sửa tại chỗ, danh từ/phân từ cho trả bản mới).
    7. Quên @retroactive khi conform kiểu bên thứ ba với protocol bên thứ ba (Swift 6).
    8. Dùng extension để che giấu logic nghiệp vụ phức tạp: khó tìm, khó test.

    11. Tóm tắt¶

    • Extension thêm method, computed property, init, subscript, conformance; không thêm stored property. • Struct/enum cần mutating khi sửa chính nó; đặt init tùy biến trong extension để giữ memberwise init. • where cho extension có điều kiện (Sequence, Collection, Optional); conditional conformance. • Protocol extension cho cài đặt mặc định; khai báo trong protocol nếu muốn ghi đè. • Dùng extension để tổ chức conformance/helper, thêm modifier SwiftUI. • Cẩn trọng với xung đột tên và retroactive conformance.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Thực hành 1 — Tiện ích cho String và Array¶

    Viết extension String { var isValidPlate: Bool } (sau khi trim, dài 6–12 ký tự) và extension Array { subscript(safe:) }. Dùng chúng để lấy phần tử thứ 5 của mảng có 3 phần tử mà không crash.

    Gợi ý Dùng trimmingCharacters và (6...12).contains(count); indices.contains.
    Đáp án 
    import Foundation

extension String {
    var isValidPlate: Bool {
        (6...12).contains(trimmingCharacters(in: .whitespaces).count)
    }
}

extension Array {
    subscript(safe index: Int) -> Element? { indices.contains(index) ? self[index] : nil }
}

print("30A-12345".isValidPlate, "  A1 ".isValidPlate)   // true false
print([10, 20, 30][safe: 5] ?? -1)                        // -1
    **Giải thích:** Subscript an toàn trả Optional, chuyển lỗi crash "index out of range" thành giá trị nil có thể xử lý (null-safety).

    Thực hành 2 — Extension có điều kiện¶

    Viết extension Collection where Element == Double { var average: Double? } và extension Optional where Wrapped == String { var orEmpty: String }. Giải thích vì sao average trả Optional.

    Gợi ý Mảng rỗng không có trung bình hợp lệ.
    Đáp án 
    extension Collection where Element == Double {
    var average: Double? { isEmpty ? nil : reduce(0, +) / Double(count) }
}

extension Optional where Wrapped == String {
    var orEmpty: String { self ?? "" }
}

print([1.0, 2.0, 6.0].average ?? 0, [Double]().average as Any)   // 3.0 nil
let name: String? = nil
print(name.orEmpty.isEmpty)                                       // true
    **Giải thích:** Optional diễn đạt "không có giá trị hợp lệ" thay vì trả 0 gây hiểu nhầm. Điều kiện `where` giữ tiện ích chỉ xuất hiện cho kiểu phù hợp.

    Thực hành 3 — Gọn code SwiftUI bằng extension¶

    Viết extension View { func badge(_ text: String) -> some View } bọc view trong một HStack kèm nhãn nhỏ dạng viên thuốc. Áp dụng cho Text("Camry").

    Gợi ý Dùng HStack/Text/Capsule trong extension của View.
    Đáp án 
    import SwiftUI

extension View {
    func badge(_ text: String) -> some View {
        HStack(spacing: 8) {
            self
            Text(text)
                .font(.caption.bold())
                .padding(.horizontal, 8).padding(.vertical, 3)
                .background(.green.opacity(0.2), in: Capsule())
        }
    }
}

struct Demo: View {
    var body: some View { Text("Camry").badge("MỚI") }
}
    **Giải thích:** Extension của `View` tạo modifier tái sử dụng, thay cho lặp lại cùng nhóm modifier ở nhiều nơi.

    Thực hành 4 — Bẫy dispatch¶

    Đoán kết quả và giải thích: protocol P { func a() -> String }, extension P { func a() -> String { "default" }; func b() -> String { "default" } }, struct S: P { func a() -> String { "S" }; func b() -> String { "S" } }, rồi let p: any P = S() và in p.a(), p.b(), S().b().

    Gợi ý Chỉ `a()` là requirement của protocol.
    Đáp án 
    protocol P { func a() -> String }
extension P {
    func a() -> String { "default" }
    func b() -> String { "default" }
}
struct S: P {
    func a() -> String { "S" }
    func b() -> String { "S" }
}
let p: any P = S()
print(p.a())    // "S"        a() là requirement -> dynamic dispatch
print(p.b())    // "default"  b() chỉ ở extension -> static dispatch theo kiểu P
print(S().b())  // "S"        kiểu khai báo là S
    **Giải thích:** Muốn `b()` có thể ghi đè qua protocol, hãy khai báo `func b() -> String` trong chính protocol.
