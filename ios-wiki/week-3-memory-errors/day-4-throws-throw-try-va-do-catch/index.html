    Tuần 3 · Ngày 4 · throws, throw, try và do-catch¶

    Mục tiêu: Khai báo custom error, ném và bắt lỗi có cấu trúc, và chọn đúng giữa try, try? và try!.
    Thời lượng: 75–90 phút

    Khái niệm: Error protocol, throws, throw, do-catch, try? / try!, defer, Result

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Lỗi trong Swift khác exception như thế nào¶

    Swift xử lý lỗi bằng throws, không phải exception kiểu Java hay JavaScript. Khác biệt cốt lõi: hàm có thể ném lỗi phải được khai báo throws, và người gọi bắt buộc dùng try. Nhờ vậy, mỗi chỗ có thể xảy ra lỗi đều hiện rõ trong code, và compiler bắt bạn xử lý hoặc chuyển tiếp.

    Swift phân biệt: • Lỗi phục hồi được (file không tồn tại, mạng lỗi, dữ liệu sai): dùng throws. • Thiếu giá trị đơn giản: dùng Optional. • Lỗi lập trình không thể phục hồi (index vượt phạm vi, force unwrap nil): crash, không dùng throws.

    2. Định nghĩa lỗi và ném lỗi¶

    Lỗi là một kiểu conform protocol Error, thường là enum. Associated value cho phép đính kèm chi tiết. Hàm khai báo throws trước kiểu trả về; dùng throw để ném.

    Enum lỗi nên mô tả điều gì sai theo ngôn ngữ nghiệp vụ, không phải chuỗi mơ hồ. Để hiển thị cho người dùng, conform thêm LocalizedError và cài errorDescription.

    import Foundation

enum VehicleError: Error, LocalizedError {
    case invalidID
    case duplicateID(String)
    case notFound(id: String)
    case invalidYear(Int)

    var errorDescription: String? {
        switch self {
        case .invalidID:            return "ID không hợp lệ"
        case .duplicateID(let id):  return "ID \(id) đã tồn tại"
        case .notFound(let id):     return "Không tìm thấy xe \(id)"
        case .invalidYear(let y):   return "Năm \(y) không hợp lệ"
        }
    }
}

func validate(year: Int) throws {
    guard (1990...2100).contains(year) else {
        throw VehicleError.invalidYear(year)
    }
}

    3. Bắt lỗi: do-catch và try¶

    Gọi hàm throws phải đặt try phía trước và nằm trong ngữ cảnh xử lý lỗi: hoặc trong do { } catch { }, hoặc trong hàm khác cũng throws (lỗi được lan truyền lên).

    Trong catch bạn có thể khớp từng case, kèm pattern. Khối catch cuối không có pattern bắt mọi lỗi còn lại, với biến error ngầm định. Swift buộc do-catch phải bắt hết, hoặc hàm chứa nó phải throws.

    func register(id: String, year: Int) throws {
    guard !id.isEmpty else { throw VehicleError.invalidID }
    try validate(year: year)                    // lan truyền lỗi lên nơi gọi
    print("Đã đăng ký \(id)")
}

do {
    try register(id: "V001", year: 1980)
} catch VehicleError.invalidID {
    print("Thiếu ID")
} catch VehicleError.invalidYear(let year) {
    print("Năm sai: \(year)")
} catch {
    print("Lỗi khác: \(error.localizedDescription)")   // fallback bắt mọi lỗi còn lại
}

    4. try?, try! và defer¶

    • try?: đổi kết quả thành Optional. Nếu hàm ném lỗi, kết quả là nil và lỗi bị bỏ qua. Dùng khi bạn không cần biết vì sao thất bại. • try!: tuyên bố sẽ không bao giờ lỗi; nếu lỗi thì crash. Tương tự ! của Optional, chỉ dùng khi đảm bảo tuyệt đối (ví dụ đọc file có trong bundle). • defer: khối lệnh chạy khi thoát phạm vi hiện tại, dù thoát bằng return hay throw. Hợp để dọn dẹp (đóng file, dừng loading).

    Cũng có Result<Success, Failure>: enum success/failure để mang kết quả hoặc lỗi dưới dạng giá trị, hữu ích với callback; với async/await (tuần 6) bạn thường dùng throws trực tiếp.

    let ok = (try? validate(year: 2024)) != nil   // true nếu hợp lệ
let bad: Void? = try? validate(year: 1)    // nil: lỗi bị nuốt

func importData() throws {
    print("Bắt đầu loading")
    defer { print("Kết thúc loading") }     // luôn chạy dù throw hay return
    try validate(year: 1900)                 // throw ở đây
    print("Không tới được dòng này")
}

do { try importData() } catch { print("Failed: \(error.localizedDescription)") }

func parse(_ text: String) -> Result<Int, VehicleError> {
    guard let value = Int(text) else { return .failure(.invalidID) }
    return .success(value)
}

    5. So sánh với try/catch của JavaScript¶

    • JS: bất kỳ hàm nào cũng có thể ném lỗi mà không báo trước; catch nhận unknown/any. Swift: lỗi phải được khai báo (throws) và ghi nhận (try). • JS thường ném Error hay chuỗi bất kỳ; Swift dùng enum có kiểu, và switch/catch kiểm tra đầy đủ các case. • finally của JS tương ứng defer nhưng chạy khi thoát phạm vi chứ không riêng khối try. • try? tương tự .catch(() => undefined); hạn chế dùng nếu cần phân biệt nguyên nhân lỗi. • Swift chưa kiểm tra kiểu lỗi cụ thể ở mức hàm (đến Swift 6 có typed throws throws(MyError)), nên catch vẫn cần một nhánh tổng quát.

    6. Lỗi thường gặp¶

    1. Dùng try! cho đầu vào người dùng: crash.
    2. try? nuốt lỗi khiến app "im lặng thất bại"; chỉ dùng khi thực sự không cần nguyên nhân.
    3. Dùng một catch { } rỗng: ẩn lỗi, rất khó debug. Ít nhất hãy log.
    4. Ném NSError/chuỗi chung chung thay vì enum nghiệp vụ.
    5. Quên throws ở hàm gọi hàm có try không bọc do-catch: compiler báo "errors thrown from here are not handled".
    6. Dùng throws cho kết quả bình thường (ví dụ "không tìm thấy"): dùng Optional nếu không cần phân biệt lý do.
    7. Đưa error.localizedDescription ra UI mà enum chưa conform LocalizedError: ra chuỗi khó hiểu.

    7. Tóm tắt¶

    • Lỗi là enum conform Error; hàm khai báo throws, ném bằng throw, gọi bằng try. • do-catch xử lý theo từng case; hàm throws có thể lan truyền lỗi lên. • try? → Optional (nuốt lỗi); try! → crash nếu lỗi; defer dọn dẹp khi thoát phạm vi. • LocalizedError để có thông báo thân thiện. • Phân biệt: Optional (thiếu giá trị), throws (lỗi phục hồi), crash (lỗi lập trình).

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Định nghĩa custom error¶

    Tạo enum VehicleError: Error với emptyID, invalidYear(Int) và duplicateID(String). Viết validate(id:year:) ném các lỗi tương ứng khi ID rỗng hoặc năm ngoài 1990–2100.

    Gợi ý Dùng guard rồi throw. Case có dữ liệu đi kèm dùng associated value.
    Đáp án 
    enum VehicleError: Error {
    case emptyID
    case invalidYear(Int)
    case duplicateID(String)
}

func validate(id: String, year: Int) throws {
    guard !id.isEmpty else { throw VehicleError.emptyID }
    guard (1990...2100).contains(year) else { throw VehicleError.invalidYear(year) }
}
    **Giải thích:** Enum cho phép phân biệt lỗi theo nghiệp vụ. `guard ... else { throw }` kiểm tra điều kiện sớm và giữ luồng chính ngắn gọn.

    Bài 2 — Bắt từng loại lỗi¶

    Gọi validate(id: "", year: 2024) trong do-catch và in thông báo khác nhau cho emptyID, invalidYear và các lỗi còn lại.

    Gợi ý Mỗi catch có thể khớp một case; catch cuối không có pattern bắt phần còn lại.
    Đáp án 
    do {
    try validate(id: "", year: 2024)
} catch VehicleError.emptyID {
    print("Vui lòng nhập ID")
} catch VehicleError.invalidYear(let year) {
    print("Năm \(year) không hợp lệ")
} catch {
    print("Lỗi khác: \(error)")
}
    **Giải thích:** Thứ tự catch quan trọng: case cụ thể trước, tổng quát sau. Nhánh cuối đảm bảo `do-catch` bắt hết lỗi.

    Bài 3 — try, try? hay try!¶

    Chọn try, try? hay try! cho: (a) parse dữ liệu người dùng nhập; (b) đọc một file cấu hình mặc định luôn nằm trong app bundle; (c) lưu cache tùy chọn mà thất bại cũng không ảnh hưởng.

    Gợi ý Tự hỏi: lỗi có thể xảy ra thật sự không, và có cần biết nguyên nhân không?
    Đáp án 
    // (a) try trong do-catch: cần báo lỗi cho người dùng.
do { try validate(id: input, year: yearInput) } catch { show(error) }

// (b) try!: file nằm trong bundle, nếu thiếu là lỗi lập trình.
let data = try! Data(contentsOf: Bundle.main.url(forResource: "defaults", withExtension: "json")!)

// (c) try?: thất bại cũng không sao.
let cached = try? Data(contentsOf: cacheURL)
    **Giải thích:** Đầu vào bên ngoài không đáng tin nên cần `try` và xử lý. `try!` chỉ cho bất biến chắc chắn. `try?` hợp cho thao tác không quan trọng và không cần nguyên nhân.

    Bài 4 — defer¶

    Viết hàm importFile() bật isLoading = true, rồi gọi try process(). Dùng defer để isLoading luôn trở về false kể cả khi process() ném lỗi.

    Gợi ý Đặt defer ngay sau khi bật isLoading.
    Đáp án 
    var isLoading = false

func process() throws { throw VehicleError.emptyID }

func importFile() throws {
    isLoading = true
    defer { isLoading = false }     // chạy dù return hay throw
    try process()
}

do { try importFile() } catch { print("Lỗi") }
print(isLoading)   // false
    **Giải thích:** `defer` chạy khi thoát phạm vi bất kể bằng cách nào, nên tránh quên đặt lại trạng thái trên nhánh lỗi, một lỗi UI rất phổ biến (spinner quay mãi).
