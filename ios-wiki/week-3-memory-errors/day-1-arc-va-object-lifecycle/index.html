    Tuần 3 · Ngày 1 · ARC và object lifecycle¶

    Mục tiêu: Hiểu ARC quản lý bộ nhớ của class instance thế nào, khi nào instance bị giải phóng và cách quan sát bằng deinit.
    Thời lượng: 75–90 phút

    Khái niệm: ARC, strong reference, reference count, deinit, scope, value vs reference type

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Bộ nhớ trong Swift: không có garbage collector¶

    JavaScript dùng garbage collector: một tiến trình chạy định kỳ tìm object không còn ai dùng để xóa. Swift không có GC. Thay vào đó, compiler tự chèn các lệnh đếm tham chiếu vào code lúc build. Cơ chế này gọi là ARC (Automatic Reference Counting).

    Mỗi instance của class có một bộ đếm: có bao nhiêu tham chiếu mạnh (strong reference) đang trỏ tới nó. Khi bộ đếm về 0, instance được giải phóng ngay lập tức và deinit chạy. Không có độ trễ ngẫu nhiên như GC, nên hành vi dự đoán được và phù hợp với thiết bị di động.

    ARC chỉ áp dụng cho class (và closure, actor). Struct và enum là value type, được sao chép và không cần đếm tham chiếu.

    2. Strong reference và bộ đếm¶

    Mặc định mọi biến, hằng, thuộc tính tham chiếu tới class là strong: nó giữ instance sống. Gán thêm một biến trỏ tới instance làm bộ đếm tăng; biến ra khỏi phạm vi (scope) hoặc được gán nil làm bộ đếm giảm.

    Bạn không thể đọc trực tiếp reference count trong code bình thường, nhưng có thể quan sát qua deinit: dòng print trong deinit cho biết đúng lúc instance bị giải phóng. Đây là công cụ debug đơn giản và hiệu quả nhất cho vòng đời.

    final class DeviceSession {
    let id: String
    init(id: String) {
        self.id = id
        print("Session \(id) created")
    }
    deinit { print("Session \(id) freed") }
}

var first: DeviceSession? = DeviceSession(id: "S1")   // count = 1
var second = first                                    // count = 2
first = nil                                           // count = 1, chưa giải phóng
print("first = nil, nhưng second vẫn giữ")
second = nil                                          // count = 0 -> "Session S1 freed"

func run() {
    let local = DeviceSession(id: "S2")   // count = 1
    print("Đang dùng \(local.id)")
}                                          // ra khỏi hàm: "Session S2 freed"
run()

    3. Khi nào instance bị giải phóng¶

    Một instance được giải phóng ngay khi tham chiếu mạnh cuối cùng biến mất. Các tình huống phổ biến: • Biến cục bộ: giải phóng khi hàm kết thúc (hoặc sớm hơn, nếu không còn được dùng). • Thuộc tính của object khác: sống đến khi object cha bị giải phóng, hoặc thuộc tính bị gán lại. • Phần tử trong mảng/dictionary: sống đến khi bị xóa khỏi collection hoặc collection bị giải phóng. • Bị closure bắt (capture): sống chừng nào closure còn sống (bài 3).

    Hệ quả quan trọng: bạn không "gọi delete". Việc của bạn là thiết kế ai sở hữu ai. Instance cần sống bao lâu thì phải có một tham chiếu mạnh tương ứng giữ nó.

    final class Vehicle {
    let name: String
    init(name: String) { self.name = name }
    deinit { print("\(name) freed") }
}

var fleet: [Vehicle] = [Vehicle(name: "A"), Vehicle(name: "B")]
fleet.removeFirst()          // "A freed": mảng không còn giữ A
fleet = []                   // "B freed"

class Garage {
    var car: Vehicle?
    deinit { print("Garage freed") }
}
var garage: Garage? = Garage()
garage?.car = Vehicle(name: "C")
garage = nil                 // "Garage freed" rồi "C freed": cha chết kéo theo con

    4. Struct và ARC: vì sao struct không có deinit¶

    Struct và enum không có deinit vì chúng không có identity: mỗi bản sao độc lập và được hủy khi biến chứa nó hết phạm vi. Tuy vậy, struct có thể chứa thuộc tính kiểu class. Khi đó struct sao chép chỉ sao chép con trỏ, không sao chép instance, nên bộ đếm của class tăng theo số bản sao.

    Vì lý do này, "struct thì an toàn, không lo bộ nhớ" chỉ đúng khi mọi thuộc tính của nó cũng là value type. Một struct chứa một class và closure vẫn có thể tham gia retain cycle.

    final class Photo { deinit { print("Photo freed") } }

struct Gallery {
    var cover: Photo
}

var a: Gallery? = Gallery(cover: Photo())
var b = a                // bản sao struct, nhưng cùng một Photo (count = 2)
a = nil
print("a = nil, Photo vẫn sống vì b")
b = nil                  // "Photo freed"

    5. So sánh với JavaScript/Angular¶

    • JS: object bị thu hồi khi GC quyết định, thời điểm không xác định. Swift: giải phóng đúng lúc bộ đếm về 0, xác định. • Vì xác định, deinit đáng tin để dọn tài nguyên (đóng file, hủy đăng ký), còn finalize của JS thì không. • Angular có ngOnDestroy và phải hủy subscription thủ công để tránh leak; ở Swift bạn gặp vấn đề tương tự: nếu có tham chiếu mạnh vòng tròn, deinit không bao giờ chạy. • JS có closure bắt biến tự do và GC xử lý được vòng tham chiếu; ARC thì không phát hiện được vòng tham chiếu, bạn phải tự phá bằng weak/unowned.

    6. Lỗi thường gặp¶

    1. Tin rằng Swift "tự lo hết bộ nhớ": ARC không giải quyết được retain cycle (bài 2).
    2. Quên rằng mảng, dictionary, closure đều giữ tham chiếu mạnh tới class.
    3. Cho rằng đặt biến về nil luôn giải phóng instance: nếu còn tham chiếu khác, nó vẫn sống.
    4. Dùng class cho mọi thứ rồi gặp vấn đề vòng đời; hãy ưu tiên struct.
    5. Đặt logic quan trọng (lưu dữ liệu, gọi mạng) trong deinit: không nên, deinit chỉ để dọn dẹp đơn giản và không được là async.
    6. Không đặt print trong deinit khi nghi ngờ rò rỉ: đây là cách kiểm tra nhanh nhất.

    7. Tóm tắt¶

    • ARC đếm số tham chiếu mạnh tới class instance; về 0 thì giải phóng và chạy deinit. • Biến, thuộc tính, phần tử collection, closure đều có thể giữ strong reference. • Struct/enum không dùng ARC cho chính nó, nhưng nếu chứa class thì vẫn giữ strong reference tới class đó. • deinit là công cụ quan sát vòng đời; nếu không thấy nó chạy khi kỳ vọng, có thể đang rò rỉ. • Bài tiếp theo: khi hai object giữ nhau, ARC không thể giải phóng cả hai.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Đếm tham chiếu bằng deinit¶

    Tạo final class Session có deinit in "freed". Viết đoạn: tạo một biến Optional, gán thêm biến thứ hai trỏ cùng instance, gán lần lượt nil và quan sát thời điểm "freed" xuất hiện.

    Gợi ý Instance chỉ bị giải phóng khi MỌI biến strong trỏ tới nó đều đã nil.
    Đáp án 
    final class Session {
    deinit { print("freed") }
}

var a: Session? = Session()
var b = a
a = nil
print("a = nil")     // chưa freed
b = nil              // in ra "freed" ngay tại đây
    **Giải thích:** Sau dòng `var b = a` bộ đếm là 2. Gán `a = nil` giảm còn 1, `b = nil` giảm còn 0 và `deinit` chạy ngay lập tức.

    Bài 2 — Dự đoán thứ tự deinit¶

    Với Garage giữ var car: Vehicle?, tạo garage, gán một xe vào car, rồi đặt biến garage về nil. Thứ tự "Garage freed" và "car freed" ra sao? Vì sao?

    Gợi ý Garage bị giải phóng trước, sau đó các thuộc tính của nó mới được giải phóng.
    Đáp án 
    final class Vehicle { deinit { print("car freed") } }
final class Garage {
    var car: Vehicle?
    deinit { print("Garage freed") }
}

var garage: Garage? = Garage()
garage?.car = Vehicle()
garage = nil
// In ra: Garage freed
//        car freed
    **Giải thích:** `deinit` của Garage chạy trước, rồi các thuộc tính stored của nó được giải phóng. Xe chỉ bị giải phóng sau vì Garage là chủ sở hữu duy nhất của nó.

    Bài 3 — Struct chứa class¶

    Một struct Gallery chứa var cover: Photo (class). Sao chép gallery sang biến khác rồi hủy biến gốc. Photo có bị giải phóng không? Rút ra điều gì về value semantics?

    Gợi ý Sao chép struct chỉ sao chép con trỏ tới Photo.
    Đáp án 
    final class Photo { deinit { print("Photo freed") } }
struct Gallery { var cover: Photo }

var g1: Gallery? = Gallery(cover: Photo())
var g2 = g1
g1 = nil
print("vẫn còn g2")
g2 = nil         // lúc này Photo mới bị giải phóng
    **Giải thích:** Hai bản sao struct cùng giữ strong reference tới một Photo. Value semantics chỉ đầy đủ khi mọi thuộc tính đều là value type; thuộc tính class vẫn được chia sẻ.
