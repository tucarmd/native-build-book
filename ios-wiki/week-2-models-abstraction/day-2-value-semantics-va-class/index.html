    Tuần 2 · Ngày 2 · Value semantics và Class¶

    Mục tiêu: Phân biệt copy semantics của struct với shared identity của class, và biết khi nào nên chọn cái nào.
    Thời lượng: 75–90 phút

    Khái niệm: value semantics, reference semantics, identity, === vs ==, final class, deinit, inheritance

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Struct: mỗi biến giữ một bản sao riêng¶

    Gán một struct cho biến khác, hoặc truyền vào hàm, sẽ tạo bản sao độc lập. Sửa bản này không ảnh hưởng bản kia. Đây gọi là value semantics. Nó loại bỏ cả một lớp lỗi "ai đã sửa object của tôi?" vì dữ liệu không bị chia sẻ ngầm.

    Lưu ý: Array, String, Dictionary cũng là value type. Swift tối ưu bằng copy-on-write: dữ liệu chỉ được sao chép thật khi có ai sửa, nên bạn không phải lo hiệu năng khi truyền mảng lớn.

    struct Vehicle { var mileage: Int }

var a = Vehicle(mileage: 1000)
var b = a                // b là bản sao độc lập
b.mileage = 2000

print(a.mileage)         // 1000
print(b.mileage)         // 2000

func reset(_ v: Vehicle) -> Vehicle {
    var copy = v         // tham số là bản sao; sửa trong hàm không ảnh hưởng bên ngoài
    copy.mileage = 0
    return copy
}

    2. Class: nhiều biến cùng trỏ một instance¶

    Class là reference type. Hai biến có thể trỏ đến cùng một instance, nên sửa qua biến này sẽ thấy qua biến kia. Class có identity (đây có phải cùng một object không?) và vòng đời: nó được giải phóng khi không còn tham chiếu mạnh nào (ARC, tuần 3).

    Để so sánh danh tính dùng ===; để so sánh giá trị dùng == (cần Equatable). let với class chỉ giữ cố định tham chiếu, thuộc tính var bên trong vẫn sửa được. Class có deinit chạy ngay trước khi instance bị giải phóng, hữu ích để debug vòng đời.

    final class VehicleSession {
    var isConnected = false
    let id: String
    init(id: String) { self.id = id }
    deinit { print("Session \(id) freed") }
}

let first = VehicleSession(id: "S1")
let second = first                 // cùng instance
second.isConnected = true

print(first.isConnected)           // true
print(first === second)            // true: cùng identity

let other = VehicleSession(id: "S2")
print(first === other)             // false

    3. Khi nào dùng class, khi nào dùng struct¶

    Mặc định: struct. Chuyển sang class khi bạn thực sự cần: • Identity chung: nhiều nơi phải quan sát và sửa cùng một thực thể (kết nối BLE, session, cache dùng chung). • Vòng đời có ý nghĩa: cần deinit để dọn dẹp tài nguyên. • Kế thừa hoặc giao tiếp với API Objective-C/UIKit yêu cầu class (ví dụ UIViewController).

    Ví dụ trong dự án chẩn đoán: Vehicle, DiagnosticCode là struct vì chỉ là dữ liệu; BluetoothSession là class vì đại diện cho kết nối duy nhất mà nhiều thành phần dùng chung.

    4. Kế thừa, final và vì sao Swift ít dùng¶

    Class hỗ trợ kế thừa đơn: class Car: Vehicle. Subclass ghi đè method bằng override, gọi bản cha bằng super. Đánh dấu final để cấm kế thừa, vừa bày tỏ ý định vừa giúp compiler tối ưu.

    Swift cổ vũ composition và protocol thay cho cây kế thừa sâu (bài 4). Struct và enum không kế thừa được. Quy tắc thực dụng: viết final class trừ khi bạn có lý do rõ ràng để mở cho kế thừa.

    class Base {
    func describe() -> String { "Base" }
}
class Derived: Base {
    override func describe() -> String { "Derived of " + super.describe() }
}

final class Leaf { }          // không thể kế thừa
// class Sub: Leaf { }        // LỖI: inheritance from a final class

print(Derived().describe())   // "Derived of Base"

    5. Khởi tạo class: designated, convenience và required¶

    Khác struct, class không có memberwise initializer tự sinh: bạn phải viết init cho các thuộc tính chưa có giá trị mặc định. Có ba loại initializer: • Designated init: initializer chính, khởi tạo mọi thuộc tính của lớp rồi gọi init của lớp cha (nếu có). • Convenience init (convenience init): initializer phụ, tiện lợi, bắt buộc gọi một init khác của cùng lớp (cuối cùng dẫn tới designated). • Required init (required init): mọi subclass bắt buộc phải cài lại.

    Swift khởi tạo theo hai pha để bảo đảm an toàn. Pha 1: mọi thuộc tính của subclass được gán giá trị, rồi gọi super.init để cha gán nốt thuộc tính của nó. Pha 2: lúc này đối tượng đã hợp lệ, bạn mới được dùng self, gọi method hoặc tùy chỉnh thuộc tính của cha. Vì vậy trong subclass, gán thuộc tính của chính mình TRƯỚC super.init.

    Quy tắc kế thừa initializer: subclass chỉ tự động thừa hưởng init của cha khi nó không định nghĩa designated init riêng. Failable init (init?) trả về nil khi dữ liệu không hợp lệ.

    import Foundation

class Vehicle {
    let id: String
    var name: String

    init(id: String, name: String) {                 // designated
        self.id = id
        self.name = name
    }

    convenience init(name: String) {                 // convenience: gọi init khác của cùng lớp
        self.init(id: UUID().uuidString, name: name)
    }

    convenience init?(csv: String) {                 // failable convenience
        let parts = csv.split(separator: ",").map(String.init)
        guard parts.count == 2 else { return nil }
        self.init(id: parts[0], name: parts[1])
    }

    func describe() -> String { "Vehicle \(name)" }
}

final class ElectricCar: Vehicle {
    var batteryPercent: Int

    init(id: String, name: String, batteryPercent: Int) {
        self.batteryPercent = batteryPercent         // Pha 1: thuộc tính của subclass trước
        super.init(id: id, name: name)               // rồi mới gọi init của cha
        self.name = name.uppercased()                // Pha 2: bây giờ mới được dùng self
    }

    convenience init(name: String) {                 // phải tự khai báo vì đã có designated init riêng
        self.init(id: UUID().uuidString, name: name, batteryPercent: 100)
    }

    override func describe() -> String { super.describe() + " (\(batteryPercent)%)" }
}

print(Vehicle(csv: "V1,Camry")?.describe() ?? "invalid")   // Vehicle Camry
print(Vehicle(csv: "hỏng") == nil)                          // true

    6. Đóng gói (encapsulation): access control và property observers¶

    Đóng gói nghĩa là che chi tiết bên trong, chỉ để lộ giao diện cần thiết, để lớp tự bảo vệ các bất biến của nó. Swift có năm mức truy cập (từ rộng đến hẹp): • open: truy cập và kế thừa/override được từ module khác (chỉ cho class, dùng khi viết framework). • public: truy cập được từ module khác nhưng không kế thừa/override ngoài module. • internal: mặc định, trong cùng module (target). • fileprivate: chỉ trong cùng file. • private: chỉ trong khai báo bao quanh và các extension của nó cùng file.

    Không có protected như TypeScript/Java. private(set) rất hay dùng: cho đọc rộng nhưng chỉ lớp được ghi (public private(set) var state). Quy tắc: bắt đầu bằng mức hẹp nhất có thể, chỉ mở rộng khi thật sự cần.

    Property observer willSet/didSet chạy khi giá trị của một stored property đổi (không chạy khi gán trong init của chính lớp). Hợp để giữ bất biến (kẹp giá trị vào khoảng hợp lệ) hoặc kích hoạt cập nhật. Computed property (get/set) tính giá trị theo yêu cầu, còn lazy var chỉ tính lần đầu truy cập.

    final class BatteryMonitor {
    private(set) var percent: Int = 100 {            // ngoài lớp chỉ đọc được
        didSet {
            if percent < 0 { percent = 0 }            // giữ bất biến 0...100
            if percent > 100 { percent = 100 }
            if percent <= 15 && oldValue > 15 { print("Pin yếu") }
        }
    }
    private var history: [Int] = []                   // chi tiết nội bộ, không lộ ra

    var status: String { percent > 15 ? "OK" : "LOW" }  // computed property

    lazy var summary: String = {                      // chỉ tính khi dùng lần đầu
        "Lịch sử \(history.count) lần đo"
    }()

    func update(to newValue: Int) {
        history.append(newValue)
        percent = newValue
    }
}

let monitor = BatteryMonitor()
monitor.update(to: 150)            // percent bị kẹp về 100
monitor.update(to: 10)             // in "Pin yếu"
print(monitor.percent, monitor.status)
// monitor.percent = 50            // LỖI: 'percent' setter is inaccessible

    7. Đa hình (polymorphism): một lời gọi, nhiều hành vi¶

    Đa hình nghĩa là cùng một lời gọi, hành vi thực tế phụ thuộc vào kiểu thật của đối tượng. Swift có ba dạng: 1. Đa hình theo kế thừa (subtype): biến kiểu Vehicle có thể giữ ElectricCar; gọi describe() sẽ chạy bản override của kiểu thật (dynamic dispatch). Bài này. 2. Đa hình theo protocol: nhiều kiểu (cả struct, enum) cùng conform một protocol; dùng [any Describable] (bài 4). 3. Đa hình tham số (generics): một hàm/kiểu viết một lần, dùng cho nhiều kiểu (bài 4).

    Downcasting: khi cần biết kiểu thật, dùng is (kiểm tra), as? (ép kiểu an toàn, trả Optional) hoặc as! (ép bắt buộc, crash nếu sai). Hãy tránh phụ thuộc quá nhiều vào downcasting: nếu bạn thường xuyên "if is A ... else if is B ...", đó là dấu hiệu nên chuyển hành vi vào method đa hình.

    Hiệu năng: method của class không final dùng dynamic dispatch (tra bảng) và không thể inline; final, struct, enum dùng static dispatch nhanh hơn. Chỉ để mở khi bạn thật sự cần override.

    class Vehicle {
    let name: String
    init(name: String) { self.name = name }
    func fuelCost(km: Double) -> Double { km * 0.10 }     // xăng
}

final class ElectricCar: Vehicle {
    override func fuelCost(km: Double) -> Double { km * 0.04 }
}

final class Truck: Vehicle {
    override func fuelCost(km: Double) -> Double { super.fuelCost(km: km) * 3 }
}

let fleet: [Vehicle] = [Vehicle(name: "Camry"), ElectricCar(name: "Model 3"), Truck(name: "F-150")]

for v in fleet {
    print("\(v.name): \(v.fuelCost(km: 100))")             // mỗi kiểu chạy bản riêng của nó
}
let total = fleet.map { $0.fuelCost(km: 100) }.reduce(0, +)

// Downcasting
for v in fleet {
    if let ev = v as? ElectricCar { print("EV: \(ev.name)") }
}
print(fleet.contains { $0 is Truck })                       // true

    8. So sánh với TypeScript/JavaScript¶

    Trong JS, object và mảng luôn là reference: const b = a; b.x = 1 sửa cả a. Muốn sao chép phải tự structuredClone hay spread. Swift ngược lại: struct tự sao chép, và bạn chọn class khi muốn chia sẻ.

    Trong Angular, service là singleton chia sẻ trạng thái; tương đương là class (hoặc actor ở tuần 7). Model của component thường là object/POJO; ở Swift nên là struct. Về const: const obj của JS cho sửa thuộc tính bên trong, còn let với struct Swift thì không, vì bản thân giá trị là bất biến.

    9. Lỗi thường gặp¶

    1. Dùng class cho mọi model: dễ gặp tình huống một nơi sửa object khiến nơi khác thay đổi bất ngờ.
    2. Sửa struct trong mảng for var item in items rồi ngạc nhiên mảng không đổi: bạn đang sửa bản sao, phải gán lại vào mảng hoặc dùng chỉ số.
    3. Truyền struct lớn vào hàm và lo hiệu năng: thường không cần lo nhờ copy-on-write và tối ưu của compiler.
    4. Nhầm == với ===: === chỉ dùng cho class và so sánh cùng instance.
    5. Giữ tham chiếu mạnh lẫn nhau giữa hai class gây rò rỉ (tuần 3).
    6. Nói "struct ở stack, class ở heap": đây chỉ là xấp xỉ, vị trí thật do compiler quyết định.

    10. Tóm tắt¶

    • Struct/enum: value type, mỗi biến có bản sao riêng. • Class: reference type, nhiều biến có thể trỏ cùng instance; có identity (===), vòng đời và deinit. • Mặc định dùng struct; dùng final class khi cần identity/lifecycle chung. • Kế thừa chỉ có ở class; ưu tiên composition và protocol. • let với class chỉ cố định tham chiếu, không bảo vệ thuộc tính bên trong. • OOP trong Swift: khởi tạo hai pha (designated/convenience/required), đóng gói bằng access control (private(set), không có protected) và property observers, đa hình qua override (dynamic dispatch).

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Dự đoán output¶

    Với struct Counter { var value: Int }, chạy var a = Counter(value: 1); var b = a; b.value = 2; print(a.value, b.value). Kết quả là gì? Nếu Counter là class thì sao?

    Gợi ý Struct sao chép khi gán; class trỏ cùng một instance.
    Đáp án 
    struct Counter { var value: Int }
var a = Counter(value: 1)
var b = a
b.value = 2
print(a.value, b.value)    // 1 2

final class RefCounter { var value: Int; init(value: Int) { self.value = value } }
let x = RefCounter(value: 1)
let y = x
y.value = 2
print(x.value, y.value)    // 2 2
    **Giải thích:** Struct: hai bản sao độc lập. Class: `x` và `y` là hai tên cho cùng một instance nên sửa qua `y` làm `x` đổi theo.

    Bài 2 — Chọn struct hay class¶

    Chọn kiểu cho Vehicle (dữ liệu xe) và DeviceSession (kết nối thiết bị dùng chung bởi nhiều màn hình). Giải thích bằng value semantics.

    Gợi ý Hỏi: có cần nhiều nơi cùng thấy một thay đổi không? Có cần dọn dẹp khi kết thúc không?
    Đáp án 
    struct Vehicle {
    let id: String
    var make: String
}

final class DeviceSession {
    private(set) var isConnected = false
    func connect() { isConnected = true }
    func disconnect() { isConnected = false }
    deinit { print("Session closed") }
}
    **Giải thích:** `Vehicle` là dữ liệu, mỗi nơi nên có bản sao riêng nên dùng struct. `DeviceSession` đại diện cho một kết nối duy nhất, cần chia sẻ trạng thái và dọn dẹp nên dùng class.

    Bài 3 — Sửa phần tử struct trong mảng¶

    Cho var vehicles = [Vehicle(...), ...] với Vehicle là struct có var mileage. Viết đoạn tăng mileage thêm 100 cho tất cả xe. Vì sao for v in vehicles { v.mileage += 100 } không đúng?

    Gợi ý Biến lặp là bản sao. Hãy sửa qua chỉ số, hoặc dùng map để tạo mảng mới.
    Đáp án 
    struct Vehicle { let id: String; var mileage: Double }
var vehicles = [Vehicle(id: "1", mileage: 10), Vehicle(id: "2", mileage: 20)]

// Cách 1: sửa theo chỉ số
for index in vehicles.indices {
    vehicles[index].mileage += 100
}

// Cách 2: tạo mảng mới
vehicles = vehicles.map { v in
    var copy = v
    copy.mileage += 100
    return copy
}
    **Giải thích:** Trong `for v in vehicles`, `v` là hằng bản sao (và là `let`), nên vừa không sửa được vừa không ảnh hưởng mảng gốc. Truy cập qua chỉ số sửa trực tiếp phần tử trong mảng.

    Bài 4 — === và ==¶

    Với hai instance FinalSession khác nhau nhưng cùng id, == và === cho kết quả gì nếu class conform Equatable dựa trên id? Khi nào dùng ===?

    Gợi ý === kiểm tra cùng một ô nhớ, == kiểm tra theo định nghĩa bằng nhau của kiểu.
    Đáp án 
    final class FinalSession: Equatable {
    let id: String
    init(id: String) { self.id = id }
    static func == (l: FinalSession, r: FinalSession) -> Bool { l.id == r.id }
}

let a = FinalSession(id: "S1")
let b = FinalSession(id: "S1")
print(a == b)    // true: cùng id
print(a === b)   // false: hai instance khác nhau
    **Giải thích:** `===` hỏi "có cùng một object không", chỉ áp dụng cho class. `==` hỏi "có được coi là bằng nhau không" theo định nghĩa của kiểu. Hai khái niệm này độc lập với nhau.

    Bài 5 — Khởi tạo class có kế thừa¶

    Viết class Vehicle (id, name) và final class ElectricCar: Vehicle thêm batteryPercent. Cài đúng thứ tự khởi tạo hai pha và thêm một convenience init(name:) cho ElectricCar. Giải thích vì sao phải gán batteryPercent trước super.init.

    Gợi ý Subclass gán thuộc tính của chính nó trước, rồi super.init; convenience init phải gọi self.init.
    Đáp án 
    import Foundation

class Vehicle {
    let id: String
    var name: String
    init(id: String, name: String) { self.id = id; self.name = name }
}

final class ElectricCar: Vehicle {
    var batteryPercent: Int

    init(id: String, name: String, batteryPercent: Int) {
        self.batteryPercent = batteryPercent       // Pha 1: thuộc tính của subclass
        super.init(id: id, name: name)             // Pha 1: thuộc tính của cha
        // Pha 2: từ đây dùng self tự do
    }

    convenience init(name: String) {
        self.init(id: UUID().uuidString, name: name, batteryPercent: 100)
    }
}
    **Giải thích:** Swift yêu cầu mọi thuộc tính của một đối tượng có giá trị trước khi dùng `self`. Nếu gọi `super.init` trước mà `batteryPercent` chưa có giá trị, đối tượng chưa hợp lệ, nên compiler báo lỗi. Convenience init phải ủy quyền cho designated init của cùng lớp.

    Bài 6 — Đóng gói session Bluetooth¶

    Thiết kế final class BluetoothSession có state (enum idle/connecting/connected) chỉ đọc được bên ngoài, retryCount hoàn toàn nội bộ và method connect() / disconnect(). Viết một dòng code ngoài lớp cố ghi state để thấy lỗi compile.

    Gợi ý private(set) cho state, private cho retryCount.
    Đáp án 
    final class BluetoothSession {
    enum State { case idle, connecting, connected }

    private(set) var state: State = .idle
    private var retryCount = 0

    func connect() {
        state = .connecting
        retryCount += 1
        state = .connected
    }

    func disconnect() {
        state = .idle
        retryCount = 0
    }
}

let session = BluetoothSession()
session.connect()
print(session.state)             // đọc được
// session.state = .idle          // LỖI: setter is inaccessible
// session.retryCount             // LỖI: 'retryCount' is inaccessible due to 'private' protection
    **Giải thích:** Chỉ lớp thay đổi `state` thông qua các method, nên mọi chuyển trạng thái hợp lệ đều đi qua một chỗ. Đây là mục đích của đóng gói: bảo vệ bất biến và giữ chi tiết nội bộ tự do thay đổi.

    Bài 7 — Đa hình thay cho if/else theo kiểu¶

    Đoạn sau dùng nhiều is/as? để tính phí. Viết lại bằng đa hình: Vehicle.fee(days:) được ElectricCar và Truck override, và tính tổng phí của một mảng [Vehicle].

    func fee(for v: Vehicle, days: Int) -> Double { if v is ElectricCar { return Double(days) * 20 } else if v is Truck { return Double(days) * 80 } return Double(days) * 30 }

    Gợi ý Chuyển hành vi vào method của từng lớp và dùng map/reduce trên mảng.
    Đáp án 
    class Vehicle {
    func fee(days: Int) -> Double { Double(days) * 30 }
}
final class ElectricCar: Vehicle {
    override func fee(days: Int) -> Double { Double(days) * 20 }
}
final class Truck: Vehicle {
    override func fee(days: Int) -> Double { Double(days) * 80 }
}

let fleet: [Vehicle] = [Vehicle(), ElectricCar(), Truck()]
let total = fleet.map { $0.fee(days: 3) }.reduce(0, +)
print(total)   // 90 + 60 + 240 = 390
    **Giải thích:** Thêm loại xe mới chỉ cần thêm một subclass, không phải sửa hàm tính phí trung tâm (nguyên tắc Open/Closed). Với chuỗi `is/as?`, mỗi loại mới là một lần sửa hàm và dễ quên.
