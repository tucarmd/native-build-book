    Tuần 2 · Ngày 4 · Protocol và conformance¶

    Mục tiêu: Tách contract khỏi implementation bằng protocol, dùng extension, và hiểu some và any.
    Thời lượng: 75–90 phút

    Khái niệm: protocol, conformance, extension, protocol extension, some / any, protocol composition

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Protocol là một bản hợp đồng¶

    Protocol mô tả những gì một kiểu phải cung cấp (property, method, initializer) mà không nói cách làm. Bất kỳ struct, class hay enum nào đáp ứng đủ yêu cầu đều conform được. Code khác chỉ cần biết hợp đồng, không cần biết kiểu cụ thể.

    Bạn đã dùng protocol từ tuần 1 mà chưa biết: Equatable, Hashable, Identifiable, CaseIterable đều là protocol của thư viện chuẩn.

    protocol VehicleRepository {
    func getAll() -> [Vehicle]
    func findByID(_ id: String) -> Vehicle?
}

protocol Describable {
    var summary: String { get }        // { get }: chỉ cần đọc được
}

struct Vehicle: Describable {
    let id: String
    let make: String
    var summary: String { "Xe \(make)" }
}

    2. Cài đặt (conformance) và nhiều implementation¶

    Một protocol có thể có nhiều implementation: dữ liệu giả để phát triển, bộ nhớ, SQLite, REST API… Consumer chỉ phụ thuộc vào protocol nên đổi nguồn dữ liệu không phải sửa consumer. Đây chính là nền tảng của dependency injection (bài 5) và dễ viết test với mock.

    Khi một kiểu khai báo conform mà thiếu requirement, compiler báo lỗi "does not conform to protocol", kèm gợi ý "Add stubs for conformance".

    struct InMemoryVehicleRepository: VehicleRepository {
    private let vehicles: [Vehicle]
    init(vehicles: [Vehicle]) { self.vehicles = vehicles }

    func getAll() -> [Vehicle] { vehicles }
    func findByID(_ id: String) -> Vehicle? {
        vehicles.first { $0.id == id }
    }
}

struct EmptyVehicleRepository: VehicleRepository {   // implementation khác, ví dụ cho test
    func getAll() -> [Vehicle] { [] }
    func findByID(_ id: String) -> Vehicle? { nil }
}

    3. Extension và protocol extension¶

    extension thêm method/computed property vào một kiểu đã có, kể cả kiểu của Apple như String hay Int, mà không cần kế thừa. Dùng để chia code theo trách nhiệm hoặc đặt conformance ra riêng.

    extension của protocol cho phép cung cấp implementation mặc định: mọi kiểu conform đều có sẵn, và có thể ghi đè nếu muốn. Đây là cách Swift chia sẻ hành vi mà không cần cây kế thừa của class.

    extension Vehicle {
    var isRecent: Bool { year >= 2020 }      // thêm hành vi cho kiểu có sẵn
}

extension String {
    var isBlank: Bool { trimmingCharacters(in: .whitespaces).isEmpty }
}

extension VehicleRepository {                // implementation mặc định cho mọi repository
    func exists(_ id: String) -> Bool { findByID(id) != nil }
}

print("  ".isBlank)    // true

    4. any và some: dùng protocol như một kiểu¶

    Từ Swift 5.6+, khi dùng protocol làm kiểu của biến/tham số, bạn viết rõ any VehicleRepository: giá trị có thể là bất kỳ kiểu nào conform, được xác định lúc chạy (existential, có chi phí nhỏ). some VehicleRepository (opaque type) nghĩa là một kiểu cụ thể nhưng ẩn tên, compiler biết lúc build; hiệu năng tốt hơn và thường dùng trong SwiftUI (some View).

    Quy tắc đơn giản: cần lưu nhiều kiểu khác nhau trong cùng biến/mảng thì dùng any. Chỉ trả về hoặc nhận một kiểu cụ thể mà không muốn lộ tên thì dùng some. Hầu hết code UI bạn viết ở tuần 5 sẽ gặp some View.

    final class VehicleListModel {
    private let repository: any VehicleRepository     // lưu bất kỳ implementation nào
    init(repository: any VehicleRepository) { self.repository = repository }
}

func makeDefaultRepository() -> some VehicleRepository {   // trả về một kiểu cụ thể, ẩn tên
    InMemoryVehicleRepository(vehicles: [])
}

    5. Đa hình qua protocol (protocol-oriented programming)¶

    Swift khuyến khích "protocol-oriented programming": thay vì cây kế thừa, bạn mô tả khả năng bằng protocol rồi để nhiều kiểu (struct, enum, class) cùng conform. Cùng một lời gọi hoạt động trên mọi kiểu conform, đây là đa hình (ở bài 2 là đa hình theo kế thừa).

    Điểm khác biệt quan trọng so với class: struct và enum cũng đa hình được và vẫn giữ value semantics; một kiểu có thể conform nhiều protocol (Swift chỉ cho kế thừa đơn từ một class). Protocol extension cho phép chia sẻ cài đặt mặc định mà không cần lớp cha.

    Lưu ý dispatch: hàm là requirement của protocol sẽ gọi bản của kiểu thật (dynamic). Hàm chỉ tồn tại trong protocol extension mà không khai báo trong protocol thì được chọn theo kiểu khai báo của biến (static), dễ gây bất ngờ. Hãy khai báo mọi hàm muốn ghi đè được trong protocol.

    protocol Scannable {
    var name: String { get }
    func scan() -> String                       // requirement: dynamic dispatch
}

extension Scannable {
    func scan() -> String { "Quét mặc định bởi \(name)" }   // cài đặt mặc định
    func report() -> String { "[\(name)] " + scan() }        // dùng chung
}

struct ObdScanner: Scannable { let name = "OBD" }                              // dùng mặc định
struct BleScanner: Scannable {
    let name = "BLE"
    func scan() -> String { "Quét BLE trong 5 giây" }                          // ghi đè
}
enum DemoScanner: Scannable {
    case fake
    var name: String { "Demo" }
    func scan() -> String { "Dữ liệu giả lập" }
}

let scanners: [any Scannable] = [ObdScanner(), BleScanner(), DemoScanner.fake]
for s in scanners { print(s.report()) }          // mỗi kiểu chạy scan() của riêng nó

    6. Generics: viết một lần, dùng cho nhiều kiểu¶

    Generics cho phép viết hàm và kiểu không gắn với một kiểu cụ thể. Bạn đã dùng generics từ tuần 1: Array<Element>, Dictionary<Key, Value>, Optional<Wrapped>, Result<Success, Failure> đều là generic. Đây cũng là "đa hình tham số".

    Cú pháp: tham số kiểu trong <> (<T>). Có thể ràng buộc bằng protocol: <T: Comparable> nghĩa là T phải so sánh được; dùng mệnh đề where cho ràng buộc phức tạp (where T.ID == String). Compiler chuyên biệt hóa mã cho từng kiểu cụ thể nên nhanh như viết tay, và kiểu vẫn tồn tại khi chạy (khác TypeScript xóa kiểu sau khi biên dịch).

    Protocol cũng có thể generic thông qua associatedtype: một placeholder kiểu mà kiểu conform sẽ chỉ rõ. Ví dụ Repository có associatedtype Item. Khi dùng protocol có associatedtype làm kiểu của biến, bạn cần some/any hoặc ràng buộc generic.

    // 1. Hàm generic với ràng buộc
func largest<T: Comparable>(_ items: [T]) -> T? {
    items.max()
}
print(largest([3, 9, 4]) ?? 0, largest(["b", "z", "a"]) ?? "")

// 2. Kiểu generic: Stack dùng được cho mọi Element
struct Stack<Element> {
    private var storage: [Element] = []
    mutating func push(_ item: Element) { storage.append(item) }
    mutating func pop() -> Element? { storage.popLast() }      // Optional: null-safety
    var top: Element? { storage.last }
    var count: Int { storage.count }
}
var stack = Stack<String>()
stack.push("A"); stack.push("B")
print(stack.pop() ?? "", stack.count)                          // B 1

// 3. Protocol với associatedtype + repository generic
protocol Repository {
    associatedtype Item: Identifiable
    func getAll() -> [Item]
    func find(id: Item.ID) -> Item?
}

struct InMemoryRepository<Item: Identifiable>: Repository {
    private let items: [Item]
    init(items: [Item]) { self.items = items }
    func getAll() -> [Item] { items }
    func find(id: Item.ID) -> Item? { items.first { $0.id == id } }
}

struct Vehicle: Identifiable { let id: String; let name: String }
let repo = InMemoryRepository(items: [Vehicle(id: "V1", name: "Camry")])
print(repo.find(id: "V1")?.name ?? "not found")

// 4. where clause
func firstDuplicate<S: Sequence>(in items: S) -> S.Element? where S.Element: Hashable {
    var seen = Set<S.Element>()
    for item in items {
        if !seen.insert(item).inserted { return item }
    }
    return nil
}
print(firstDuplicate(in: [1, 2, 3, 2]) ?? 0)                    // 2

    7. Extension nâng cao: extension function, ràng buộc và null-safety¶

    Extension cho phép thêm method, computed property, initializer, subscript và conformance vào một kiểu có sẵn (kể cả kiểu của Apple) mà không cần mã nguồn của nó. Đây là khái niệm tương đương "extension function" của Kotlin/C#, hoặc việc mở rộng prototype trong JavaScript nhưng an toàn kiểu và có phạm vi module.

    Các kỹ thuật quan trọng: • Extension có điều kiện: extension Array where Element == Int chỉ thêm tính năng khi kiểu phần tử thỏa điều kiện. Dùng Sequence/Collection để áp dụng cho nhiều kiểu. • Extension cho Optional: extension Optional where Wrapped == String thêm tiện ích cho chuỗi có thể nil (null-safety gọn hơn). • Conditional conformance: extension Stack: Equatable where Element: Equatable: Stack so sánh được khi phần tử so sánh được. • Giới hạn: extension không thêm được stored property; không nên ghi đè hành vi có sẵn; đặt tên tránh xung đột; đặt private/fileprivate cho tiện ích nội bộ. Tổ chức code: dùng extension để chia một kiểu thành các nhóm (conformance, helper) theo file.

    import Foundation

// 1. Thêm method/computed property cho kiểu có sẵn
extension String {
    var trimmed: String { trimmingCharacters(in: .whitespacesAndNewlines) }
    func truncated(to length: Int) -> String {
        count <= length ? self : String(prefix(length)) + "…"
    }
}
print("  Toyota Camry  ".trimmed.truncated(to: 6))          // Toyota…

// 2. Extension có điều kiện trên Sequence
extension Sequence where Element: Numeric {
    var total: Element { reduce(0, +) }
}
print([1, 2, 3].total, [1.5, 2.5].total)                    // 6 4.0

extension Collection where Element == Int {
    var average: Double? {
        isEmpty ? nil : Double(total) / Double(count)       // null-safety: rỗng thì nil
    }
}
print([2, 4, 6].average ?? 0, [Int]().average as Any)       // 4.0 nil

// 3. Extension cho Optional (null-safety)
extension Optional where Wrapped == String {
    var isNilOrEmpty: Bool { self?.isEmpty ?? true }
    func orDefault(_ fallback: String) -> String { isNilOrEmpty ? fallback : self! }
}
let model: String? = nil
print(model.isNilOrEmpty, model.orDefault("Không rõ"))      // true Không rõ

// 4. Conditional conformance
struct Stack<Element> { var items: [Element] = [] }
extension Stack: Equatable where Element: Equatable { }
print(Stack(items: [1, 2]) == Stack(items: [1, 2]))         // true

    8. So sánh với TypeScript và Angular¶

    • protocol tương đương interface của TypeScript nhưng kiểu phải khai báo conform một cách tường minh (không phải structural typing như TS: có đủ method chưa đủ để "tự conform"). • Trong Angular, bạn tạo abstract class hoặc InjectionToken rồi provide implementation; ở Swift là protocol + truyền implementation qua initializer. • extension giống việc thêm method vào prototype, nhưng an toàn kiểu và có phạm vi (module). • Protocol extension ~ mixin; không có kế thừa nhiều class nhưng một kiểu conform được nhiều protocol.

    9. Lỗi thường gặp¶

    1. Tạo protocol cho mọi thứ "đề phòng": thêm phức tạp mà không có lợi. Chỉ trừu tượng hóa ở ranh giới cần thay thế hoặc test.
    2. Quên mutating trong requirement khi struct cần sửa mình.
    3. Quên any: Swift đang tiến tới bắt buộc ghi any khi dùng protocol làm kiểu; nên viết rõ ngay từ bây giờ.
    4. Protocol có associatedtype hoặc Self không dùng làm kiểu trực tiếp được; cần generic hoặc some/any.
    5. Kỳ vọng ghi đè method từ protocol extension hoạt động như kế thừa: nếu method không phải requirement, nó được gọi tĩnh theo kiểu khai báo.
    6. Đặt quá nhiều trách nhiệm vào một protocol: nên tách nhỏ theo vai trò.

    10. Tóm tắt¶

    • Protocol là hợp đồng; nhiều kiểu (struct/class/enum) có thể cùng conform. • Consumer phụ thuộc protocol thì đổi implementation không đổi consumer. • extension thêm hành vi cho mọi kiểu, protocol extension cho implementation mặc định. • any P: bất kỳ kiểu conform P (quyết định lúc chạy); some P: một kiểu cụ thể ẩn tên. • Chỉ tạo protocol ở ranh giới thật sự cần thay thế hoặc test. • Đa hình qua protocol cho struct/enum và nhiều protocol; generics (<T: Constraint>, where, associatedtype) viết một lần dùng nhiều kiểu; extension nâng cao (có điều kiện, trên Optional, conditional conformance) tương đương extension function.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Thêm requirement¶

    Thêm func count() -> Int vào VehicleRepository và cập nhật InMemoryVehicleRepository. Nếu muốn mọi repository có count mà không phải viết lại, nên làm cách nào?

    Gợi ý Có hai hướng: thêm requirement (mỗi kiểu tự cài) hoặc thêm vào protocol extension (cài một lần, dựa trên getAll()).
    Đáp án 
    protocol VehicleRepository {
    func getAll() -> [Vehicle]
    func findByID(_ id: String) -> Vehicle?
}

// Cách giữ nguyên các implementation: implementation mặc định dựa trên requirement sẵn có
extension VehicleRepository {
    func count() -> Int { getAll().count }
}

// Nếu cần tối ưu, từng kiểu vẫn có thể tự cài count() riêng
    **Giải thích:** Nếu thêm requirement vào protocol, mọi kiểu conform phải cài (trừ khi có default). Extension cung cấp default nên không làm vỡ code cũ.

    Bài 2 — Vì sao phụ thuộc protocol?¶

    Giải thích lợi ích khi VehicleListModel nhận any VehicleRepository thay vì InMemoryVehicleRepository. Viết một mock dùng cho test.

    Gợi ý Nghĩ đến việc test không cần mạng và việc chuyển nguồn dữ liệu sang REST API.
    Đáp án 
    struct MockVehicleRepository: VehicleRepository {
    var vehicles: [Vehicle] = []
    func getAll() -> [Vehicle] { vehicles }
    func findByID(_ id: String) -> Vehicle? { vehicles.first { $0.id == id } }
}

let model = VehicleListModel(
    repository: MockVehicleRepository(vehicles: [Vehicle(id: "V1", make: "Test")])
)
    **Giải thích:** Model không phụ thuộc chi tiết lấy dữ liệu nên có thể thay in-memory bằng remote hay mock mà không sửa model. Mock giúp test nhanh, ổn định và không cần mạng.

    Bài 3 — Extension cho kiểu có sẵn¶

    Thêm computed property isValidPlate cho String kiểm tra biển số không rỗng và dài từ 6 đến 12 ký tự (sau khi bỏ khoảng trắng hai đầu).

    Gợi ý Dùng trimmingCharacters(in:) và so sánh count với range.
    Đáp án 
    import Foundation

extension String {
    var isValidPlate: Bool {
        let trimmed = trimmingCharacters(in: .whitespaces)
        return (6...12).contains(trimmed.count)
    }
}

print("30A-12345".isValidPlate)   // true
print("  A1 ".isValidPlate)       // false
    **Giải thích:** Extension thêm hành vi cho kiểu có sẵn mà không cần kế thừa. Cần `import Foundation` vì `trimmingCharacters` thuộc Foundation.

    Bài 4 — Protocol composition¶

    Viết hàm show nhận một giá trị vừa Identifiable vừa CustomStringConvertible rồi in id và description. Giải thích ý nghĩa của & và vì sao cần some.

    Gợi ý Identifiable có associatedtype nên cần dùng some/any hoặc generic. & nghĩa là phải conform cả hai.
    Đáp án 
    struct Vehicle: Identifiable, CustomStringConvertible {
    let id: String
    var description: String { "Vehicle \(id)" }
}

func show(_ item: some Identifiable & CustomStringConvertible) {
    print(item.id, item.description)
}

show(Vehicle(id: "V1"))
    **Giải thích:** `&` kết hợp nhiều protocol: tham số phải conform tất cả. `Identifiable` có `associatedtype ID` nên không dùng như kiểu trần được; `some` giải quyết bằng cách chọn một kiểu cụ thể khi gọi.

    Bài 5 — Generic Stack và Queue¶

    Viết struct Stack<Element> với push, pop (trả Optional), peek và isEmpty. Sau đó viết hàm generic reversed<T>(_ items: [T]) -> [T] dùng Stack. Vì sao pop() trả Element??

    Gợi ý Stack rỗng thì không có phần tử để trả; Optional biểu diễn điều đó.
    Đáp án 
    struct Stack<Element> {
    private var storage: [Element] = []
    var isEmpty: Bool { storage.isEmpty }
    func peek() -> Element? { storage.last }
    mutating func push(_ item: Element) { storage.append(item) }
    mutating func pop() -> Element? { storage.popLast() }
}

func reversed<T>(_ items: [T]) -> [T] {
    var stack = Stack<T>()
    items.forEach { stack.push($0) }
    var result: [T] = []
    while let item = stack.pop() { result.append(item) }
    return result
}

print(reversed([1, 2, 3]), reversed(["a", "b"]))   // [3, 2, 1] ["b", "a"]
    **Giải thích:** Một cài đặt dùng được cho `Int`, `String` và mọi kiểu khác nhờ tham số kiểu. `pop()` trả Optional để ép người gọi xử lý trường hợp rỗng thay vì crash (null-safety).

    Bài 6 — Extension nâng cao và null-safety¶

    Viết (1) extension Optional where Wrapped == String có isNilOrEmpty; (2) extension Collection where Element: Numeric có isAllZero; (3) một hàm describe(_ model: String?) dùng isNilOrEmpty để trả "Không rõ" khi thiếu.

    Gợi ý Extension có điều kiện dùng where; Optional chaining self?.isEmpty ?? true.
    Đáp án 
    extension Optional where Wrapped == String {
    var isNilOrEmpty: Bool { self?.isEmpty ?? true }
}

extension Collection where Element: Numeric {
    var isAllZero: Bool { allSatisfy { $0 == 0 } }
}

func describe(_ model: String?) -> String {
    model.isNilOrEmpty ? "Không rõ" : model!
}

print(describe(nil), describe(""), describe("Camry"))    // Không rõ Không rõ Camry
print([0, 0].isAllZero, [0.0, 1.5].isAllZero)             // true false
    **Giải thích:** Extension có điều kiện chỉ xuất hiện khi kiểu thỏa ràng buộc, nên không làm "ô nhiễm" các kiểu khác. Dùng `!` ở trên an toàn vì đã kiểm tra `isNilOrEmpty` ngay trước đó; cách tốt hơn là `if let`.

    Bài 7 — Repository generic¶

    Viết protocol Repository với associatedtype Item: Identifiable và struct InMemoryRepository<Item: Identifiable> cài đặt getAll() và find(id:). Dùng nó cho cả Vehicle và Driver. Điều gì được "tái sử dụng" so với viết hai repository riêng?

    Gợi ý find(id: Item.ID) dùng associatedtype ID của Identifiable.
    Đáp án 
    protocol Repository {
    associatedtype Item: Identifiable
    func getAll() -> [Item]
    func find(id: Item.ID) -> Item?
}

struct InMemoryRepository<Item: Identifiable>: Repository {
    private let items: [Item]
    init(items: [Item]) { self.items = items }
    func getAll() -> [Item] { items }
    func find(id: Item.ID) -> Item? { items.first { $0.id == id } }
}

struct Vehicle: Identifiable { let id: String; let name: String }
struct Driver: Identifiable { let id: Int; let fullName: String }

let vehicles = InMemoryRepository(items: [Vehicle(id: "V1", name: "Camry")])
let drivers = InMemoryRepository(items: [Driver(id: 7, fullName: "An")])
print(vehicles.find(id: "V1")?.name ?? "-", drivers.find(id: 7)?.fullName ?? "-")
    **Giải thích:** Logic tìm kiếm viết một lần cho mọi kiểu `Identifiable`, kể cả khi `ID` là `String` hay `Int`. Bạn chỉ viết riêng khi hành vi thực sự khác nhau (ví dụ truy vấn API riêng cho từng loại).
