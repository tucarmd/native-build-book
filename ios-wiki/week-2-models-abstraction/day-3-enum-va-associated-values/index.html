    Tuần 2 · Ngày 3 · Enum và associated values¶

    Mục tiêu: Mô hình hóa trạng thái hữu hạn bằng enum, dùng associated value và raw value, và để compiler buộc xử lý đầy đủ.
    Thời lượng: 75–90 phút

    Khái niệm: enum, switch exhaustiveness, associated values, raw values, CaseIterable, enum vs Optional

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Enum: tập hợp trạng thái hữu hạn¶

    Enum của Swift mạnh hơn nhiều so với enum của TypeScript/Java: nó là kiểu hạng nhất, có thể có method, computed property và conform protocol. Dùng enum bất cứ khi nào một giá trị chỉ có thể là một trong số ít khả năng rõ ràng: trạng thái kết nối, loại lỗi, loại xe.

    Ý nghĩa lớn nhất: tạo ra dữ liệu mà trạng thái không hợp lệ không thể diễn đạt được. Thay vì hai biến isConnected và isConnecting có thể cùng true, enum cho phép đúng một trạng thái tại một thời điểm.

    enum ConnectionStatus {
    case disconnected
    case connecting
    case connected
}

var status = ConnectionStatus.disconnected
status = .connecting                // kiểu đã rõ nên viết gọn .case

func message(for status: ConnectionStatus) -> String {
    switch status {
    case .disconnected: return "Chưa kết nối"
    case .connecting:   return "Đang kết nối"
    case .connected:    return "Đã kết nối"
    }                               // không cần default vì đã đủ case
}

    2. Associated values: case mang dữ liệu riêng¶

    Mỗi case có thể mang dữ liệu đi kèm với kiểu khác nhau. Khi switch, bạn lấy dữ liệu ra bằng case .failed(let message). Mô hình này gọi là tagged union hoặc sum type, giúp gộp "trạng thái" và "dữ liệu của trạng thái đó" vào một chỗ, thay vì giữ status và errorMessage? rời rạc dễ lệch nhau.

    Bạn cũng có thể gắn nhãn cho giá trị đi kèm, ví dụ case failed(code: Int, message: String). Khi chỉ cần kiểm tra một case, if case ngắn gọn hơn switch.

    enum ConnectionStatus {
    case disconnected
    case connecting
    case connected(deviceName: String)
    case failed(code: Int, message: String)
}

func message(for status: ConnectionStatus) -> String {
    switch status {
    case .disconnected:
        return "Chưa kết nối"
    case .connecting:
        return "Đang kết nối"
    case .connected(let deviceName):
        return "Đã kết nối \(deviceName)"
    case .failed(let code, let message):
        return "Lỗi \(code): \(message)"
    }
}

let s = ConnectionStatus.failed(code: 408, message: "Timeout")
print(message(for: s))

if case .connected(let name) = s { print(name) }   // không chạy: s không phải connected

    3. Raw values, CaseIterable và method trong enum¶

    Enum có thể gán raw value (chuỗi hoặc số) để nối với dữ liệu bên ngoài như JSON hay database. CaseIterable tự sinh allCases để duyệt mọi case, tiện cho picker và hiển thị. init?(rawValue:) trả về Optional vì giá trị bên ngoài có thể không hợp lệ.

    Bạn có thể thêm computed property và method vào enum để nhóm logic liên quan: ví dụ isActive hay title, thay vì rải switch khắp nơi.

    enum FuelType: String, CaseIterable {
    case gasoline
    case diesel
    case electric

    var title: String {
        switch self {
        case .gasoline: return "Xăng"
        case .diesel:   return "Dầu"
        case .electric: return "Điện"
        }
    }
}

print(FuelType.electric.rawValue)           // "electric"
print(FuelType(rawValue: "diesel") as Any)  // Optional(FuelType.diesel)
print(FuelType(rawValue: "hydrogen") as Any)// nil

for fuel in FuelType.allCases { print(fuel.title) }

    4. Enum hay Optional? Enum hay Bool?¶

    • Optional phù hợp khi chỉ có hai khả năng "có" hoặc "không có", và lý do không có không quan trọng. • Enum phù hợp khi cần phân biệt nhiều lý do hoặc nhiều trạng thái có ý nghĩa nghiệp vụ. • Nhiều Bool có thể thay bằng một enum: isLoading, isLoaded, hasError dễ rơi vào tổ hợp vô lý (vừa loading vừa error). Một enum LoadState (idle, loading, loaded, failed) không thể.

    Swift còn có sẵn Result<Success, Failure> (enum success/failure) cho kết quả có thể thất bại; bạn sẽ dùng nó và throws ở tuần 3.

    5. So sánh với TypeScript và Angular¶

    • enum của TypeScript chỉ là tập hằng; Swift enum mang dữ liệu và method. • Tương đương gần nhất với associated values là discriminated union của TypeScript: type State = { kind: "failed"; message: string } | .... Swift làm điều đó gọn và an toàn hơn vì compiler kiểm tra exhaustiveness. • Trong Angular bạn thường dùng isLoading, error, data rời rạc; ở Swift nên gom thành enum một biến duy nhất. • switch với enum không cần default: thêm case mới thì compiler tự báo mọi chỗ cần cập nhật. Đây là lợi ích bảo trì lớn.

    6. Lỗi thường gặp¶

    1. Thêm default vào mọi switch của enum: che mất cảnh báo khi thêm case mới. Chỉ dùng default khi thật sự muốn gộp.
    2. Dùng String thay enum cho trạng thái ("connected" gõ sai thành "conected" thì không ai báo).
    3. Quên rằng init(rawValue:) trả về Optional.
    4. Dùng nhiều Bool để mô tả trạng thái loại trừ nhau.
    5. Trộn trạng thái và dữ liệu rời rạc (status + errorMessage) khiến dữ liệu lỗi còn sót khi trạng thái đã đổi.
    6. Lấy dữ liệu từ associated value mà không dùng let trong pattern: case .failed(message) sẽ lỗi.

    7. Tóm tắt¶

    • Enum biểu diễn tập trạng thái hữu hạn; mỗi lần chỉ ở một case. • Associated value gắn dữ liệu riêng cho từng case, gom trạng thái và dữ liệu lại. • Raw value nối với JSON/DB; CaseIterable cho allCases. • switch phải exhaustive; tránh default để compiler giúp bạn khi thêm case. • Dùng enum thay cho nhiều Bool hoặc String "ma thuật".

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Thêm trạng thái¶

    Thêm case unauthorized vào ConnectionStatus và cập nhật message(for:). Điều gì xảy ra nếu bạn quên cập nhật switch và vì sao không nên dùng default?

    Gợi ý Thêm case vào enum rồi build: compiler sẽ chỉ ra những switch chưa xử lý.
    Đáp án 
    enum ConnectionStatus {
    case disconnected, connecting, connected, unauthorized
    case failed(message: String)
}

func message(for status: ConnectionStatus) -> String {
    switch status {
    case .disconnected: return "Chưa kết nối"
    case .connecting:   return "Đang kết nối"
    case .connected:    return "Đã kết nối"
    case .unauthorized: return "Cần cấp quyền"
    case .failed(let message): return message
    }
}
    **Giải thích:** Nếu quên, compiler báo lỗi "Switch must be exhaustive". Nếu bạn dùng `default`, lỗi bị che và case mới sẽ rơi vào nhánh mặc định một cách âm thầm.

    Bài 2 — Kết quả tìm kiếm¶

    Tạo enum VehicleLookupResult có found(Vehicle), notFound, invalidID. Viết hàm lookup(id:) và xử lý bằng switch.

    Gợi ý Case found mang Vehicle làm associated value. ID rỗng là invalidID.
    Đáp án 
    struct Vehicle { let id: String; let model: String }

enum VehicleLookupResult {
    case found(Vehicle)
    case notFound
    case invalidID
}

let store = ["V001": Vehicle(id: "V001", model: "Camry")]

func lookup(id: String) -> VehicleLookupResult {
    guard !id.isEmpty else { return .invalidID }
    if let v = store[id] { return .found(v) }
    return .notFound
}

switch lookup(id: "V001") {
case .found(let v):  print("Tìm thấy \(v.model)")
case .notFound:      print("Không có")
case .invalidID:     print("ID không hợp lệ")
}
    **Giải thích:** Optional chỉ phân biệt có/không; enum này phân biệt hai lý do thất bại khác nhau nên UI có thể hiển thị thông báo phù hợp.

    Bài 3 — Raw value và JSON¶

    Một API trả về "fuel": "diesel". Viết enum FuelType: String và chuyển chuỗi nhận được thành enum một cách an toàn, mặc định .gasoline nếu không nhận ra.

    Gợi ý init?(rawValue:) trả về Optional; dùng ?? để đặt mặc định.
    Đáp án 
    enum FuelType: String {
    case gasoline, diesel, electric
}

let raw = "diesel"
let fuel = FuelType(rawValue: raw) ?? .gasoline
print(fuel)   // diesel

print(FuelType(rawValue: "hydrogen") ?? .gasoline)   // gasoline
    **Giải thích:** Dữ liệu từ ngoài không đáng tin, nên `init(rawValue:)` trả về Optional. Quyết định mặc định hay báo lỗi phụ thuộc nghiệp vụ.

    Bài 4 — Thay nhiều Bool bằng một enum¶

    Đoạn code dùng var isLoading = false; var hasError = false; var data: [String]?. Chỉ ra tổ hợp trạng thái vô lý và thiết kế lại bằng enum LoadState.

    Gợi ý Các trạng thái loại trừ nhau: chưa tải, đang tải, tải xong (có dữ liệu), lỗi (có thông báo).
    Đáp án 
    enum LoadState {
    case idle
    case loading
    case loaded([String])
    case failed(String)
}

var state = LoadState.idle
state = .loading
state = .loaded(["V001", "V002"])

switch state {
case .idle:           print("Chưa tải")
case .loading:        print("Đang tải…")
case .loaded(let items): print("Có \(items.count) mục")
case .failed(let msg):   print("Lỗi: \(msg)")
}
    **Giải thích:** Với ba biến rời, có thể xảy ra `isLoading == true` và `hasError == true` cùng lúc hoặc có `data` mà vẫn `hasError`. Enum chỉ cho phép đúng một trạng thái và dữ liệu đi kèm trạng thái đó. Mẫu này sẽ dùng lại ở tuần 5 và 6.
