    Tuần 7 · Ngày 3 · Actors, MainActor và data races¶

    Mục tiêu: Phân biệt async task với actor isolation, cập nhật UI an toàn bằng @MainActor, tránh shared mutable state và hiểu Sendable.
    Thời lượng: 90–120 phút

    Khái niệm: actor, @MainActor, Sendable, data race, isolation, nonisolated, structured concurrency

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Data race là gì và vì sao nguy hiểm¶

    Data race xảy ra khi hai luồng cùng truy cập một dữ liệu đồng thời và ít nhất một bên ghi, mà không có đồng bộ. Hậu quả: giá trị sai ngẫu nhiên, crash khó tái hiện, hỏng cấu trúc dữ liệu. JavaScript đơn luồng nên gần như không gặp; Swift chạy nhiều luồng nên đây là mối nguy thật.

    Ví dụ: hai task cùng counter += 1 trên một biến chung: cả hai đọc 5, cùng ghi 6; một lần tăng bị mất. Hoặc một mảng bị append đồng thời có thể crash.

    Swift 6 và Swift Concurrency đưa kiểm tra data race vào compiler (strict concurrency): nhiều lỗi bị bắt lúc build thay vì lúc chạy.

    2. Actor: bảo vệ trạng thái chia sẻ¶

    actor là reference type như class nhưng đảm bảo chỉ một công việc chạy bên trong nó tại một thời điểm (actor isolation). Bạn gọi method từ bên ngoài bằng await vì có thể phải chờ tới lượt. Trạng thái trong actor an toàn mà không cần lock thủ công.

    Dùng actor cho trạng thái mutable được nhiều task truy cập: cache dữ liệu, bộ đếm, hàng đợi gửi lệnh BLE. Lưu ý await là điểm tạm dừng: giữa hai await trạng thái actor có thể bị thay đổi bởi lời gọi khác (reentrancy). Đừng giả định bất biến qua một await.

    import Foundation

actor VehicleCache {
    private var storage: [String: String] = [:]
    private(set) var hits = 0

    func value(for key: String) -> String? {
        if let v = storage[key] { hits += 1; return v }
        return nil
    }

    func set(_ value: String, for key: String) { storage[key] = value }
}

let cache = VehicleCache()

func use() async {
    await cache.set("Camry", for: "V1")             // gọi từ ngoài cần await
    let name = await cache.value(for: "V1")
    print(name ?? "nil")
}

// Chạy 1000 task cùng ghi vẫn an toàn:
func stress() async {
    await withTaskGroup(of: Void.self) { group in
        for i in 0..<1000 { group.addTask { await cache.set("v\(i)", for: "k\(i)") } }
    }
}

    3. @MainActor: actor của giao diện¶

    @MainActor là actor toàn cục đại diện cho main thread. Gắn nó vào class/hàm/thuộc tính nghĩa là code đó luôn chạy trên main. View trong SwiftUI mặc định là @MainActor (phần body), nên bạn cập nhật state UI tự nhiên. Đánh dấu ViewModel là @MainActor để toàn bộ state của nó chỉ đổi trên main.

    Công việc nặng (parse file lớn, xử lý ảnh) không nên chạy trên main vì làm UI giật. Cách: đặt vào một actor khác hoặc hàm nonisolated/@concurrent (Swift 6.2) rồi await kết quả và gán lại state trên main. Từ @MainActor gọi hàm async không-main bằng await sẽ chuyển công việc ra ngoài main rồi quay lại.

    import Foundation
import Observation

actor VehicleParser {
    func parse(_ data: Data) throws -> [String] {
        // việc nặng chạy ngoài main
        try JSONDecoder().decode([String].self, from: data)
    }
}

@MainActor
@Observable
final class ImportViewModel {
    private(set) var names: [String] = []
    private(set) var isImporting = false
    private let parser = VehicleParser()

    func importData(_ data: Data) async {
        isImporting = true                           // trên main
        defer { isImporting = false }
        do {
            names = try await parser.parse(data)      // parse ngoài main, kết quả gán lại trên main
        } catch {
            names = []
        }
    }
}

    4. Sendable: dữ liệu nào được đi qua ranh giới¶

    Khi một giá trị đi từ ngữ cảnh (actor/luồng) này sang ngữ cảnh khác, nó phải an toàn để chia sẻ; Swift đánh dấu bằng protocol Sendable. Value type chỉ chứa Sendable (struct/enum của Int, String, mảng…) tự động Sendable. Class mutable thì không, trừ khi nó final và bất biến hoặc tự bảo vệ bằng cơ chế đồng bộ (@unchecked Sendable là cam kết thủ công, dùng thận trọng).

    Quy tắc thực dụng: truyền giữa các actor/task bằng struct bất biến (DTO, domain model); giữ class mutable trong một actor hoặc @MainActor. Closure truyền vào Task/TaskGroup phải @Sendable, nên không được bắt biến mutable chung.

    import Foundation

struct VehicleSnapshot: Sendable {          // struct bất biến: an toàn
    let id: String
    let name: String
}

final class MutableVehicle {                // class mutable: không Sendable
    var name = ""
}

func send(_ snapshot: VehicleSnapshot) async {
    await Task.detached { print(snapshot.name) }.value   // OK
}

// Sai: truyền class mutable vào task chạy song song -> cảnh báo/lỗi strict concurrency
// let shared = MutableVehicle()
// Task.detached { shared.name = "x" }

    5. So sánh với JavaScript và các lỗi thường gặp¶

    So sánh: JS dùng event loop đơn luồng và Web Worker + postMessage (sao chép dữ liệu) để song song hóa; actor của Swift tương tự mô hình "mỗi worker sở hữu trạng thái, trao đổi qua tin nhắn" nhưng nhẹ hơn nhiều và an toàn kiểu.

    Lỗi thường gặp: 1. Dùng DispatchQueue.main.async rải rác thay vì @MainActor: khó theo dõi và không được compiler kiểm tra. 2. Truy cập thuộc tính actor mà quên await (compiler sẽ báo; đừng "sửa" bằng nonisolated(unsafe)). 3. Nghĩ rằng actor làm mọi thứ tuần tự: reentrancy nghĩa là trạng thái có thể đổi qua await. 4. Chạy việc nặng trong @MainActor ViewModel làm UI giật. 5. Dùng class mutable chung giữa các task rồi đánh dấu @unchecked Sendable cho "hết cảnh báo". 6. Dùng quá nhiều actor nhỏ gây overhead chuyển ngữ cảnh; actor cho từng vùng trạng thái chia sẻ thật. 7. Gọi DispatchSemaphore/wait để chặn async: dễ deadlock.

    6. Tóm tắt¶

    • Data race là truy cập đồng thời không đồng bộ vào dữ liệu mutable; Swift Concurrency giúp compiler bắt chúng. • actor bảo vệ trạng thái chia sẻ; gọi từ ngoài bằng await; cẩn thận reentrancy. • @MainActor cho UI và ViewModel; chuyển việc nặng ra actor khác rồi gán kết quả lại trên main. • Sendable: truyền giữa ngữ cảnh bằng value type bất biến. • Tránh @unchecked Sendable và DispatchSemaphore để chữa cháy.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Bộ đếm an toàn¶

    Viết actor Counter với increment() và value. Chạy 1000 task cùng tăng và kiểm tra kết quả 1000. Giải thích vì sao class thường có thể cho kết quả sai.

    Gợi ý withTaskGroup và addTask { await counter.increment() }.
    Đáp án 
    actor Counter {
    private(set) var value = 0
    func increment() { value += 1 }
}

func run() async {
    let counter = Counter()
    await withTaskGroup(of: Void.self) { group in
        for _ in 0..<1000 { group.addTask { await counter.increment() } }
    }
    print(await counter.value)   // luôn là 1000
}
    **Giải thích:** Actor tuần tự hóa truy cập nên mỗi lần tăng đều thấy giá trị mới nhất. Với class thường, hai task có thể cùng đọc giá trị cũ và ghi chồng nhau, làm mất lượt tăng.

    Bài 2 — Đưa việc nặng ra khỏi main¶

    ViewModel @MainActor đang parse file JSON lớn trực tiếp làm UI giật. Tách việc parse sang một actor và giữ cập nhật state trên main.

    Gợi ý await parser.parse(data) từ ViewModel.
    Đáp án 
    import Foundation
import Observation

actor Parser {
    func parse(_ data: Data) throws -> [String] {
        try JSONDecoder().decode([String].self, from: data)
    }
}

@MainActor
@Observable
final class VM {
    private(set) var items: [String] = []
    private let parser = Parser()

    func load(_ data: Data) async {
        items = (try? await parser.parse(data)) ?? []   // parse ngoài main, gán trên main
    }
}
    **Giải thích:** Khi `await` gọi actor khác, công việc chạy ngoài main thread, nên UI vẫn mượt. Kết quả quay về `@MainActor` để gán state an toàn.

    Bài 3 — Sendable hay không¶

    Trong các kiểu sau, kiểu nào Sendable tự động? (a) struct A { let id: String }; (b) final class B { var count = 0 }; (c) enum C { case x(Int) }; (d) final class D { let name: String }. Nếu cần truyền B giữa task, làm thế nào?

    Gợi ý Value type bất biến và class chỉ có thuộc tính let Sendable thì an toàn.
    Đáp án 
    // (a) Sendable: struct chỉ chứa Sendable.
// (b) KHÔNG: class có thuộc tính var mutable.
// (c) Sendable: enum với giá trị Sendable.
// (d) Sendable nếu khai báo explicit (final class chỉ chứa let Sendable).
final class D: Sendable { let name: String; init(name: String) { self.name = name } }

// Truyền B giữa task: bọc trong actor hoặc truyền snapshot bất biến:
struct BSnapshot: Sendable { let count: Int }
actor BBox { private var b = B(); func snapshot() -> BSnapshot { BSnapshot(count: b.count) } }
final class B { var count = 0 }
    **Giải thích:** Class mutable chia sẻ tạo data race. Giữ nó trong actor và truyền ra snapshot bất biến, thay vì dùng `@unchecked Sendable`.
