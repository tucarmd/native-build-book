    Tuần 7 · Ngày 4 · UIKit interoperability và lifecycle¶

    Mục tiêu: Nhúng UIKit vào SwiftUI bằng Representable, nhúng SwiftUI vào UIKit bằng UIHostingController và hiểu lifecycle của UIViewController.
    Thời lượng: 90–120 phút

    Khái niệm: UIKit, UIViewRepresentable, UIViewControllerRepresentable, Coordinator, UIHostingController, view controller lifecycle

    • Đã đọc xong
    • Đã làm hết bài tập

    1. Khi nào cần UIKit¶

    SwiftUI là hướng đi chính, nhưng UIKit vẫn cần trong các tình huống: (1) SDK/thư viện chỉ cung cấp UIView/UIViewController (máy quét mã vạch, trình phát video tùy biến, bản đồ nâng cao); (2) tính năng SwiftUI chưa có hoặc chưa ổn định trên phiên bản iOS bạn hỗ trợ; (3) bạn kế thừa codebase UIKit sẵn có và muốn di chuyển dần; (4) cần kiểm soát mức thấp (camera preview, text layout phức tạp).

    Chiến lược di chuyển từ app UIKit sang SwiftUI: làm theo từng màn hình mới bằng SwiftUI trong UIHostingController, giữ nguyên phần cũ. Không viết lại tất cả cùng lúc.

    2. UIViewRepresentable: UIKit view trong SwiftUI¶

    Tạo struct conform UIViewRepresentable với ba phần: makeUIView(context:) tạo UIView một lần; updateUIView(_:context:) được gọi mỗi khi state SwiftUI đổi để cập nhật UIView; và tùy chọn makeCoordinator() để nhận sự kiện từ UIKit (delegate, target-action) và gửi ngược về SwiftUI.

    Coordinator là class (vì delegate của UIKit thường cần reference type) và là cầu nối: UIKit gọi delegate → coordinator cập nhật @Binding → SwiftUI cập nhật.

    import SwiftUI
import UIKit

struct SearchBarRepresentable: UIViewRepresentable {
    @Binding var text: String
    var placeholder: String

    func makeUIView(context: Context) -> UISearchBar {
        let bar = UISearchBar()
        bar.placeholder = placeholder
        bar.delegate = context.coordinator              // nhận sự kiện từ UIKit
        return bar
    }

    func updateUIView(_ uiView: UISearchBar, context: Context) {
        if uiView.text != text { uiView.text = text }   // đồng bộ SwiftUI -> UIKit
    }

    func makeCoordinator() -> Coordinator { Coordinator(text: $text) }

    final class Coordinator: NSObject, UISearchBarDelegate {
        @Binding var text: String
        init(text: Binding<String>) { _text = text }

        func searchBar(_ searchBar: UISearchBar, textDidChange searchText: String) {
            text = searchText                            // UIKit -> SwiftUI
        }
    }
}

    3. UIViewControllerRepresentable và UIHostingController¶

    Với cả màn hình UIKit (ví dụ UIImagePickerController, SFSafariViewController, PHPickerViewController), dùng UIViewControllerRepresentable với makeUIViewController/updateUIViewController.

    Chiều ngược lại: UIHostingController(rootView:) bọc một SwiftUI view thành UIViewController để push vào UINavigationController hay thêm làm child controller. Dùng khi app có nền UIKit và đang thêm màn hình mới bằng SwiftUI.

    import SwiftUI
import SafariServices

struct SafariView: UIViewControllerRepresentable {
    let url: URL

    func makeUIViewController(context: Context) -> SFSafariViewController {
        SFSafariViewController(url: url)
    }
    func updateUIViewController(_ controller: SFSafariViewController, context: Context) { }
}

// SwiftUI trong UIKit:
final class LegacyViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        let host = UIHostingController(rootView: Text("Màn hình SwiftUI"))
        addChild(host)
        host.view.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(host.view)
        NSLayoutConstraint.activate([
            host.view.leadingAnchor.constraint(equalTo: view.leadingAnchor),
            host.view.trailingAnchor.constraint(equalTo: view.trailingAnchor),
            host.view.topAnchor.constraint(equalTo: view.safeAreaLayoutGuide.topAnchor),
            host.view.bottomAnchor.constraint(equalTo: view.bottomAnchor)
        ])
        host.didMove(toParent: self)
    }
}

    4. Lifecycle của UIViewController¶

    Khi làm việc với UIKit hoặc đọc code cũ, bạn cần biết các điểm vòng đời: • init/loadView: tạo view. • viewDidLoad: view đã tải vào bộ nhớ, gọi một lần; nơi cấu hình ban đầu. • viewWillAppear: sắp hiển thị, mỗi lần quay lại đều gọi. • viewDidAppear: đã hiển thị; bắt đầu animation, quét BLE. • viewWillDisappear/viewDidDisappear: sắp/đã ẩn; dừng tác vụ, hủy đăng ký. • deinit: bị giải phóng; nếu không in ra khi rời màn thì có retain cycle (tuần 3).

    Tương ứng SwiftUI: onAppear/onDisappear, .task (tự hủy), scenePhase. View SwiftUI là struct nhẹ; không có viewDidLoad như vậy: đừng khởi tạo nặng trong init của View.

    Nhớ luôn gọi super trong các hàm override và luôn cập nhật UI trên main thread.

    5. So sánh với Capacitor/Ionic¶

    Với Capacitor, native code được gói thành plugin và gọi từ JavaScript qua bridge. Trong app native thuần, "UIKit trong SwiftUI" là cách tích hợp tương đương: bạn truy cập trực tiếp mọi API mà không cần bridge, không serialize qua JSON, và không bị giới hạn của WebView. Đổi lại, bạn phải tự quản lý lifecycle và đồng bộ state giữa hai thế giới. Một số plugin Capacitor (camera, geolocation) khi chuyển sang native sẽ trở thành UIImagePickerController/PHPicker, CLLocationManager mà bạn tích hợp trực tiếp.

    6. Lỗi thường gặp¶

    1. Tạo/khởi động lại UIKit view trong updateUIView thay vì chỉ cập nhật thuộc tính: nhấp nháy, mất trạng thái.
    2. Vòng lặp cập nhật: updateUIView đặt giá trị → delegate gọi → đổi binding → lại updateUIView. Kiểm tra giá trị khác nhau trước khi gán.
    3. Quên Coordinator khi cần delegate; hoặc Coordinator giữ tham chiếu mạnh gây rò rỉ.
    4. Không gọi addChild/didMove(toParent:) đúng thứ tự khi nhúng UIHostingController: lifecycle sai.
    5. Dùng Auto Layout bằng code mà quên translatesAutoresizingMaskIntoConstraints = false.
    6. Cập nhật UI UIKit từ luồng nền.
    7. Dùng UIKit "vì quen" cho thứ SwiftUI làm được.

    7. Tóm tắt¶

    • UIKit khi SDK/tính năng yêu cầu hoặc khi di chuyển dần codebase cũ. • UIViewRepresentable/UIViewControllerRepresentable đưa UIKit vào SwiftUI; Coordinator nhận delegate. • UIHostingController đưa SwiftUI vào UIKit. • Lifecycle UIKit: viewDidLoad → viewWillAppear → viewDidAppear → … → deinit. • Ưu tiên SwiftUI; chỉ dùng UIKit cho phần thật sự cần.

    Bài tập¶

    Tự làm trước, rồi mới mở gợi ý / đáp án.

    Bài 1 — Bọc UIActivityIndicatorView¶

    Tạo Spinner: UIViewRepresentable bọc UIActivityIndicatorView với tham số isAnimating: Bool. Giải thích vì sao updateUIView là nơi cập nhật animation.

    Gợi ý startAnimating()/stopAnimating() trong updateUIView.
    Đáp án 
    import SwiftUI
import UIKit

struct Spinner: UIViewRepresentable {
    var isAnimating: Bool

    func makeUIView(context: Context) -> UIActivityIndicatorView {
        UIActivityIndicatorView(style: .medium)
    }

    func updateUIView(_ uiView: UIActivityIndicatorView, context: Context) {
        isAnimating ? uiView.startAnimating() : uiView.stopAnimating()
    }
}
    **Giải thích:** `makeUIView` chỉ chạy một lần để tạo view; mọi lần state SwiftUI đổi, `updateUIView` được gọi để đồng bộ thuộc tính sang UIKit.

    Bài 2 — Coordinator cho delegate¶

    Bọc UITextField thành NativeTextField với @Binding var text. Dùng Coordinator làm delegate và cập nhật binding khi người dùng gõ.

    Gợi ý addTarget(.editingChanged) hoặc delegate; Coordinator giữ Binding.
    Đáp án 
    import SwiftUI
import UIKit

struct NativeTextField: UIViewRepresentable {
    @Binding var text: String

    func makeUIView(context: Context) -> UITextField {
        let field = UITextField()
        field.borderStyle = .roundedRect
        field.addTarget(context.coordinator, action: #selector(Coordinator.changed(_:)), for: .editingChanged)
        return field
    }

    func updateUIView(_ uiView: UITextField, context: Context) {
        if uiView.text != text { uiView.text = text }
    }

    func makeCoordinator() -> Coordinator { Coordinator(text: $text) }

    final class Coordinator: NSObject {
        @Binding var text: String
        init(text: Binding<String>) { _text = text }
        @objc func changed(_ sender: UITextField) { text = sender.text ?? "" }
    }
}
    **Giải thích:** Coordinator là cầu nối UIKit → SwiftUI. Kiểm tra `uiView.text != text` tránh vòng lặp cập nhật vô hạn giữa hai phía.

    Bài 3 — Nhúng SwiftUI vào UIKit¶

    Một UIViewController cũ cần hiển thị VehicleListView (SwiftUI) làm child. Viết đoạn nhúng đúng thứ tự addChild, addSubview, didMove(toParent:).

    Gợi ý UIHostingController(rootView:), Auto Layout phủ view cha.
    Đáp án 
    import SwiftUI
import UIKit

struct VehicleListView: View { var body: some View { Text("Danh sách xe") } }

final class LegacyContainerViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        let host = UIHostingController(rootView: VehicleListView())
        addChild(host)
        host.view.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(host.view)
        NSLayoutConstraint.activate([
            host.view.leadingAnchor.constraint(equalTo: view.leadingAnchor),
            host.view.trailingAnchor.constraint(equalTo: view.trailingAnchor),
            host.view.topAnchor.constraint(equalTo: view.topAnchor),
            host.view.bottomAnchor.constraint(equalTo: view.bottomAnchor)
        ])
        host.didMove(toParent: self)
    }
}
    **Giải thích:** Thứ tự `addChild` → thêm view → `didMove(toParent:)` bảo đảm lifecycle của child controller được cha quản lý đúng (appearance, rotation, memory).
