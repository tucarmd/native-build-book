    Claude Code Skills — Guide¶

    ⚠️ Status: in development & testing — for reference only. These skills are still being developed and tested. They are kept here as-is from the working setup used while building this repo; behaviour, scripts and paths may change and are not re-verified in this repo. Read them to learn the approach, adapt them before relying on them.

    The skills live in .claude/skills/. Claude Code loads them automatically when this repo is opened — invoke one with /<skill-name>, or just describe the task and Claude picks the matching skill from its description. Each skill is one folder with a SKILL.md (instructions) and, for some, scripts/, assets/ (templates) and references/ (longer notes read only when needed).

    How the skills fit together¶

                     one coding request ("add a Remember-me checkbox")
                                  │
                        native-feature-task  ── writes TASK.md, splits the work
                 ┌────────────────┼─────────────────┐
         kotlin-android-code   native-ui-layout   swift-ios-code
                 │                                   │
         kotlin-android-test                    swift-ios-test
                 │                                   │
       kotlin-android-build-run              swift-ios-build-run
                 │                                   │
       kotlin-android-review                  swift-ios-review
                 └──────── native-live-build (real phone loop) ────────┘

  Learning track:  *-mentor (what to learn next) → *-setup / swift-ios-doctor / swift-ios-scaffold
                   → code → build-run → review (Day / Week / Milestone gates)

    Entry point & shared¶

    Skill What it does Use it when Ships with
    native-feature-task Entry point for one concrete coding request (Android, iOS or both). Turns the requirement into a TASK.md, then hands off to the code / layout / test skills and tracks what is done. "build the login screen", "add button X to screen Y", "do this on Android and iOS", "is this task finished?" assets/TASK.md.tpl, references/top-repos.md
    native-ui-layout Screen layout in Jetpack Compose ↔ SwiftUI: Column/Row/Box ↔ VStack/HStack/ZStack, padding, spacing, alignment, forms, lists, whole-row checkboxes, keyboard covering inputs, rebuilding UI from a Figma screenshot. Also answers where shared styles live (design tokens, theme, reusable components). "lay out this screen", "make it look like the design", "can't center this", "where do colors/spacing go?", "reuse or new component?" shared-styles.md
    native-live-build Watches the source and rebuilds + reinstalls on a physical phone every time a Kotlin / Swift file is saved. It is a live rebuild, not hot reload. Also covers the traps hit on this machine (JAVA_HOME, device locked, no device found). "live build", "save the file and see it on the phone", "auto install on device" scripts/live-build.sh, references/research-and-limits.md
    open-native-project Opens a native project in Xcode or Android Studio from a roughly-typed name (scans ~/DATA/PROJECTS for .xcodeproj / .xcworkspace / settings.gradle), optionally booting a Simulator / emulator. "open Native Device Monitor Android", "open X in Xcode with iPhone 17", "where is project X?" open-project.sh
    ios-device-carmd-identity Builds the learning iOS app from current code and installs it on a real iPhone under the CarMD Connect bundle id / signing profile — without editing the project or opening Xcode. Used to test real BLE / camera when only the CarMD profile exists on the machine. Not for the CarMD Ionic app itself. "run iOS on a real iPhone as CarMD", "install the learning app on my iPhone" scripts/run_device.sh

    🤖 Android — Kotlin + Compose¶

    Follows this repo's roadmap: Setup → Week 1 → Week 2 → Week 3 → Final.

    Skill What it does Use it when Ships with
    kotlin-android-mentor 1-1 mentor and the main skill of the Kotlin set: checks where the learner is, explains concepts (null safety, lambdas, coroutines, lifecycle, Intent, BLE GATT, Foreground Service, WorkManager…), suggests the next step and updates progress. "where do I start?", "what's next today?", "explain coroutines", "how is Kotlin different from Swift?", "I'm stuck, give me a hint" —
    kotlin-android-setup Installs / checks the Kotlin + Android toolchain on macOS (JDK, SDK, AVD, Gradle/AGP versions) and creates empty projects (Kotlin console for Day 1, Android app for Day 3+) without clicking through the GUI. Includes a doctor for repeated sync errors. "set up Kotlin", "Gradle sync failed", "SDK location not found", "JAVA_HOME", "create an emulator" scripts/check_env.sh, doctor.py, new_android_app.py, new_kotlin_console.py, run_android.sh
    kotlin-android-code Writes Kotlin logic kept out of the Composables: feature-based packages, ViewModel + UiState + StateFlow, repository / service, SharedPreferences, coroutines — then wires it to the UI. "code screen X in Kotlin", "write a ViewModel", "add logic to this button", "this Composable is too long" —
    kotlin-android-build-run Claude runs ./gradlew, adb and the emulator itself, reads Gradle / compiler / Logcat errors and takes screenshots to look at the UI. Covers permission resets, simulated OS kill / force stop, checking a running service and reading on-device log files. Points at learner errors instead of silently fixing them. "build / run the app", "app crashes", "show Logcat", "adb install failed", "is the service still running?" —
    kotlin-android-test Unit tests for ViewModels (JUnit4, kotlinx-coroutines-test, runTest, MainDispatcherRule) with hand-written fakes (no mocking library), plus Compose UI tests on stateless XxxContent. "write tests for this ViewModel", "Module with the Main dispatcher is missing", "test the Compose UI" —
    kotlin-android-review Reviews code the learner wrote at the end of each Day (4 checkpoints) and checks the Week gates (Week 1 UI shell, Week 2 Permission/BLE/Camera/API, Week 3 NativeCore/Background, Final). Teaches why, never rewrites the code; refuses to review code that has not run. "review my Kotlin", "is Day N done?", "can I pass this week?", "refactor checklist" —

    🍎 iOS — Swift + SwiftUI¶

    Follows a 100-step roadmap grouped into 5 milestones (M1–M5).

    Skill What it does Use it when Ships with
    swift-ios-mentor 1-1 mentor for complete beginners: explains Swift / SwiftUI concepts, tracks progress on the 100-step roadmap, points to learning resources, good GitHub repos, Reddit communities, monetization basics and Claude Code tooling for Swift. "how do I start iOS?", "what step am I on?", "explain optionals / @State / struct vs class", "good Swift resources?" references/ (environment, knowledge map, 100-step roadmap, resources, top repos, Reddit, monetization, Claude Code for Swift, progress tracking), assets/fetch_swift_resources.py
    swift-ios-doctor Checks and fixes the Swift / Xcode environment (xcode-select, license, CommandLineTools, signing identity, schemes, DerivedData) and boots a Simulator before building. The iOS twin of kotlin-android-setup. "xcodebuild not found", "no simulator", "Unable to boot device", "Developer Mode", "clean Xcode junk" scripts/check_env.sh, scripts/doctor.py
    swift-ios-scaffold Creates the learning repo the first time (CLAUDE.md, PROGRESS.md, Xcode .gitignore) and a new SwiftUI Xcode project for each roadmap step — no Xcode GUI, no extra tools. "start learning iOS", "create a project for step N", "scaffold an iOS app" assets/new_ios_app.py, assets/templates/
    swift-ios-feature Codes one numbered feature into demo/ together with a master SPEC.md: requirement, ASCII diagram, approach / pattern, lessons, pitfalls, book references, change log. Includes an Ionic/Angular → SwiftUI mapping table. "build this feature", "turn this into an app", "which pattern for this screen?", "document it when done" assets/patch_pbxproj.py, assets/templates/SPEC.md.tpl
    swift-ios-code Writes Swift logic kept out of the Views: @Observable ViewModel, @MainActor, async/await, service protocols, UserDefaults — then wires it to the View. Covers Swift 6 Sendable errors. "code screen X in Swift", "write a SwiftUI ViewModel", "@State or @Observable?", "this View is too long" —
    swift-ios-animation SwiftUI animations learned from the real CSS animations of the CarMD Ionic app (keyframes, duration, easing) mapped to SwiftUI, plus community patterns. Verifies by screenshotting two moments in time, because a clean build proves nothing about motion. "add an animation", "fade in", "loading dots", "map CSS keyframes to SwiftUI", "this feels stiff" —
    swift-ios-port-ionic Finds the real logic in the CarMD Ionic / Angular source (every claim with file:line) and ports it to SwiftUI. Also syncs assets (SVG, images, SCSS colors) into Xcode and reads Figma (read-only MCP), flow docs, spec docs and Jira tickets. "how does the Ionic app do this?", "port this screen to Swift", "sync assets from the old app", "check it against Figma" scripts/sync-assets.sh, references/ (knowledge sources, Figma MCP, CSS → SwiftUI)
    swift-ios-build-run Claude runs xcodebuild / xcrun simctl itself, reads build logs and crash reports, takes and reads screenshots, runs tests, deploys to a real iPhone, archives for TestFlight / fastlane. Also a Network tab for iOS: capture requests / responses through a proxy and export a scrubbed HAR. "build / run the app", "build failed", "app crashes", "which API does this screen call?", "export a HAR for backend" scripts/netlog.sh, scripts/har_scrub.py, assets/run_sim.sh, assets/templates/ (Fastfile, Gemfile), references/network-debugging.md
    swift-ios-test Unit tests for ViewModels with Swift Testing (@Test, #expect) or XCTest, async / @MainActor tests, hand-written fakes; runs without a Simulator via swift test when possible. "write tests for this ViewModel", "swift test", "main actor-isolated … nonisolated context", "project has no test target" —
    swift-ios-review Reviews code at the end of each roadmap step (4 checkpoints) and checks milestone gates (M1–M5) before moving on. Beginner-level feedback that explains why; optional SwiftUI Pro pass from M2. Refuses to review code that has not run. "review my code", "is step N done?", "can I pass this milestone?" —

    Android ↔ iOS mapping¶

    Role 🤖 Android 🍎 iOS
    Mentor / roadmap kotlin-android-mentor swift-ios-mentor
    Environment setup / doctor kotlin-android-setup swift-ios-doctor
    New project kotlin-android-setup swift-ios-scaffold
    Write logic kotlin-android-code swift-ios-code
    Layout native-ui-layout native-ui-layout
    Tests kotlin-android-test swift-ios-test
    Build · run · screenshot kotlin-android-build-run swift-ios-build-run
    Review + gates kotlin-android-review swift-ios-review
    Real phone loop native-live-build native-live-build · ios-device-carmd-identity
    iOS only — swift-ios-feature · swift-ios-animation · swift-ios-port-ionic

    Known limits¶

    • Work in progress. Skills are still being developed and tested; treat them as reference, not a finished toolkit.
    • Machine-specific. Several skills hard-code paths, tool versions, simulators and devices verified on the author's Mac (e.g. ~/DATA/PROJECTS, Compose BOM / AGP versions, iOS 26.x simulators). Adjust before reuse.
    • CarMD-specific. ios-device-carmd-identity, swift-ios-port-ionic and swift-ios-animation assume access to the private CarMD Connect source, signing profile, Figma and Jira — they will not work without them.
    • Written in Vietnamese. The SKILL.md files are in Vietnamese (this guide is the English summary).
