    Chống crash khi code Swift (kể cả khi vibe code)¶

    Swift cố ý cho app crash ngay khi gặp một giá trị "không thể xảy ra" (nil, index sai, ép kiểu sai). Swift không chạy tiếp với dữ liệu sai như JavaScript. Vì vậy cách chống crash là không để code của bạn tự hứa rằng chuyện đó không xảy ra. Nguồn: Apple — Addressing crashes from Swift runtime errors.

    1. Bảy nguyên nhân crash hay gặp nhất và cách viết an toàn¶

    # Code gây crash Khi nào crash Viết thế này thay vào
    1 value! (force unwrap) value là nil guard let value else { return } · if let value { … } · value ?? mặcĐịnh
    2 try! decode(...) Hàm throw lỗi try? (bỏ qua lỗi) hoặc do { try … } catch { … }
    3 x as! Int Kiểu không khớp if let n = x as? Int { … }
    4 array[5] Index nằm ngoài mảng array.first, array.last, array.indices.contains(i) ? array[i] : nil
    5 var name: String! (implicitly unwrapped) Dùng biến trước khi gán var name: String?, hoặc gán ngay trong init
    6 Dùng camera, mic, vị trí… mà thiếu key NS…UsageDescription Ngay lúc xin quyền Thêm INFOPLIST_KEY_NS…UsageDescription vào project.yml trước khi viết code xin quyền
    7 Chia cho 0 với Int, fatalError(), precondition Lúc chạy guard total > 0 else { return 0 } (xem TimerViewModel.progress)

    Thêm 2 loại lỗi không làm crash ngay nhưng gây hỏng ngầm: - Cập nhật UI ngoài main thread. Đã chặn bằng cài đặt MainActor mặc định. Main Thread Checker của Xcode cũng tự báo. - Giữ nhau trong bộ nhớ (retain cycle). Task { self.… } hoặc closure giữ self mãi mãi. Cách tránh: dùng [weak self] (xem TimerViewModel.start).

    Ngoại lệ được phép: try! / ! ở chỗ mà nếu lỗi thì app không thể chạy được nữa (ví dụ mở database trong PomodoroApp). Viết kèm comment giải thích, và thêm // swiftlint:disable:next force_try.

    2. Bắt crash khi nó xảy ra¶

    Công cụ Cách bật Bắt được gì
    Chạy bằng Xcode (⌘R) Có sẵn Crash dừng đúng dòng gây lỗi, console in Fatal error: Unexpectedly found nil…
    Swift Error Breakpoint + Exception Breakpoint Breakpoint navigator (⌘8) › + Dừng ngay chỗ lỗi được throw hoặc chỗ exception xảy ra
    Main Thread Checker Bật mặc định trong Scheme › Run › Diagnostics UI bị cập nhật ngoài main thread
    Thread Sanitizer Scheme › Run › Diagnostics (bật khi nghi có data race, build sẽ chậm hơn) Data race
    Memory Graph (Debug › Debug Memory Graph) Khi app đang chạy Object không được giải phóng (retain cycle)
    Crash report ~/Library/Logs/DiagnosticReports/Pomodoro-*.ips (Simulator) · iPhone thật: Xcode › Window › Devices › View Device Logs Stack trace sau khi app đã crash
    Log của app xcrun simctl spawn booted log stream --predicate 'process == "Pomodoro"' Mọi thứ app in ra

    Cách đọc crash trong 3 bước: 1. Tìm dòng Thread 0 Crashed (hoặc thread có ghi Crashed). 2. Đi từ trên xuống, tìm dòng đầu tiên có tên app của bạn (Pomodoro). Đó là file và dòng gây lỗi. 3. Đọc lý do: EXC_BREAKPOINT hoặc Fatal error thường do nguyên nhân 1–5 ở bảng §1, còn EXC_BAD_ACCESS là lỗi bộ nhớ.

    3. SwiftLint — "ESLint cho Swift"¶

    JS / Angular Swift
    ESLint SwiftLint (brew install swiftlint, bản 0.65.x)
    Prettier swiftlint --fix. Tuỳ chọn thêm swift format (có sẵn trong Xcode 16+). Chỉ nên dùng một công cụ format để chúng không sửa đè lên nhau
    .eslintrc .swiftlint.yml
    npm run lint make lint
    husky pre-commit .git/hooks/pre-commit (xem 03 §3)

    Luật quan trọng trong .swiftlint.yml của app (đã có từ Day 1):

    Luật Mặc định Ta đặt Chặn crash #
    force_unwrapping tắt (opt-in) bật 1
    force_try warning error 2
    force_cast error error 3
    implicitly_unwrapped_optional tắt (opt-in) bật 5
    type_body_length, function_body_length, file_length — 300 / 50 / 400 Giữ file ngắn, dễ đọc

    make lint chạy với --strict, nên mọi warning cũng làm lệnh thất bại. Commit chỉ khi lint sạch.

    Vì sao không gắn SwiftLint vào Build Phase? Từ Xcode 15, script trong build chạy trong sandbox (ENABLE_USER_SCRIPT_SANDBOXING), nên báo Sandbox: swiftlint deny file-read-data. Có thể tắt sandbox, nhưng như vậy là thêm một cấu hình phải nhớ. Chạy make lint đơn giản hơn.

    4. Vibe code an toàn — luật cho AI¶

    Code do AI viết hay mắc các lỗi sau: - Dùng API cũ: NavigationView, ObservableObject / @Published / @StateObject, .foregroundColor, onChange(of:perform:). - Bịa ra API không tồn tại. - Dùng ! cho nhanh. - Viết Task { self.… } mà không có [weak self]. - Nhét logic vào View.

    Bước 1: tạo mini-pomodoro/CLAUDE.md (AI sẽ đọc file này mỗi lần làm việc trong thư mục):

    # Rules for this app
- iOS 17+, Swift 6, SwiftUI. Default actor isolation = MainActor (do not add @MainActor everywhere).
- Architecture: Views (no logic) → ViewModels (@Observable, all logic, unit-tested) → Services (protocols) ← real impl.
  Real services are created ONLY in App/PomodoroApp.swift.
- NEVER use: `!` force unwrap, `try!`, `as!`, `String!`, NavigationView, ObservableObject/@Published/@StateObject,
  .foregroundColor, onChange(of:perform:), DispatchQueue.main.async, UIKit.
- Use: guard let / if let / ??, NavigationStack, @Observable + @State, .foregroundStyle, async/await, [weak self] in Task.
- Keep code simple for a beginner: no generics, no Combine, no extra libraries. Comment the "why".
- Done = `make test` green + `make lint` clean + I ran it on the Simulator.

    Bước 2: checklist review mỗi khi AI đưa code (2 phút):

    • make lint sạch, không có !, try!, as! mới
    • Có API nào mình chưa từng thấy không? Nếu có, ⌥ click để xem tài liệu. Không mở được thì có thể là API bịa
    • View có thêm if/logic nghiệp vụ không? Nếu có, chuyển sang ViewModel
    • Có Task { … self … } mà thiếu [weak self] không?
    • Có xin quyền mới (camera, vị trí…) không? Đã thêm key NS…UsageDescription chưa?
    • make test xanh. Nếu AI sửa ViewModel thì đã có test cho phần sửa chưa?
    • Bạn giải thích được từng dòng không? Không giải thích được thì hỏi /swift-ios-mentor trước khi commit

    Bước 3: nhờ AI review chéo: gõ /swift-ios-review trên phần code vừa sửa.

    5. Bài tập Day 8¶

    Ghi kết quả từng bài vào mini-pomodoro/CRASH-NOTES.md: dòng gây lỗi, thông báo lỗi, cách sửa. Nhớ hoàn tác sau mỗi bài (git checkout -- .).

    Bài 1: force unwrap. Trong TimerViewModel.start(now:), thêm dòng đầu tiên: 

    let saved = UserDefaults.standard.string(forKey: "no-such-key")!
print(saved)
    - Mở Xcode và chạy bằng ⌘R, rồi bấm Start. Ghi lại dòng Xcode dừng và thông báo trong console. - Chạy make lint. Luật nào báo? - Sửa bằng guard let.

    Bài 2: index ngoài mảng. Trong SessionDots.body, thêm let _ = [1, 2, 3][total] rồi chạy app. Tìm crash report trong ~/Library/Logs/DiagnosticReports/ và chỉ ra dòng đầu tiên có chữ Pomodoro. Sửa bằng indices.contains.

    Bài 3: thiếu quyền trong Info.plist. Trong TimerViewModel.start, thêm: 

    AVCaptureDevice.requestAccess(for: .video) { _ in }   // cần `import AVFoundation`
    Chạy và bấm Start. App bị hệ điều hành kill. Đọc thông báo về usage description. Sửa bằng cách thêm INFOPLIST_KEY_NSCameraUsageDescription vào project.yml, chạy make project, rồi chạy lại.

    Bài 4: AI viết code cũ. 1. Nhờ AI (không có CLAUDE.md): "Write a SwiftUI settings screen with a view model". Áp checklist §4 lên code đó và đếm số lỗi tìm được. 2. Thêm CLAUDE.md rồi hỏi lại. So sánh 2 kết quả.
